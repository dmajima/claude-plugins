# case-09: 反映対象 5 件超過時のサブエージェント委譲

## 入力

```text
/project-harness:update
```

前提: 大規模差分により反映計画の更新対象が 5 件を超えた（例: 更新 6 件 + 新規 2 件）。ユーザは全反映を承認済み。

## 期待動作

1. Phase 4 で agents.md の反映エージェント構成に従い、**1 ドキュメント = 1 エージェント** で並列委譲する
2. 各委譲プロンプトに「担当ドキュメントパス（編集対象はこの 1 ファイルのみ）・起因 diff・反映原則（乖離箇所のみ更新 / 捏造禁止）・frontmatter 規則」を含める
3. 各フォルダの `CLAUDE.md` 索引・`.claude/CLAUDE.md`・`.sync-state.json` は **メインのみ** が更新する
4. メインが統合時に「報告と実ファイルの整合・frontmatter 3 フィールド存在・担当外ファイルへの書き込み有無（`git status` 突合）」を検証する

## 期待出力

- 反映結果表 + 委譲したドキュメントとエージェント数の内訳 + 統合検証の結果

## 禁止事項（このケースで起きてはならないこと）

- エージェントによる索引 `CLAUDE.md` / `.claude/CLAUDE.md` / `.sync-state.json` への直接書き込み
- 複数エージェントによる同一ファイルの編集競合
- 統合検証（担当外書き込みチェック）の省略

## 分岐の根拠

agents.md「更新対象 5 件以下はメイン直接反映・5 件超過時のみ委譲」の分岐と、procedures.md Phase 4「エージェント委譲（更新対象 5 件超過時）」。
