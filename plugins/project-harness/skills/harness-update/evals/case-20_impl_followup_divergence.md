# case-20: 実装追随の突合で記載と実装の乖離を検出

## 入力

```text
/project-harness:update
```

前提: ハーネス構築済み。`specs/order-entry.md`（`status: agreed` / `sources: []`）に対応する実装 `src/features/order/` 配下が追加された。仕様は明細行の上限を 20 行と記載しているが、実装は 50 行を上限としている（記載と実装の乖離）。

## 期待動作

1. Phase 2 手順 4 で実装追随候補として一意に特定し、Phase 3 で AskUserQuestion による紐付け実施の承認を得る
2. Phase 4「実装追随の反映」手順 1 で `sources` へ実装パスのグロブを設定する
3. 同手順 2 で記載内容と実装を突合し、上限行数の相違を乖離として検出する。**報告にまとめるのみ** とし、ドキュメントの書き換えも実装の修正も行わない
4. 乖離の扱い（ドキュメントを実装に合わせる / 実装を仕様に合わせる）はユーザ判断として提示する（sync-spec.md 節 2.1「乖離は報告のみ」）
5. ユーザがドキュメント側の更新を承認した場合: 記載を更新のうえ `status: implemented` へ昇格し、合意ベースの定型注記を除去する（Phase 4 手順 3）
6. ユーザが判断を保留した場合: `sources` 設定のみ実施して `status` は `agreed` のまま据え置き、報告に「実装追随は部分完了（乖離未解消）」と明記する（Phase 4 手順 4）
7. いずれの分岐でも索引 `CLAUDE.md` と `.sync-state.json` は通常どおり更新する

## 期待出力

- 乖離の内容（該当箇所・仕様の記載・実装の実態・根拠となるソース位置）
- ドキュメント修正 / 実装修正のどちらで解消するかの判断依頼（Phase 7 の報告項目）
- 保留時: `sources` は設定済み・`status` は `agreed` 維持・「実装追随は部分完了（乖離未解消）」の明示

## 禁止事項（このケースで起きてはならないこと）

- 乖離を検出した際にドキュメントを実装に合わせて自動で書き換えること
- 対象プロジェクトのソースコードを仕様に合わせて修正すること（反映方向はコード → ドキュメントの一方向）
- 乖離が未解消のまま `status: implemented` へ昇格すること（昇格は乖離の解消後）
- どちらが正しいかをエージェントが裁定すること（仕様適合性の判断には踏み込まない）
- 乖離を報告に含めず `sources` 設定のみで完了扱いにすること

## 分岐の根拠

procedures.md Phase 4「実装追随の反映」手順 2〜4 と、sync-spec.md 節 2.1 の規則表（乖離は報告のみ / 昇格の条件 / 部分実装）。実装追随の正常系（case-16）から分岐する主要経路であり、乖離の有無で `status` 昇格の可否が変わる。
