# case-15: 構成仕様バージョンの差異を検出

## 入力

```text
/project-harness:update
```

前提: `.sync-state.json` の `harness_spec_version` が `1.0`（または未設定）で、プラグイン側の現行仕様が `1.1`。現行仕様で追加されたフォルダ種別・frontmatter フィールドが既存ハーネスに存在しない。

## 期待動作

1. Phase 1 で `harness_spec_version` と現行仕様（structure-spec.md 節 9）を照合し、マイナー上位であることを検出する
2. 不足しているフォルダ・frontmatter フィールドを列挙する
3. AskUserQuestion で補完の可否を確認する
4. 承認時: 不足構成を補完し、通常の差分反映へ進む。完了時に `harness_spec_version` を現行版へ更新する
5. 非対話モード: 補完せず、差分（不足している構成）を報告のみとする
6. 現行がメジャー上位の場合: 破壊的変更のため update では移行できない旨を報告し、`harness-init` の再構築（保持マージ）を案内して終了する

## 期待出力

- 検出したバージョン差異（state 側 / 現行）と不足構成の一覧
- 補完結果、または未補完の理由

## 禁止事項（このケースで起きてはならないこと）

- バージョン照合を行わず旧構成のまま反映を続けること（新旧ハーネスが混在し判定不能になる）
- 無確認での構成補完（フォルダ追加は `.claude/` 配下だが構成変更を伴うため確認する）
- メジャー差異を自動移行しようとすること

## 分岐の根拠

sync-spec.md 節 5「構成仕様バージョンの照合」。プラグイン側の仕様進化に既存ハーネスを追随させる経路であり、通常の差分反映（case-01）とは別フェーズ。
