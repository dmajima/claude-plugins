# case-15: 構成仕様バージョンの差異を検出

## 入力

```text
/project-harness:update
```

前提: `.sync-state.json` の `harness_spec_version` が現行版より古い（例: `1.0`・未設定・`1.1`）。現行仕様は structure-spec.md 節 9 の版（本ケース記載時点で `1.2`）。

## 期待動作

1. Phase 1 で `harness_spec_version` と現行仕様（structure-spec.md 節 9）を照合し、マイナー上位であることを検出する
2. **必須構成** の不足フォルダ・不足 frontmatter フィールドを列挙する。**任意要素（`status` フィールド・`requirements/` フォルダ。structure-spec.md 節 9.0）は列挙・補完の対象にしない**
3. 必須構成の不足がある場合は AskUserQuestion で補完の可否を確認する
4. 承認時: 不足構成を補完し、通常の差分反映へ進む。完了時に `harness_spec_version` を現行版へ更新する
5. **1.1 → 1.2 のように改定内容が任意要素のみの場合**: 補完すべき必須構成が無いため、確認なしで `harness_spec_version` の版数追随のみを行い、通常の差分反映へ進む
6. 非対話モード: 必須構成の補完は行わず差分（不足している構成）を報告のみとする。補完を伴わない版数追随のみの更新（手順 5）は非対話モードでも実施してよい（sync-spec.md 節 5）
7. 現行がメジャー上位の場合: 破壊的変更のため update では移行できない旨を報告し、`harness-init` の再構築（保持マージ）を案内して終了する

## 期待出力

- 検出したバージョン差異（state 側 / 現行）と不足構成の一覧（任意要素のみの改定では「補完対象なし・版数追随のみ」）
- 補完結果、または未補完の理由

## 禁止事項（このケースで起きてはならないこと）

- バージョン照合を行わず旧構成のまま反映を続けること（新旧ハーネスが混在し判定不能になる）
- 無確認での必須構成の補完（フォルダ追加は `.claude/` 配下だが構成変更を伴うため確認する）
- **任意要素（`status` / `requirements/`）を不足構成として補完提案すること**（存在しなくても正しいハーネス。code-first ハーネスに不要なフィールド・空フォルダを増やす誤動作）
- メジャー差異を自動移行しようとすること

## 分岐の根拠

sync-spec.md 節 5「構成仕様バージョンの照合」。プラグイン側の仕様進化に既存ハーネスを追随させる経路であり、通常の差分反映（case-01）とは別フェーズ。
