# case-14: 全量監査モード（--full）

## 入力

```text
/project-harness:update --full
```

前提: ハーネス構築済み。`glossary.md` と `conventions/naming.md` は `sources: []` のため通常の差分検出では更新対象にならない。コード側では用語（エンティティ名）と命名規則が変化している。

## 期待動作

1. Phase 1 で前提を確認する（乖離ゼロでも中断せず続行する）
2. 差分検出をスキップし、Phase 2F で `references/` 配下 **全ドキュメント** を対象とする
3. 各ドキュメントの記載内容とソース実態を突合する:
   - `sources` を持つドキュメント: 対象ソースの実在と記載の整合を確認する
   - `sources: []` のドキュメント（用語集・規約・ADR）: 記載内容とコード実態の乖離を確認する
4. 検出した乖離を Phase 3 の反映計画として提示し、以降は通常モードと同じ手順で反映する
5. 完了時に `.sync-state.json` を HEAD で更新する

## 期待出力

- 全量監査の対象件数と、検出した乖離の一覧（`sources: []` のドキュメントを含む）
- 反映結果と検証スクリプトの結果

## 禁止事項（このケースで起きてはならないこと）

- `sources: []` のドキュメントを対象から除外すること（本モードの主目的）
- 乖離ゼロを理由に監査せず終了すること
- 全ドキュメントを機械的に書き直すこと（乖離箇所のみ更新する原則は通常モードと同じ）

## 分岐の根拠

sync-spec.md 節 4「全量監査モード」。差分検出（case-01）では到達できないドキュメントの整合確認手段であり、起動フラグで経路が分岐する。
