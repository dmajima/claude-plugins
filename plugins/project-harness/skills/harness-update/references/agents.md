# harness-update エージェント運用定義

## このスキルで使用するエージェント

| 用途 | subagent_type | 実行形態 |
|------|--------------|---------|
| 変更内容の調査（大規模差分時のみ） | `Explore`（読み取り専用調査）または `general-purpose` | 並列 |
| ドキュメント反映（更新対象 5 件超過時のみ） | `general-purpose` | ドキュメント単位で並列（Independent 型） |

更新対象 5 件以下の場合はエージェントを使わずメインが直接反映する（調整オーバーヘッド回避）。

## Phase 4: 反映エージェント構成

### 分割単位

**1 ドキュメント = 1 エージェント**。同一ファイルを複数エージェントが編集しないよう、担当ドキュメントと参照専用ファイルを明確に分離する。
各フォルダの `CLAUDE.md` 索引・`.claude/CLAUDE.md`・`.sync-state.json` は **メインのみ** が更新する（エージェントには触らせない）。

### 起動時の必須プロンプト要素

1. 担当ドキュメントのパス（編集対象はこの 1 ファイルのみ）
2. 起因する変更ファイル一覧と diff の要約（または diff 取得コマンド）
3. 反映の原則: 「diff を読み、記載と実装の乖離箇所のみ更新。全体書き直し禁止。確認できない内容は `TODO:` 明示（捏造禁止）」
4. frontmatter 規則（`${CLAUDE_PLUGIN_ROOT}/references/structure-spec.md` 節 5。`updated` の更新を含む）
5. 返却フォーマット: 更新箇所の要約（節名 + 変更概要）と解消 / 新規発生した `TODO:` の一覧

### エラー増幅への対策

Independent 型並列反映のため、メインが統合時に以下を検証する:

- 各エージェントの報告と実ファイルの整合（更新箇所のサンプリング確認）
- frontmatter の破壊がないこと（`title` / `sources` / `updated` の 3 フィールド存在）
- 担当外ファイルへの書き込みがないこと（`git status` で編集ファイル一覧を突合）
