# Evals: harness-init

このディレクトリは `harness-init` の動作分岐の期待挙動を例示する。

## ケース一覧

| ケース | 内容 | 主な分岐根拠 |
|-------|-----|-------------|
| case-01 | 標準の初期構築（対話モード） | SKILL.md 実行フロー 1〜7 |
| case-02 | ハーネス構築済みプロジェクトでの起動（再構築 3 択含む） | Phase 1 既存ハーネス検査 |
| case-03 | 非対話モード | 実行モード判定 |
| case-04 | ルート CLAUDE.md 既存プロジェクト | Phase 2 既存資産調査 |
| case-05 | git リポジトリでないプロジェクト | Phase 1 前提確認 |
| case-06 | 部分的に構築済みのハーネス（.sync-state.json なし） | Phase 1 部分的既存検査 |
| case-07 | コミットが 1 つもない git リポジトリ | Phase 1 コミット有無検査 |
| case-08 | 生成対象 10 件超過時のサブエージェント委譲 | Phase 4 委譲条件 + agents.md |

## 実行確認方法

各ケースの「入力」セクションのフレーズで Claude Code を起動し、「期待動作」「期待出力」と一致することを目視確認する。
本スキルは対象プロジェクトの状態に依存する AI 主導スキルのため、自動実行スクリプト（demo.sh）は適用外とし、目視確認を基本とする。

## ケース追加ルール

新しい分岐ロジックを追加した時は、対応するケースファイル（`case-{2 桁番号}_{snake_case 名}.md`）を必ず追加し、本一覧表を同期する。各ケースには「分岐の根拠」「関連ケース」セクションを含める。
