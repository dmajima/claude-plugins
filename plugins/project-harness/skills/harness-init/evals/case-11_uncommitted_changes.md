# case-11: 未コミット変更がある状態での初期構築

## 入力

```text
/project-harness:init
```

前提: 作業ツリーに未コミット変更が 5 件ある（コミット済みの HEAD は存在する）。

## 期待動作

1. Phase 1〜4 は通常どおり実行する（解析は作業ツリーの現在の内容に基づく）
2. Phase 5 で `.sync-state.json` の `last_synced_commit` を **HEAD の SHA** で初期化する（未コミット分は state に記録できない）
3. 報告で「未コミット変更が 5 件あり、ドキュメントには現在の内容を反映したが、同期基準は HEAD である。コミット後の `/project-harness:update` では未コミット分が新規差分として検出される」旨を明示する

## 期待出力

- 生成結果の報告 + 未コミット変更の件数と同期基準に関する注記

## 禁止事項（このケースで起きてはならないこと）

- 未コミット変更の存在を報告せずに完了すること（次回 update で「反映済みの内容が差分として再提示される」理由が利用者に分からなくなる）
- 未コミット変更を自動でコミットすること

## 分岐の根拠

procedures.md Phase 5「未コミット変更の扱い」。同期基準がコミット SHA である設計（sync-spec.md 節 1）から生じる制約の説明責任。
