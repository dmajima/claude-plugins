# case-09: 調査エージェント間の矛盾を裁定する

## 入力

```text
/project-harness:init
```

前提: Phase 3 の並列調査で、技術スタック担当（エージェント 1）と規約・用語担当（エージェント 4）が異なるフレームワークを報告した（例: 一方が Vue、他方が React）。

## 期待動作

1. 統合時にメインが調査結果間の矛盾を検出する（agents.md「エラー増幅への対策」）
2. メインが根拠として示されたソースを直接確認し、どちらが実態かを裁定する
3. 裁定できた場合: 正しい方を採用し、`.claude/CLAUDE.md` と `architecture/` に反映する
4. ソースからも判断がつかない場合: 生成物へ `TODO:` として両説を残し、報告でユーザに提示する（片方を推測で採用しない）
5. 根拠パスの実在をサンプリング確認する

## 期待出力

- 矛盾の内容（どのエージェントが何を報告したか）と裁定結果・根拠ファイル
- 裁定不能だった項目の `TODO:` 一覧

## 禁止事項（このケースで起きてはならないこと）

- 矛盾を検出せずどちらか一方を採用すること
- 根拠を確認せずに多数決・報告順で決めること
- 裁定不能な事項を確定事実として記載すること（捏造）

## 分岐の根拠

agents.md「エラー増幅への対策」。Independent 型並列調査に固有のエラー増幅リスクに対する防御ロジックであり、通常の統合（case-01）とは経路が異なる。
