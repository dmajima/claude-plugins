# case-08: 生成対象 10 件超過時のサブエージェント委譲

## 入力

```text
.claude ハーネスを初期化して
```

前提: 大規模プロジェクト。Phase 3 の機能一覧提示でユーザが「全機能」を選択し、生成対象ドキュメントが 10 件を超えた（例: specs 8 + system-designs 8 + flows 5）。

## 期待動作

1. Phase 4 で agents.md の生成エージェント構成に従い、**フォルダ単位（1 フォルダ = 1 エージェント）** で `general-purpose` サブエージェントへ並列委譲する
2. 各委譲プロンプトに「テンプレートパス・frontmatter 規則（structure-spec.md 節 5）・担当フォルダ分の解析結果・捏造禁止制約」を含める
3. 各フォルダの `CLAUDE.md` 索引・`references/CLAUDE.md`・`.claude/CLAUDE.md` は **メインが最後に生成** する
4. メインが全生成物の frontmatter（title / sources / updated）とインデックス整合を最終確認する

## 期待出力

- case-01 と同等の報告 + 委譲したフォルダとエージェント数の内訳

## 禁止事項（このケースで起きてはならないこと）

- 複数エージェントによる同一ファイルへの書き込み競合（フォルダ分割の破り）
- 委譲プロンプトへのテンプレートパス・捏造禁止制約の伝達漏れ
- エージェントによる索引 `CLAUDE.md` の生成（メインの責務）

## 分岐の根拠

procedures.md Phase 4「生成量が多い場合のエージェント委譲」（10 件超過が委譲条件）と agents.md の生成エージェント構成。
