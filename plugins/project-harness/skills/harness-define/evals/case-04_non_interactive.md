# case-04: 非対話モード

## 入力

```text
/project-harness:define --non-interactive docs/requirements-memo.md
```

前提: 2 パターンを扱う。（A）提供資料が引数・既存配置で特定できる。（B）提供資料が無い。

## 期待動作

### （A）提供資料が特定できる場合

1. `AskUserQuestion` を一切発火させずに進行する
2. Phase 3 のヒアリングはスキップし、Phase 2 で取り込んだ資料のみからドキュメントを生成する
3. Phase 5 の合意確認をスキップし、生成物は **すべて `status: draft` のまま** とする
4. Phase 6 のコミットは実施せず、手順を報告に含める。ユーザ判断が必須の事項（`git init` / 初回コミット / `.claude/` 外への書き込み）は自動処置せず報告のみとする
5. Phase 7 の検証スクリプトと `git status --porcelain` の確認は実施する

### （B）提供資料が無い場合

6. ドキュメントを生成せずに中断し、対話モードでの再実行を案内する

## 期待出力

- （A）: 生成ファイル一覧・**「合意確認未実施（すべて `draft`）」の明記**・未確定事項一覧・検証結果・保留したユーザ判断事項（初回コミット等）の手順
- （B）: 資料が特定できないため中断した旨と、対話モードでの再実行案内

## 禁止事項（このケースで起きてはならないこと）

- 非対話モードでの `AskUserQuestion` 発火（進行が停止するため）
- 合意確認を経ていないドキュメントの `agreed` 化
- 無確認での `git init`・コミット実行
- 資料が無い状態でヒアリング内容を推測してドキュメントを生成すること
- 報告での「合意確認未実施」の記載漏れ

## 分岐の根拠

SKILL.md の実行モード判定表（資料から `draft` のみ生成し、資料が無い場合は中断）。procedures.md では Phase 3 冒頭（対話モードのみ実施）・Phase 5 手順 5（本 Phase をスキップし報告に明記）・Phase 6 末尾（コミットを実施せず手順を報告）が対応する。
