# case-07: コード実態が十分あるプロジェクトでの起動（スキル切替の確認）

## 入力

```text
/project-harness:define
```

前提: 対象は git リポジトリでコミットあり。実装が進んでおり、ソースファイルが相当数存在する。ハーネスの有無は問わない。

## 期待動作

1. Phase 1 のコード実態検査で、言語別ファイル数等からソース規模を概観し、コード実態が十分あることを検出する
2. 対話モードでは SKILL.md の「スキル選択の 2 軸判定」表を提示し、`AskUserQuestion` で意図を確認する
   - `harness-init` へ切替（ハーネス未構築で、既存コードの解析から構築したい）
   - `harness-update` へ切替（ハーネスがあり、コード変更を反映したい）
   - 本スキルを続行（未実装機能の仕様を先行作成したい）
3. 続行が選ばれた場合のみ Phase 2 以降へ進む。既存ハーネスがある場合は case-03 のドキュメント追加モードとなる
4. 非対話モードでは切替提案のみを行い中断する

## 期待出力

- 2 軸判定表と、コード実態の観測結果（言語別ファイル数等の判断根拠）
- 選択に応じた案内（切替先スキルの起動方法、または続行して生成した内容の報告）
- 非対話時: 切替提案と、中断した旨・対話モードでの再実行案内

## 禁止事項（このケースで起きてはならないこと）

- コード実態を確認しないまま spec-first の生成を進めること
- 2 軸判定を提示せずにエージェントの判断でスキルを切り替える、または続行すること
- コード解析で読み取った内容を「合意根拠」として記載すること（合意根拠に書けるのは対話で明示的に承認された内容・提供資料の記載のみ。ソース根拠として書く場合は `sources` を伴う）
- 非対話モードでの `AskUserQuestion` 発火・切替可否の自動判断

## 分岐の根拠

procedures.md Phase 1 の検査表「コード実態」行（2 軸判定表の提示と `AskUserQuestion` による確認、非対話では切替提案のみで中断）。判定表そのものは SKILL.md「スキル選択の 2 軸判定」。根拠種別の区別は authoring-spec.md 節 1.1。
