description: 対象プロジェクトを解析して .claude ハーネスを初期構築
argument-hint: "[対象パス] [--non-interactive]"
---

ユーザの引数: $ARGUMENTS

`project-harness` プラグインの `harness-init` スキルを Skill ツール経由で起動し、`.claude` ハーネス（`CLAUDE.md` + `references/` 配下のドキュメント体系）の初期構築を開始してください。

## 動作モード判定

| 引数 | モード | 動作 |
|-----|-------|------|
| 空 | 対話 | カレントディレクトリを対象としてスキルへ渡す（取り込み方針・生成範囲はスキル側で確認） |
| 対象パスあり | 対話 | 指定パスを対象プロジェクトルートとしてスキルへ渡す |
| `--non-interactive` フラグ含む | 非対話 | フラグごとスキルへ渡す（スキル側で確認なし進行） |

`対象パス` は **独立した git リポジトリのルート** を指定する（例: `/project-harness:init ../another-repo`）。既存リポジトリのサブフォルダを指定してはならない。ハーネスは git リポジトリのルート直下の `.claude/` に構築され、鮮度検知フックもリポジトリルートの `.claude/references/.sync-state.json` のみを参照するため、サブフォルダに構築すると通知が機能しない。モノレポでパッケージごとにドキュメントを分けたい場合は、リポジトリルートに 1 つのハーネスを構築し、`specs/<package>/` のサブ名前空間を使う。

## ルーティング

| 引数パターン | 起動スキル |
|------------|----------|
| すべて（対象パス + 任意フラグ） | `project-harness:harness-init` |

このコマンドは薄いラッパーであり、前提確認・既存資産調査・プロジェクト解析・ハーネス生成・同期状態初期化の実処理はすべて `harness-init` スキルが行う。

ハーネスが構築済み（`.claude/references/.sync-state.json` が存在）の場合、スキルは `/project-harness:update` への切替を提案する。

このコマンドは対象プロジェクトに `.claude` ハーネスを構築するものであり、Claude Code 組み込みの `/init`（リポジトリルートの `CLAUDE.md` を生成する機能）とは別。組み込み `/init` で作られたルート `CLAUDE.md` が既にある場合、本コマンドはその内容を取り込んだうえで `@.claude/CLAUDE.md` の import 行を追記する（既存記述は削除しない）。

## 共通の終了処理

スキル完了後、以下を提示する:

- 生成ファイル一覧（フォルダ別件数）と解析サマリ
- ハーネス検証スクリプトの結果
- `TODO:`（未確認事項）の残数と代表例（未実行の検証コマンドを含む）
- 以後の運用案内（`/project-harness:update` による同期・SessionStart フックの鮮度通知）

`git commit` 以降の操作はこのコマンドからは実行しない。
