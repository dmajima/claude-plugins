ユーザの引数: $ARGUMENTS

`project-harness` プラグインの `harness-define` スキルを Skill ツール経由で起動し、プログラム実態がない状態（要件定義・仕様作成フェーズ）での `.claude` ハーネス構築と仕様先行ドキュメント作成を開始してください。

## 動作モード判定

| 引数 | モード | 動作 |
|-----|-------|------|
| 空 | 対話 | カレントディレクトリを対象とし、要件ヒアリング・生成・合意確認をスキル側で行う |
| 対象パスあり | 対話 | 指定パスを対象プロジェクトルートとしてスキルへ渡す |
| 資料パスあり | 対話 | 指定資料を取り込み対象（合意根拠）としてスキルへ渡す（原本は変更されない） |
| `--non-interactive` フラグ含む | 非対話 | フラグごとスキルへ渡す（資料がある場合のみ `draft` を生成。ヒアリング・合意確認・コミットは行わない） |

`対象パス` は **独立した git リポジトリのルート**（またはこれから `git init` する新規フォルダ）を指定する。git 未初期化・コミット 0 件でも実行できる（`git init` と初回コミットはスキル側でユーザ承認のうえ実施される）。

## ルーティング

| 引数パターン | 起動スキル |
|------------|----------|
| すべて（対象パス + 資料パス + 任意フラグ） | `project-harness:harness-define` |

このコマンドは薄いラッパーであり、前提確認・資料取り込み・要件ヒアリング・ドキュメント生成・合意確認・同期状態初期化の実処理はすべて `harness-define` スキルが行う。

コード実態が十分あるプロジェクトで起動された場合、スキルは `harness-init`（コード解析による構築）/ `harness-update`（コード変更の反映）との使い分けを提示して意図を確認する。未実装機能の仕様先行作成（spec-first 追加）であれば本スキルのまま続行できる。

## 共通の終了処理

スキル完了後、以下を提示する:

- 生成ファイル一覧（フォルダ別件数）
- 合意状態（`agreed` / `draft` の件数）
- 未確定事項一覧（`TODO:` の要旨。spec-first では多いのが正常）
- ハーネス検証スクリプトの結果
- 以後の運用案内（実装開始後の `/project-harness:update` による実装追随・仕様追加時の本コマンド再実行）

`git commit` 以降の操作は、スキル内で承認された初回コミット（同期基準の確立）を除き、このコマンドからは実行しない。
