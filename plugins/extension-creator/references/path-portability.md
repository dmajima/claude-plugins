# ポータブルパス規約（SSOT）

`extension-creator` が生成する全ファイルにおける、環境非依存パス記法の規約。

## 1. 推奨変数

| 用途 | 変数 | 設定タイミング |
|-----|------|---------------|
| スキル自身のディレクトリ | `${CLAUDE_SKILL_DIR}` | スキル実行時に Claude Code が自動設定 |
| プラグイン自身のルート | `${CLAUDE_PLUGIN_ROOT}` | プラグイン由来のスキル/コマンド/フック実行時 |
| プラグインの永続データ領域 | `${CLAUDE_PLUGIN_DATA}` | プラグイン実行時 |

## 2. NG パターン（必須修正）

| パターン | 例 |
|---------|---|
| Windows ドライブレター付き絶対パス | `C:\Users\foo\...` `C:/inetpub/...` |
| Unix 系絶対パス | `/home/foo/...` `/Users/foo/...` |
| Windows 環境変数展開 | `%USERPROFILE%\...` `%APPDATA%\...` |
| シェル HOME 変数 | `$HOME/...` `${HOME}/...` |
| UNC パス | `\\server\share\...` |
| ホスト名込みパス | `\\DESKTOP-ABC123\...` |
| 個人名・社員 ID 入りパス | `C:/Users/{username}/...` |
| `.claude/skills/{name}/` ハードコード（自スキル参照） | スキル内自己参照で禁止。`${CLAUDE_SKILL_DIR}` を使う |

## 3. OK パターン

| パターン | 例 | 理由 |
|---------|---|------|
| Claude Code の標準変数 | `${CLAUDE_SKILL_DIR}/scripts/...` | プラグイン実行時に自動解決 |
| 相対パス | `./scripts/foo.sh` | カレントディレクトリ基準 |
| ホームディレクトリのチルダ表記 | `~/.claude/skills/` | シェルが各環境で展開 |
| プレースホルダ表記 | `<repo>/.claude/...` `{plugin-name}` | ドキュメント上の汎用パス |
| URL | `https://example.com/...` | ローカルパスではない |
| 標準ツール汎用インストール先 | `/usr/bin/python` | 多くの環境で同位置 |

## 4. 例外: 指定システムへの依存

プラグインが意図的に特定システムを利用する場合、絶対パス・特定 URL のハードコードを許容する。条件:

1. 当該プラグインの README.md に **「依存システム（External Dependencies）」** セクションを設けて明記する
2. その依存はプラグインの **本質的な目的** であること（個人ローカル環境ではない）
3. 依存パス/URL が変わりうる場合は変更箇所を明示する

許容例: `https://tfs.w2solution.com/tfs/Engineering/...`（プラグインが対象とするマーケットプレイス）

NG 例: 個人のチェックアウトパス（`C:\inetpub\wwwroot\...`）、開発者の個人ディレクトリ

## 5. 検出手順

スキル・プラグインを生成・更新したファイル全体に対し、以下のパターンで Grep する。

| 検出対象 | 正規表現例 |
|---------|----------|
| Windows ドライブレター | `[A-Za-z]:[\\/]` |
| Unix ユーザディレクトリ | `/home/\|/Users/\|/root/` |
| Windows 環境変数 | `%USERPROFILE%\|%APPDATA%\|%LOCALAPPDATA%` |
| シェル HOME 変数 | `\$HOME\|\$\{HOME\}` |
| UNC パス | `\\\\[A-Za-z0-9._-]+\\` |

## 6. 検出結果の分類

検出された各パスを 3 分類:

| 分類 | 対応 |
|-----|------|
| NG（必須修正） | 削除 or `${CLAUDE_SKILL_DIR}` 等で書き換え |
| 例外候補（要確認） | README の「依存システム」セクション追記 |
| OK（誤検出） | 修正不要 |

## 7. ユーザ提示フォーマット

```
パスのポータビリティチェック結果:

[NG] {file_path}:{line}
  検出: {検出した文字列}
  理由: {NG 理由}
  推奨: {推奨修正方針}

[要確認] {file_path}:{line}
  検出: {検出した文字列}
  理由: {依存システム候補}
  推奨: README の「依存システム」セクション追記を確認

修正方針を指示してください:
1. すべて推奨どおり修正
2. 個別に対応
3. このまま続行（注意事項として記録）
```

## 8. 適用タイミング（必須）

以下のタイミングで必ずチェックを実施:

- スキル/プラグイン生成直後
- 既存ファイルを大規模編集した後
- マーケットプレイスへ公開する前（最終チェック）

## 9. 検出が困難な誤りパターン

| パターン | 検出方法 |
|---------|---------|
| 自然言語中のパス記述（「`C:\Users\foo\...` を参照」） | Grep で同じパターン |
| コードコメント内のパス | Grep で同じパターン |
| 半角全角混在パス | 全角コロン `：` `\` 等を別途 Grep |

## 10. 修正後の再検証

修正完了後、再度 Grep で NG パターンが残っていないことを確認する。例外として残ったパスは README の「依存システム」セクションに必ず記載する。
