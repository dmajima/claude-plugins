# description 設計ガイド（SSOT）

スキル・コマンド・エージェント・プラグインの `description` フィールドの設計指針。

## 1. 用途別の方針

| 対象 | 主な読み手 | 方針 |
|-----|----------|------|
| プラグイン `plugin.json` | 人間（マーケットプレイス UI） | 端的に 1 文 |
| スキル `SKILL.md` frontmatter | AI（自動トリガー判定） | 詳細・網羅的に |
| コマンド `*.md` frontmatter | 人間（コマンド一覧） | 端的に 1 文 |
| エージェント `*.md` frontmatter | AI（呼び出し判定） | 詳細・網羅的に |

## 2. プラグインの description

| 制約 | 値 |
|-----|---|
| 文字数 | 80 文字以内 |
| 文体 | 体言止め可。「〜を支援するツールキット」「〜を自動化するプラグイン」等 |
| 含めるもの | 主要な目的 1 つ |
| 避けるもの | 機能リスト・トリガーフレーズ |

例:

```json
{
  "description": "Claude Code の各種拡張要素の作成からマーケットプレイス公開までを支援するツールキット"
}
```

## 3. スキルの description

スキルの description は AI が **自動トリガー判定** に使うため、以下の 4 要素を含める。

### 3.1 必須 4 要素

```markdown
description: {主目的の 1 文}。{トリガーフレーズ例}「{例1}」「{例2}」「{例3}」などの依頼で起動する。Use when {英語のトリガー条件}. {責務外の明示} (use {他スキル名} for {担当業務}).
```

### 3.2 構成要素

| 要素 | 内容 | 必須 |
|-----|------|-----|
| 主目的 | スキルが何をするか 1 文 | 必須 |
| トリガーフレーズ例（日本語） | ユーザが発しそうなフレーズを 3〜5 個 | 必須 |
| Use when | 英語の起動条件 | 必須 |
| Skip when | スキップすべき場面 | 推奨 |
| 責務外の明示 | このスキルがやらないこと + 担当スキル | 推奨 |

### 3.3 例

```markdown
description: Claude Code のスキルを新規作成・既存改修するスキル。「新しいスキル foo を作って」「skill foo を更新」「○○用のスキルが欲しい」などの依頼で起動する。Use when the user wants to create, scaffold, or modify a Claude Code skill. SKIP when the user asks for a plugin (use plugin-creator), command (use command-creator), or agent (use agent-creator).
```

### 3.4 アンチパターン

| パターン | 問題 |
|---------|------|
| description が短すぎる（30 文字以下） | トリガー判定の精度が低下 |
| トリガーフレーズが抽象的 | 関連性のない場面で誤起動 |
| Use when がない | 別言語ユーザで誤判定 |
| 責務外を書かない | 重複起動の原因 |

## 4. コマンドの description

| 制約 | 値 |
|-----|---|
| 文字数 | 60 文字以内 |
| 文体 | 体言止め可 |
| 含めるもの | コマンドの効果 1 つ |
| 避けるもの | 引数仕様（本文に書く） |

例:

```markdown
---
description: 拡張要素（スキル/プラグイン/コマンド/エージェント/フック）の作成・公開を支援
---
```

## 5. エージェントの description

スキル同様 AI のトリガー判定に使われる。以下を含める。

| 要素 | 内容 |
|-----|------|
| 専門領域 | エージェントの専門性 |
| 評価観点 | レビュー時に何を見るか |
| 起動条件 | いつ呼び出されるか |

例:

```markdown
---
name: code-reviewer
description: コード品質・正確性・パフォーマンスを評価する実装エンジニア。コード生成・リファクタリング・コードレビュー時に使用する。
---
```

## 6. description 検証チェックリスト

スキル・エージェントの description 作成後に以下を確認:

- [ ] トリガーフレーズが具体的（抽象語のみではない）
- [ ] Use when が含まれる
- [ ] 責務外（or Skip when）が含まれる
- [ ] 重複起動しうる他スキル名が明示されている
- [ ] 1 行内に収まる（改行禁止）

## 7. 共通の禁止事項

- 改行（YAML frontmatter の文字列内）
- 過去形・未来形の混在（現在形で統一）
- 主語の省略（明確に対象を書く）
- バージョン情報の記載（plugin.json の `version` で管理）
