# ailead フロー詳細手順

ailead の外部共有リンクが提示された場合の議事録作成手順。

## 前提

- ailead 共有リンクが有効（期限内）であること
- `connector:ailead` スキルが利用可能であること（connector プラグインの依存）

## 手順

### Step 1: ailead データ取得

`connector:ailead` スキルを起動してデータを取得する。

```
Skill(skill: "connector:ailead", args: "<ailead 共有リンク URL>")
```

取得されるデータ:
- `transcript.txt` — 文字起こし全文
- `summary.md` — AI 会議要約（トピック別）
- `metadata.json` — 会議メタデータ
- `response.json` — GraphQL レスポンス全文

### Step 2: メタデータの整理

`metadata.json` から議事録ヘッダー情報を構成する。

| metadata フィールド | 議事録項目 |
|-------------------|-----------|
| `title` | 会議名 |
| `startDatetime` + `duration` | 日時・所要時間 |
| `system` | 場所/方式（TEAMS → Microsoft Teams 等） |
| `participants[].name` | 参加者一覧 |
| `hostUser` | 主催者 |

**組織名の正規化**:
- `organization` は正式社名（例: 「日世株式会社」「Ｗ２株式会社」）に統一する。
  発話・会議タイトル中の略称（「日世」「日世様」等）をそのまま使わない
- 正式社名が文字起こしから特定できない場合は、会議タイトル・参加者表示名から
  最も完全な表記を採用する
- 主催者（議事録作成側）の参加者には必ず `role: "host"` を設定する
  （レンダラーが自社判定・敬称制御に使用するため）

### Step 3: トピック要約をベースに骨格を構成

> **フォールバック**: `callSummary` が null または `topics` が空の場合、
> トピック骨格は構成できないため [`generic-flow.md`](generic-flow.md) の
> Step 2 以降（文字起こしからのゼロ構造化）に切替える。
> メタデータの整理（Step 2）までは本フローの手順を使用してよい。

`workspace/response.json` 内の `callSummary.topics` を読み込み、
議事録の議題構造を構成する。

各トピックの `category` を以下のように分類する:

| category | 議事録での扱い |
|----------|--------------|
| `SHARE` | 情報共有・説明 |
| `DISCUSSION` | 議論・検討 |
| `DECISION` | 決定事項 → 「決定事項」セクションにも転記 |
| `CONCERN` | 懸念事項・課題 |
| `SUGGESTION` | 提案 |
| `DIALOGUE` | 対話・質疑応答 |
| `SCHEDULE` | スケジュール・次回予定 → 「次回予定」セクションにも転記 |

トピックは `dateTime`（秒）の昇順に並べ、会議の時系列に沿った構成にする。

### Step 4: 文字起こしとの照合

構造化の過程で、トピック要約の内容を文字起こしで裏付ける。

- 各トピックの `dateTime` を起点に、文字起こしの該当時間帯のセグメントを参照する
- トピックの `description` と文字起こしの内容が大きく乖離する場合は、文字起こし側を優先する
- 発話者名がトピック側と文字起こし側で異なる場合は修正する

突合検証の詳細（漏れ検出・検証ログ出力）は `minutes-reviewer` スキルが担当するため、ここでは構造化に必要な範囲の照合に留める。

### Step 5: 議事録の整形

[`template/minutes-template.md`](../template/minutes-template.md) に従い、最終的な議事録を構成する。

**整形ルール**:

1. **議題名**: ailead トピックの `title` をベースに、必要に応じて簡潔化・日本語として自然な表現に修正する
2. **議論内容**: `description` をベースに、検証で発見した補足・修正を反映する
3. **決定事項**: 会議中に明示的に決定された事項を抽出し、表形式でまとめる
4. **アクションアイテム**: 担当者・期限・タスク内容を表形式でまとめる
5. **次回予定**: `SCHEDULE` カテゴリのトピックから抽出する

**文体ルール**:

- 「である」調で統一する
- 発言の直接引用は避け、要約表現を使う
- 専門用語・固有名詞はそのまま保持する
- 曖昧な表現（「〜かもしれない」「〜と思う」）は、発言者の見解として記録する

### Step 6: 出力

構造化データを `workspace/minutes.json` として出力する。
最終出力形式（Markdown / docx）への変換は下流スキル（`md-renderer` / `docx-renderer`）が担当する。
