# ailead フロー詳細手順

ailead の外部共有リンクが提示された場合の議事録作成手順。

## 前提

- ailead 共有リンクが有効（期限内）であること
- `ailead-fetcher` スキルが利用可能であること

## 手順

### Step 1: ailead データ取得

`ailead-fetcher` スキルを起動してデータを取得する。

```
Skill(skill: "ailead-fetcher", args: "<ailead 共有リンク URL>")
```

取得されるデータ:
- `transcript.txt` — 文字起こし全文
- `summary.md` — AI 会議要約（トピック別）
- `metadata.json` — 会議メタデータ
- `response.json` — GraphQL レスポンス全文

### Step 2: メタデータの整理

`metadata.json` から議事録ヘッダー情報を構成する。

| metadata フィールド | 議事録項目 |
|-------------------|-----------|
| `title` | 会議名 |
| `startDatetime` + `duration` | 日時・所要時間 |
| `system` | 場所/方式（TEAMS → Microsoft Teams 等） |
| `participants[].name` | 参加者一覧 |
| `hostUser` | 主催者 |

### Step 3: トピック要約をベースに骨格を構成

`workspace/response.json` 内の `callSummary.topics` を読み込み、
議事録の議題構造を構成する。

各トピックの `category` を以下のように分類する:

| category | 議事録での扱い |
|----------|--------------|
| `SHARE` | 情報共有・説明 |
| `DISCUSSION` | 議論・検討 |
| `DECISION` | 決定事項 → 「決定事項」セクションにも転記 |
| `CONCERN` | 懸念事項・課題 |
| `SUGGESTION` | 提案 |
| `DIALOGUE` | 対話・質疑応答 |
| `SCHEDULE` | スケジュール・次回予定 → 「次回予定」セクションにも転記 |

トピックは `dateTime`（秒）の昇順に並べ、会議の時系列に沿った構成にする。

### Step 4: 文字起こしとの突合検証

[`verification-rules.md`](../verification-rules.md) に従い、以下を検証する。

#### 4.1 トピック単位の検証

各 ailead トピックについて:

1. `dateTime` を起点に、文字起こしの該当時間帯のセグメントを特定する
   - `transcript.txt` の `[HH:MM:SS]` タイムスタンプを参照
   - トピック前後 1〜2 分の範囲を確認する
2. トピックの `description` が文字起こしの内容と一致するか検証する
3. `speakerName` が実際の発言者と一致するか検証する

#### 4.2 漏れの検出

文字起こし全文を通読し、以下のパターンを探す:

**決定を示す表現**:
- 「〜にしましょう」「〜で決定」「〜でいきます」「〜の方針で」
- 「〜でお願いします」「〜で進めます」「〜に変更します」

**アクションを示す表現**:
- 「〜さん、確認お願い」「次回までに〜」「〜を準備」
- 「〜を調べて」「〜を共有して」「〜をまとめて」

**懸念・リスクを示す表現**:
- 「課題は〜」「問題は〜」「懸念が〜」「リスクとして〜」
- 「注意が必要」「難しい」「検討が必要」

**数値・具体情報**:
- 金額、日付、期限、件数、パーセンテージ
- URL、システム名、設定値

これらが ailead トピックに反映されていない場合は追加対象とする。

#### 4.3 検証ログの出力

検証結果を `workspace/verification-log.md` に記録する。
フォーマットは [`verification-rules.md`](../verification-rules.md) セクション 3 を参照。

### Step 5: 議事録の整形

[`template/minutes-template.md`](../template/minutes-template.md) に従い、最終的な議事録を構成する。

**整形ルール**:

1. **議題名**: ailead トピックの `title` をベースに、必要に応じて簡潔化・日本語として自然な表現に修正する
2. **議論内容**: `description` をベースに、検証で発見した補足・修正を反映する
3. **決定事項**: 会議中に明示的に決定された事項を抽出し、表形式でまとめる
4. **アクションアイテム**: 担当者・期限・タスク内容を表形式でまとめる
5. **次回予定**: `SCHEDULE` カテゴリのトピックから抽出する

**文体ルール**:

- 「である」調で統一する
- 発言の直接引用は避け、要約表現を使う
- 専門用語・固有名詞はそのまま保持する
- 曖昧な表現（「〜かもしれない」「〜と思う」）は、発言者の見解として記録する

### Step 6: 出力

完成した議事録を `minutes.md` としてセッション直下に配置する。

ユーザーへの報告内容:
- 議事録の概要（議題数・決定事項数・アクションアイテム数）
- 検証で発見した修正・追加の件数
- HLS 動画 URL（ダウンロードが必要な場合の案内）
