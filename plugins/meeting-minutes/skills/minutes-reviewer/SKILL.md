# Minutes Reviewer

構造化議事録データを文字起こしと突合検証するレビュースキル。

## 責務

- minutes.json と transcript.txt を照合し、議事録の正確性・網羅性を検証する
- 文字起こし全文を通読し、各議題の正確性・決定事項の網羅性・アクションアイテムの完全性を検証する
- verification-log.md と review-result.json を出力する

## 責務外

- 議事録の構造化・修正（minutes-composer が担当）
- データ取得（ailead-fetcher / transcript-converter が担当）

## トリガー条件

- minutes-composer が構造データを生成した後、docx 出力前のレビューステップとして実行
- ユーザーが議事録のレビュー・チェックを依頼した場合

## 前提

- セッション作業領域の `workspace/` に minutes.json と transcript.txt が存在すること
- AI 生成の議事録には事実の歪曲・重要発言の漏れ・発言者の誤帰属等のリスクがあるため、独立した検証が必要

## 重要な制約

- 必ずフレッシュなサブエージェントとして起動すること（作成時のバイアス排除のため）
- メインコンテキストで議事録を作成した Claude が自身でレビューしてはならない

## 実行モード判定

| 入力 | モード | 動作 |
|-----|-------|------|
| workspace/ に minutes.json + transcript.txt が存在 | 非対話 | 自動で突合検証を実行 |
| 入力ファイル不在 | 対話 | minutes-composer の実行を提案 |

**このスキルは必ずフレッシュなサブエージェントとして起動されること。**
メインコンテキストで議事録を作成した Claude が自身でレビューすると、
作成時のバイアスが残り漏れを見逃すリスクがある。
独立したエージェントインスタンスで第三者視点の検証を行う。

## 実行フロー

1. メインコンテキストが Agent ツールでフレッシュインスタンスを起動する
2. workspace/minutes.json と workspace/transcript.txt をセッション作業領域から読み込む
3. 各議題について文字起こしと突合し、正確性・網羅性を検証する
4. 決定事項・アクションアイテムの漏れを検出する
5. 検証結果を verification-log.md と review-result.json に出力する
6. 修正提案がある場合はメインコンテキストに返却する

## フレッシュ起動の方法

```
Agent({
  description: "議事録の突合レビュー",
  subagent_type: "general-purpose",
  prompt: "<レビュー指示 + ファイルパス>",
  mode: "auto"
})
```

## 検証項目

| 検証項目 | 内容 |
|---------|------|
| トピック正確性 | 各議題の要約が文字起こしの内容と一致するか |
| 漏れ検出 | 決定事項・アクションアイテム・重要議論が議事録に含まれているか |
| 発言者帰属 | 議論内容が正しい発言者に帰属しているか |
| 数値・固有名詞 | 金額・日付・システム名等の具体値が正確か |
| アクション完全性 | 「次回までに確認」等の暗黙的なアクションが拾われているか |

## 入力

| ファイル | 説明 |
|---------|------|
| `workspace/minutes.json` | minutes-composer が生成した構造化議事録データ |
| `workspace/transcript.txt` | 文字起こし全文（タイムスタンプ・発話者付き） |
| `workspace/response.json` | ailead 生データ（ailead ソースの場合のみ） |

## 出力

| ファイル | 配置先 | 説明 |
|---------|-------|------|
| `verification-log.md` | `workspace/` | 検証ログ（修正・追加の詳細 + 根拠引用） |
| `review-result.json` | `workspace/` | 検証結果の構造データ（修正提案を含む） |

## 検証ルール

詳細: [`references/verification-rules.md`](references/verification-rules.md)

### 決定を示す表現の検出パターン

- 「〜にしましょう」「〜で決定」「〜でいきます」「〜の方針で」
- 「〜でお願いします」「〜で進めます」「〜に変更します」

### アクションを示す表現の検出パターン

- 「〜さん、確認お願い」「次回までに〜」「〜を準備」
- 「〜を調べて」「〜を共有して」「〜をまとめて」

### 追加すべき項目の基準

以下のいずれかに該当し、かつ minutes.json に含まれていない場合は追加を提案する:

- 明示的な決定が行われた
- 具体的なアクションアイテムが発生した
- 数値・期限・金額等の具体値が決まった
- 次回以降の進め方に影響する合意があった

## 検証ログのフォーマット

```markdown
# 突合検証ログ

## 検証サマリー

| 項目 | 件数 |
|------|------|
| 議題数 | {{N}} |
| 正確と判定 | {{N}} |
| 修正提案 | {{N}} |
| 追加提案（決定事項） | {{N}} |
| 追加提案（アクションアイテム） | {{N}} |

## 修正・追加の詳細

### [修正] 議題: {{議題名}}
- **現在の記述**: {{minutes.json の内容}}
- **問題点**: {{何が不正確か}}
- **修正提案**: {{修正内容}}
- **根拠**: 文字起こし [HH:MM:SS] 「{{引用}}」
```
