# Case 01: 修正提案あり（誤帰属・漏れ検出）

## 入力

| 項目 | 値 |
|-----|---|
| 起動条件 | `minutes-composer` の出力完了後、フレッシュなサブエージェントとして起動 |
| 前提ファイル | `workspace/minutes.json`（一部に誤った発言者帰属・決定事項の漏れを含む）、`workspace/transcript.txt`（正確な文字起こし） |
| 誤りの例 | minutes.json 内で「田中太郎」の発言が「鈴木花子」に帰属されている。文字起こしに「次回までに資料を準備する」というアクションアイテムがあるが minutes.json に含まれていない |

## 期待動作

1. メインコンテキストが Agent ツールでフレッシュインスタンスを起動する（作成バイアス排除のため）
2. `workspace/minutes.json` と `workspace/transcript.txt` を読み込む
3. 各議題について文字起こしとの突合検証を実行する:
   - トピック正確性: 各議題の要約が文字起こしの内容と一致するか検証する
   - 発言者帰属: 議論内容が正しい発言者に帰属しているか検証する
   - 数値・固有名詞: 金額・日付・システム名等の具体値が正確か検証する
4. 発言者の誤帰属を検出する:
   - 文字起こしの `[HH:MM:SS]` 付近の発言から正しい発言者を特定する
   - 修正提案に正しい発言者と根拠（タイムスタンプ・引用テキスト）を記録する
5. 漏れたアクションアイテムを検出する:
   - 文字起こし内の「次回までに～」「～を準備」等のパターンを検出する
   - minutes.json の `actionItems` に含まれていないことを確認する
   - 追加提案として記録する
6. `workspace/verification-log.md` と `workspace/review-result.json` を出力する
7. 修正提案をメインコンテキストに返却する

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| `workspace/verification-log.md` | 検証サマリー（修正提案 N 件、追加提案 N 件）+ 修正・追加の詳細（現在の記述・問題点・修正提案・根拠引用を含む） |
| `workspace/review-result.json` | 検証結果の構造データ。修正提案（corrections）と追加提案（additions）を含む |
| メインへの返却 | 修正提案のサマリー（修正件数・追加件数・具体的な修正内容の要約） |
| 終了状態 | 成功（修正提案をメインコンテキストに返却し、minutes.json への反映を促す） |

## 分岐の根拠

SKILL.md「実行フロー」ステップ3-5: 「各議題について文字起こしと突合し、正確性・網羅性を検証する」「決定事項・アクションアイテムの漏れを検出する」「検証結果を verification-log.md と review-result.json に出力する」。SKILL.md「検証項目」表の「発言者帰属」「アクション完全性」に該当。`references/verification-rules.md` の Step 1（トピック単位の突合）と Step 2（漏れの検出）に該当。
