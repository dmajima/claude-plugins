# Case 02: 修正なし（正確な議事録の通過）

## 入力

| 項目 | 値 |
|-----|---|
| 起動条件 | `minutes-composer` の出力完了後、フレッシュなサブエージェントとして起動 |
| 前提ファイル | `workspace/minutes.json`（正確な議事録データ）、`workspace/transcript.txt`（文字起こし全文） |
| 議事録の状態 | 全議題が文字起こしと正確に一致し、決定事項・アクションアイテムに漏れがなく、発言者帰属も正しい |

## 期待動作

1. メインコンテキストが Agent ツールでフレッシュインスタンスを起動する
2. `workspace/minutes.json` と `workspace/transcript.txt` を読み込む
3. 各議題について文字起こしとの突合検証を実行する:
   - トピック正確性: 全議題が文字起こしと一致 → 「正確」と判定する
   - 発言者帰属: 全発言が正しい発言者に帰属 → 「正確」と判定する
   - 数値・固有名詞: 具体値が全て正確 → 「正確」と判定する
4. 漏れ検出を実行する:
   - 決定事項: 文字起こし内の決定パターン（「～にしましょう」等）が全て minutes.json に含まれている
   - アクションアイテム: 文字起こし内のアクションパターン（「～確認お願い」等）が全て含まれている
5. 修正提案が 0 件であることを確認する
6. `workspace/verification-log.md` と `workspace/review-result.json` を出力する（修正なしの検証ログ）
7. 「修正なし」の結果をメインコンテキストに返却する

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| `workspace/verification-log.md` | 検証サマリー: 修正提案 0 件、追加提案 0 件。全議題が「正確と判定」と記録される |
| `workspace/review-result.json` | `corrections: []`, `additions: []`（空配列） |
| メインへの返却 | 「議事録の内容は文字起こしと一致しています。修正提案はありません。」等のサマリー |
| 終了状態 | 成功（修正不要。minutes.json をそのまま下流スキルに渡して出力可能） |

## 分岐の根拠

SKILL.md「実行フロー」ステップ6: 「修正提案がある場合はメインコンテキストに返却する」の裏パス（修正提案がない場合）。修正提案が 0 件の場合、minutes.json の変更は不要であり、そのまま docx-renderer / md-renderer に引き渡す。
