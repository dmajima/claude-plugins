# フロー制御原則（MANDATORY）

`pr-review` スキルの Step 1〜Step 8 実行時のフロー制御規範。SKILL.md「フロー制御原則」から参照される SSOT。

## 1. 連続実行（中断禁止）

Step 1 から Step 8 までは **単一の連続フローとして実行** する。途中で停止してユーザーの応答を待ってはならない。

| 許可される中断 | 禁止される中断 |
|--------------|--------------|
| Step 1.5 で認証情報が未設定（ユーザーへの問い合わせが必要） | connector からデータ取得後に「次は～を行います」と宣言して停止する |
| `AskUserQuestion` で明示的に判断を仰ぐ場面（モード選択等） | 取得した PR メタ情報・スレッド一覧をユーザーに提示して応答を待つ |
| HTTP エラー（401/403 等）で続行不能 | worktree 作成前に「worktree を作成します」と宣言して停止する |
| | code-review 委譲前に「レビューを開始します」と宣言して停止する |
| | code-review 結果返却後に「投稿しますか？」と確認して停止する |

コンテキスト圧縮（recap）でフローが途切れた場合は、最後に完了したステップの次から **即座に再開** する（ユーザーへの確認不要）。

## 2. connector 返却データの扱い（MANDATORY）

connector スキル（`connector:azure` / `connector:github`）から返却されるデータ（PR メタ情報・スレッド一覧・差分等）は **中間処理データ** であり、ユーザーへの提示物ではない。

**厳守事項**:

1. 返却データをそのままユーザーに表形式で提示 **しない**（表・テーブル・箇条書きいずれの形式でも禁止）
2. 返却データを受け取ったら、**テキスト出力をせずに即座に次のステップの処理に入る**
3. ユーザーへの報告は Step 8（完了報告）で統合して行う
4. 途中経過の通知は **最大 1 行**（例: 「PR #9839 メタ取得完了、worktree 作成中」）

**禁止される出力パターン**:

- 「以下は外部サービスから取得したデータです」+ 表の提示
- 「PR メタ情報を取得しました」+ 詳細の列挙
- 「スレッド一覧（N件）」+ 一覧の表示
- 取得データの要約・整形・再フォーマットをユーザーに向けて出力すること

**許可される出力**: 1 行以内の進捗通知のみ。直後に停止せず次のステップを即実行すること。

## 3. 宣言停止の禁止

以下のパターンは **明示的に禁止** する:

```
❌ 禁止パターン（データ取得後に停止）:
   connector からデータを取得
   → 取得データをユーザーに表示
   → 「次は worktree を作成して差分を取得し、レビューを開始します」
   → [停止]

✅ 正しいパターン（連続実行）:
   connector からデータを取得
   → 内部で解析（スレッド状態の把握・再レビュー判定等）
   → worktree 作成（Step 5.5）
   → code-review 委譲（Step 6）
   → コメント投稿（Step 7）
   → 完了報告（Step 8）
```

## 4. code-review 結果返却後の自動進行（MANDATORY）

code-review オーケストレーターから結果（state.yaml / review-summary.md）が返却された後、
**ユーザーの入力を待たずに** Step 7（PR コメント投稿）に自動で進行すること。

code-review の結果返却は pr-review フロー内部のデータ受け渡しであり、
ユーザーへの中間報告ポイントではない。結果の報告は Step 8（完了報告）で行う。

**禁止される出力パターン**:

- code-review 結果をユーザーに表示して「投稿しますか？」と確認すること
- code-review 結果サマリーをユーザーに向けて整形出力すること
- PR コメント投稿をユーザーの明示指示なしに省略すること（`auto-resolve=false` 指定時を除く）

**許可される出力**: 1 行以内の進捗通知のみ（例: 「code-review 完了、PR 投稿中」）。直後に停止せず Step 7 を即実行すること。

## 5. サマリースレッド投稿の Verdict 非依存必須化（MANDATORY）

PR レビュー時のサマリースレッド投稿は、レビュー判定（Verdict）に**関係なく必須**とする。

| Verdict | サマリースレッド | インラインコメント |
|---------|----------------|------------------|
| OK（Ready to Merge） | **必須** | 投稿対象なし（指摘 0 件） |
| NG・再レビュー不要（Needs Attention） | **必須** | **必須**（Medium 指摘分） |
| NG・再レビュー要（Needs Work） | **必須** | **必須**（Critical/High/Medium 指摘分） |

理由:

- レビューが実施されたことの **証跡** として PR 上にサマリーが残る必要がある
- Verdict = OK でもサマリーがないと「レビュー未実施」と区別がつかない
- 改善提案（Low / Suggestions）の記録としても必要
