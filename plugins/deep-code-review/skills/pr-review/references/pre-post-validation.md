# 投稿前バリデーションチェックリスト

Step 7 の API 投稿ループにおいて、各コメントの投稿前に全項目を通過すること。
1 項目でも未通過の場合、当該コメントの API 投稿を実行しない。未通過項目を修正してから再試行する。

---

## チェック項目

```
□ [PATH] threadContext.filePath がリモートリポジトリのパスである
  - `/` で始まるリポジトリルート相対パスであること
  - `C:\` や `C:/Program Files/` 等のローカルパスを含まないこと
  - PR iterations/changes API で取得した実際のファイルパスと一致すること
  - jq への値渡しに --rawfile（ファイル経由）を使用していること
    （--arg での / 始まりパス渡しは MSYS 自動変換により禁止）

□ [ESCAPE] ホスト固有の予約文字エスケープが適用済みである
  - #<数字> パターンが意図しない自動リンクにならないこと
    - 意図しない場合（Markdown 文脈）: \# にエスケープ済み
    - HTML ブロック（<details> 内）のタグ間テキスト: \# は使わず「123件」等の言い換え、
      または <a href> 明示リンクに変更済み（comment-sanitization.md セクション 5.5.7 を適用）
    - 件数表記: 「No.123」「123件」等 # を使わない表現に変更済み
    - 意図的なリンク: Markdown 文脈は [表示](URL)、HTML ブロック内は <a href="URL">表示</a> 形式で明示済み
  - @<英数字> パターンがユーザーメンションにならないこと
  - !<数字> パターン（Azure DevOps）が PR リンクにならないこと
  - コード中の # @ ! はインラインコード（`）/ コードフェンス / <pre><code> で保護済みであること

□ [SANITIZE] comment-sanitization.md セクション 3-4 の対策が適用済みである
  - コード引用はコードフェンスで囲まれていること
  - 外部画像 URL / <img> タグが除去されていること
  - 危険スキームリンク（javascript: / data: 等）が除去されていること
  - 機密文字列パターンが伏字化されていること
  - comment-sanitization.md セクション 5.6 の投稿前チェックリストを通過済みであること

□ [TEMPLATE] コメント本文が comment-templates.md のテンプレートから組み立てられている
  - インラインコメント: セクション 2 のテンプレート構造に準拠
  - Finding ID が本文冒頭に含まれていること
  - 致命度が記載されていること

□ [SIGNATURE] 署名は connector が自動付加するため pr-review 側では付加・検証しない
  - 投稿本文の末尾に署名を含めないこと（connector が投稿前に自動付加する）
  - 署名の定義は connector プラグインの references/signatures.md（SSOT）を参照
```

---

## バリデーション失敗時の動作

- 未通過のコメントは API 投稿をスキップする
- 未通過項目を修正して再試行する
- Step 8 完了報告に「バリデーション不通過で修正した件数」を明記する
