# case-08 投稿前バリデーション失敗時の投稿スキップ

Step 7 の投稿前バリデーションで 1 項目以上が未通過の場合、当該コメントの API 投稿を実行せず修正後に再試行するケース。

## 入力

| 項目 | 内容 |
|-----|------|
| 起動フレーズ | "PR #789 をレビューして"（Azure DevOps、MSYS パス変換が発生するケース） |
| モード | 対話 |

## 分岐の根拠

SKILL.md Step 7 投稿前バリデーションチェックリスト「1 項目でも未通過の場合、当該コメントの API 投稿を実行しない」。

## 期待動作

- [PATH] filePath が `C:/Program Files/Git/...` に変換されている場合、バリデーション不通過
- バリデーション不通過のコメントは API 投稿をスキップする
- --rawfile 経由に修正して再試行する
- 修正後にバリデーションを再通過させてから投稿する
- Step 8 完了報告に「バリデーション不通過で修正した件数」を明記する
