# case-04 アクセシビリティ確認フレーズでの起動（トリガー検証）

ユーザーが画面変更のアクセシビリティ確認を自然言語で依頼して本スキルを直接起動するケース。トリガー条件による起動と、web-designer がアクセシビリティ・レスポンシブを重点評価する基本フローを検証する。

## 入力

| 項目 | 内容 |
|-----|------|
| 起動フレーズ | "画面の変更がアクセシビリティ的に問題ないか確認して" |
| 起動形態 | 単独（オーケストレーター不在・ユーザー直接起動） |
| 前提 | 差分に UI 変更（Vue.js コンポーネント・Liquid テンプレート・CSS 等）が含まれる |

## 分岐の根拠

SKILL.md「トリガー条件」の「「アクセシビリティを確認して」と言われた場合」、SKILL.md「実行フロー」手順 2（web-designer の起動）、references/checklist.md セクション B O1 / O8。本ケースはトリガー起動と重点観点（アクセシビリティ・レスポンシブ）の指定を検証するもので、WCAG 個別達成基準（コントラスト比 / キーボード操作 / ARIA / 代替テキスト）の網羅評価は case-09 が扱う。

## 期待動作

- トリガーフレーズ「画面の変更がアクセシビリティ的に問題ないか確認して」から本スキルが単独起動する（SKILL.md「トリガー条件」）
- web-designer エージェントを起動し、アクセシビリティ（WCAG）・レスポンシブ対応を重点評価する（SKILL.md「出力フォーマット」）
- Vue.js コンポーネント・Liquid テンプレート内のマークアップの問題も含めて確認する（SKILL.md「前提」の観点表・`${CLAUDE_PLUGIN_ROOT}/references/languages/html.md`）
- オーケストレーター不在のため、本スキル自身で progress.md を作成・維持する（checklist.md O8）
- 中間レポートは「## フロントエンド観点レビュー結果」+「### web-designer」の構造で返却する（checklist.md C-Auto-1 / O2）
- Finding ID（CR-NNN）の採番・Verdict 判定は行わない（checklist.md O9）
