# case-07 防御コード削除の回帰検出（U16: a11y 属性 / エラー表示 UI）

差分の削除側（`-` 行）で既存のアクセシビリティ属性・エラー表示 UI が失われ、追加側で同等の防御が再導入されていない回帰を web-designer が指摘する分岐を検証する。

## 入力

| 項目 | 内容 |
|-----|------|
| 委譲 args | `<差分スコープ> <プロジェクト規約サマリ> mode=standard`（フォームコンポーネントのリファクタ差分を含む） |
| 起動形態 | 委譲（code-review オーケストレーターから Skill ツール経由） |
| 前提 | 削除行で `<label for>` の関連付け・`aria-describedby` エラーメッセージ・`role="alert"` のエラー表示 `<div>` が除去され、追加行はプレースホルダのみの入力に置換されている（同等の代替なし） |

## 分岐の根拠

references/skill-rules-matrix.md U16（防御コード削除の回帰検出）、`${CLAUDE_PLUGIN_ROOT}/references/universal-rules.md` U16（対象とする防御コードに「アクセシビリティ属性（`role` / `aria-*` / `alt` / `label` 関連付け）」「エラー表示 UI・フォールバック（`role="alert"` の表示・エラー state）」を明記）、references/checklist.md セクション A U16、`${CLAUDE_PLUGIN_ROOT}/references/languages/html.md` 観点 3.2（a11y）・3.3（フォーム・入力とエラーメッセージの関連付け）。silent-failure（新規コードの握りつぶし）ではなく、リファクタで既存防御が削られるケースを扱う点で他観点と別物。

## 期待動作

- web-designer は差分の削除行（`-` 行）を確認し、`<label for>` 関連付け・`aria-describedby`・`role="alert"` のエラー表示 UI 等の防御コードの消失を検出する（U16）
- 追加行で同等の防御（ラベル関連付け・エラーメッセージの提示）が再導入されていない場合、**回帰（regression）** として指摘する（U16 判定 / universal-rules.md U16）
- 意図的削除（防御が不要になった正当な理由）と区別できない場合は、信頼度を中程度にし「回帰の可能性・意図確認」として提示する（U16 判定 / U15）
- 指摘は WCAG 観点（1.3.1 ラベル関連付け / 4.1.2 / 4.1.3 ステータスメッセージ）を根拠に html.md 3.2・3.3 で評価する
- 各指摘に重要度・信頼度・スコープ内/外フラグを付与する（U11 / U15 / O5）
- 中間レポートは「## フロントエンド観点レビュー結果」+「### web-designer」の構造で返却する（checklist.md C-Auto-1）
