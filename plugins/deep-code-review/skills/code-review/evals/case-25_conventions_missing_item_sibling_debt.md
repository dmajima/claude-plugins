# case-25 欠落系指摘の兄弟コード確認による既存負債判定（conventions-resolution 2.5）

「認可属性が無い」等の欠落系指摘（「無いこと」の指摘）を、差分行に接地しているだけで High にせず、差分外の兄弟コードの同一欠落・グローバル設定を確認して既存負債と判定し、スコープ外指摘へ寄せる分岐。投機的 High を防ぐ重要度整合を検証する。

## 入力

| 項目 | 内容 |
|-----|------|
| 起動フレーズ | "このブランチをコードレビューして"（差分: 既存 `OrderController.cs` に読み取り専用（GET 相当）の新設メソッド `GetOrderSummary` を追加。明示的な認可属性なし） |
| モード | 標準 |
| リポジトリ状態 | 差分外の兄弟メソッド（同一 Controller の既存 read 系）も同様に明示認可属性を持たない。`Program.cs` のフォールバック認可ポリシー（`RequireAuthorization()` 等）は確認が取れない |
| 観点別スキルからの返却（想定） | code-review-security が「新設メソッドに認可属性がない」を **High** の欠落系指摘として返却 |

## 分岐の根拠

references/conventions-resolution.md セクション2.5（欠落系指摘での兄弟コード確認・手順1〜3）、references/severity-ranking.md セクション7（信頼度付与）、references/flow/flow.md Step 5（三分類・重要度整合）、skill-rules-matrix.md C5 / C8 / U15。

## 期待動作

- Step 5: 「認可属性が無い」を差分行に接地しているだけで High を付けない（conventions-resolution.md セクション2.5 冒頭）
- Step 5 手順1: 差分外の兄弟コード（同一ファイル・同一層の既存 read 系メソッド）が同じ認可属性欠落を持つか確認する → 兄弟も同一欠落のため **既存負債の可能性が高い** と判断する
- Step 5 手順2: グローバル設定（`Program.cs` の `RequireAuthorization()` / フォールバック認可ポリシー）を確認する → 確認不能なため「グローバル設定次第で実露出が変わる」と未確認事項に明記し、信頼度を控えめに付与する（手順3・severity-ranking.md セクション7）
- Step 5 手順3判定: 既存負債（兄弟コードも同一欠落 + グローバル担保なし）かつ新設が read 系（状態変更なし）のため、**スコープ外指摘に寄せる or 既存負債である旨を明記して重要度を調整** する（C8 スコープ外セクションへ判断理由付きで分離）
- 対照（本ケースでは該当しない高リスク経路）: 新設が状態変更 API（POST）・外部公開の新設・新規に機密を扱う等なら、高リスクである理由を明記した上で Issues に High で載せてよい（セクション2.5 手順3）
- （以下は検出してはならない誤り）
    - 差分行に接地しているだけで投機的に High を付ける（セクション2.5 が防ぐ過大評価）
    - 兄弟コードの既存欠落を確認せず、新規コード固有リスクとして過大評価する
    - グローバル設定が未確認のまま信頼度を高く付与する
