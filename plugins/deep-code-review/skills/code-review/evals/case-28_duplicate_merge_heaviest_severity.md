# case-28 重複指摘の統合（最重要度採用・連名・最大信頼度・他に N 件）（C5）

複数エージェントが同一行を **異なる重要度**で指摘した場合に、Step 5 の重複排除で最も重い重要度へ統合し、担当を連名表記、信頼度を最高値、末尾に「他に N 件の同一指摘」を注記する分岐。単一指摘の引き上げ（case-14）や回帰の脱落防止（case-16）とは別の、finding レベル重複統合の中核メカニズムを検証する。

## 入力

| 項目 | 内容 |
|-----|------|
| 起動フレーズ | "このブランチをレビューして" |
| モード | 標準 |
| 観点別スキルからの返却（想定） | 3 エージェントが `OrderService.cs:42` の同一テーマ（Null ハンドリング不備）を異なる重要度・信頼度で指摘: implementation-engineer=High（信頼度 85）/ security-engineer=Critical（信頼度 75・攻撃者が Null を送り込める）/ test-engineer=Medium（信頼度 90・Null ケースのテスト未整備） |

## 分岐の根拠

references/severity-ranking.md セクション3.1（重複判定の条件: 同一ファイル・±5 行以内・同一テーマ）・セクション3.2（重複時の処理: 最も重い重要度・連名表記・推奨対応統合・「他に N 件の同一指摘」注記）・セクション3.3（矛盾する指摘: より厳しい側 + 「5. 観点間の見解の差異」記載）・セクション6（統合例）・248 行（統合時の信頼度は最も高い値を採用）、references/flow/flow.md Step 5（結果統合・重複排除）、skill-rules-matrix.md C5 / U11 / U15。

## 期待動作

- Step 5（3.1）: 対象ファイル同一・行番号一致（±5 行以内）・テーマ同一概念のため 3 指摘を重複と判定する
- Step 5（3.2）: 重要度は **最も重い Critical** を採用する（impl の High・test の Medium に引きずられて降格しない。Critical は信頼度が最低（75）の security 由来でも降格しない）
- Step 5（248 行）: 統合後の信頼度は **最も高い値（90）** を採用する（複数エージェントの独立同一指摘が信頼度を高めるため。重要度の出所〈sec〉と信頼度の最高値の出所〈test〉が別エージェントでも各々最重・最高を採る）
- Step 5（3.2）: 担当エージェント表記を連名（「impl + sec + test」）にし、各エージェントの推奨対応を統合して最も具体的なものを採用し、末尾に「（他に N 件の同一指摘）」を注記する
- Step 5（3.3）: 仮に評価が矛盾する（片方 PASS・片方 RETHINK REQUIRED 等）場合はより厳しい側を採用しつつ、両論を統合サマリの「5. 観点間の見解の差異」セクションに記載する
- Step 6-8: 統合後の 1 件に Finding ID を採番し、Issues のサマリー表・件数集計には **統合後の 1 件**として計上する（3 件別々に計上しない）
- （以下は検出してはならない誤り）
    - 最も重い重要度でなく多数決・平均で Medium/High に丸める（3.2 違反・Critical の見落とし）
    - 重複を統合せず 3 件別々に Issues 計上する（重複排除漏れ）
    - 連名表記にせず単一エージェント名のみ記載する / 「他に N 件」注記を落とす
    - 統合後の信頼度を最低値・平均で付与する（248 行違反）
