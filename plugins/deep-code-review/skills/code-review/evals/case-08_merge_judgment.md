# case-08 マージ可否の総合判定トリガー

「マージしても大丈夫か」「総合レビューして判断して」等、マージ可否の判断を明示的に求められるケース。トリガー認識と Verdict の明示提示を検証する。

## 入力

| 項目 | 内容 |
|-----|------|
| 起動フレーズ | "この変更をマージしても大丈夫か総合レビューして判断して" |
| モード | 対話 |

## 分岐の根拠

SKILL.md「トリガー条件」（「マージ可否を判断して」「総合レビューして」）、`${CLAUDE_SKILL_DIR}/references/output/output-format.md` セクション 1.2（レビュー結果は「総合判定 + 再レビュー要否を統合した単一フィールド」）・セクション 3（Verdict 判定）、SKILL.md「責務外」（リリース可否の最終決定は人間が負う。Verdict は技術観点）。

## 期待動作

- `code-review` オーケストレータースキルが起動する（トリガー認識）
- マージ可否判断の要求のため標準モードで観点を動員する（差分内容により architecture / frontend は省略可）
- レビュー結果を「OK（Ready to Merge）/ NG・再レビュー不要（Needs Attention）/ NG・再レビュー要（Needs Work）」の 3 種の単一フィールドで明示する（output-format.md セクション 1.2）
- Critical / High の指摘がある場合は必ずユーザーに明示する（SKILL.md 基本原則 10）
- Verdict は **技術観点の判定**であり、最終的なリリース/マージの意思決定は人間が負うことを明示する（SKILL.md 責務外）
