# case-16 削除側防御コードの回帰（U16）を Issues に計上する統合分岐

観点別スキルが検出した「差分の削除側（`-` 行）で既存の防御コード（例外処理・リソース解放等）が失われた回帰」指摘を、オーケストレーターが Step 5 の統合・重複排除で欠落させず Issues（対応が必要な指摘）に計上する分岐。code-review は U16 を **統合側** として適用する（skill-rules-matrix.md セクション 8 注記）。

## 入力

| 項目 | 内容 |
|-----|------|
| 起動フレーズ | "リファクタしたのでレビューして"（差分: 既存メソッドのリファクタで `try/catch` と `finally` のリソース解放が削除側（`-` 行）に含まれ、追加側（`+` 行）に同等の防御が再導入されていない） |
| モード | 標準 |
| 観点別スキルからの返却（想定） | code-review-implementation が U16 回帰（例外処理・リソース解放の消失）を Medium〜High 相当・意図確認付きで返却 |

## 分岐の根拠

skill-rules-matrix.md U16（防御コード削除の回帰検出）・セクション 8 注記（U16 は差分を評価するスキル + それらを統合する code-review + pr-review 経由に適用）、`${CLAUDE_PLUGIN_ROOT}/references/universal-rules.md` U16（対象とする防御コード・判定）、references/flow/flow.md Step 5（結果統合・重複排除・Issues / Suggestions / Scope-out 三分）。

## 期待動作

- Step 5: 観点別スキルが返した U16 回帰指摘（削除側で例外処理・リソース解放が消失し、追加側で同等の防御が再導入されていない）を統合プールに取り込み、重複排除で **欠落・消去しない**
- Step 5: code-review は U16 を統合側として適用し、当該回帰を重要度（例外処理・リソース解放の消失は Medium〜High 相当）に応じて **Issues（セクション 1）に分類**する（Suggestions / Scope-out に落とさない）
- Step 5: 意図的削除（防御が不要になった正当理由）と区別できない場合は、信頼度を中程度にし「回帰の可能性・意図確認」として提示する（universal-rules.md U16 判定）
- Step 5: プロファイルアンカー照合（C25）でも、当該回帰パターンのアンカー下限が Medium 以上であれば Issues に維持する（flow.md Step 5）
- Step 6-8: 当該回帰に Finding ID を採番し、Issues のサマリー表・件数集計に反映する
- （以下は検出してはならない誤り）
    - U16 回帰指摘を重複排除の名目で統合サマリから欠落させる
    - マージをブロックしないために回帰を Suggestions / スコープ外へ誤分類する
    - silent-failure 観点（新規コードでの握りつぶし）と U16（既存防御の削除回帰）を同一視して一方のみ計上する
