# case-07 信頼度足切り（C24）と未対応言語の明示

観点別スキルから信頼度 60 未満の指摘が返り、かつ差分に観点プロファイル未収録の言語（Go）が含まれるケース。低信頼指摘の足切りと未対応言語の明示が正しく行われることを検証する。

## 入力

| 項目 | 内容 |
|-----|------|
| 起動フレーズ | "このブランチをコードレビューして"（差分: `api/*.go` 3 ファイル + `web/*.ts` 5 ファイル） |
| モード | 標準 |
| 観点別スキルからの返却（想定） | implementation から信頼度 85 の High 1 件・信頼度 45 の Medium 1 件（呼び出し元のデータ量を仮定した性能懸念）・信頼度 50 の Critical 相当 1 件（認可バイパスの可能性・差分外コードの状態を仮定） |

## 分岐の根拠

`${CLAUDE_PLUGIN_ROOT}/references/severity-ranking.md` セクション 7（信頼度による足切り）、skill-rules-matrix.md U15 / C24、`${CLAUDE_PLUGIN_ROOT}/references/language-detection.md` セクション 4（未対応言語の扱い）。

## 期待動作

- Step 2: TypeScript は `languages/typescript.md` を適用。**Go は観点プロファイル未収録** のため「未対応言語」として記録し、プロジェクト規約 + 汎用観点のみで評価する方針を適用規約サマリに明記する
- Step 4: 委譲引数の `language-profiles` に TypeScript プロファイルのみを含める（Go のプロファイルを捏造しない）
- Step 5: 信頼度 85 の High 指摘は Issues に通常記載する
- Step 5: 信頼度 45 の Medium 指摘は **Issues / Suggestions に記載しない**（C24 足切り）
- Step 5: 信頼度 50 の Critical 相当指摘は、足切りせず **「7. 未確認事項・制約」に「要人間確認（低信頼）」として 1 行記載** する（重大リスクの見逃し防止・severity-ranking.md セクション 7.3 例外）
- Step 8: 集計セクションに「低信頼のため除外: 1 件」を記載する（output-format.md セクション 1.4）
- Step 8: 未確認事項・制約に「Go: 観点プロファイル未収録・汎用観点のみで評価」を記載する
