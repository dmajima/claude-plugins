# case-27 inputs ヒアリングフロー（チケット未検出時の選択肢条件付き除外）（C17）

inputs フォルダ未作成・`spec=` 引数なしの初回レビューで、セクション4 のヒアリングフローに入り、チケットリンク・IDがいずれの情報源からも検出できないため「外部チケットから取得」を除外して 3 選択肢で提示する分岐。選択後に空振りする体験を防ぐ条件付き選択肢除去（4 択 vs 3 択）を検証する。

## 入力

| 項目 | 内容 |
|-----|------|
| 起動フレーズ | "このブランチをレビューして" |
| モード | 対話（標準） |
| リポジトリ状態 | `.claude/.local/plugins/deep-code-review/{branch}/inputs/` 未作成。`spec=` 引数なし。ブランチ名 `feature/refactor-order-service`（チケット ID パターンなし）。対象ブランチのコミットメッセージにもチケットリンクなし |

## 分岐の根拠

skills/code-review/references/state/inputs-management.md セクション4（ヒアリングフロー）・セクション4.1（仕様情報の取得方法選択・外部チケット自動検出・チケット未検出時の選択肢除外）・セクション4.5（スキップ時の記録）、references/flow/flow.md Step 0-P（inputs 確認）、skill-rules-matrix.md C17。

## 期待動作

- Step 0-P: `.claude/.local/plugins/deep-code-review/{branch}/inputs/` の有無を確認 → 未作成 かつ `spec=` 引数なしのため セクション4 のヒアリングフローに入る（inputs-management.md セクション3.1）
- Step 0-P: 非 PR 文脈（ブランチ指定レビュー）のため、チケットリンク・IDを対象ブランチのコミットメッセージ（`git log <base>...HEAD`）とブランチ名に含まれるチケット ID から探索する（セクション4.1 情報源表）
- Step 0-P: ブランチ名 `feature/refactor-order-service` にチケット ID パターンがなく、コミットメッセージにもチケットリンクが検出されないため、**「外部チケットから取得」を選択肢から除外**し、3 選択肢（仕様書パスを指定 / 口頭で説明 / 仕様確認不要）で `AskUserQuestion` を提示する（セクション4.1 の条件付き除外）
- ユーザーが「仕様確認不要」を選択した場合: inputs 作成をスキップし、state.yaml の `inputs_used` を空リストとし、統合サマリの集計セクションに「仕様書未参照（ユーザー指示）」と記載する（セクション4.5）
- 対照（本ケースでは該当しない）: いずれかの情報源でチケットリンク / IDを検出できた場合は「外部チケットから取得」を推奨選択肢に含めた **4 選択肢**（外部チケット取得 / 仕様書パス指定 / 口頭で説明 / 仕様確認不要）で提示する（セクション4.1）
- （以下は検出してはならない誤り）
    - チケットリンク未検出でも「外部チケットから取得」を含む 4 選択肢を提示する（選択後に空振りする体験・セクション4.1 違反）
    - inputs 未作成なのにヒアリングを行わず、AI が独断で「仕様確認不要」と判断する（inputs-management.md 禁止事項）
    - 「仕様確認不要」の選択を無視して inputs フォルダを作成する
