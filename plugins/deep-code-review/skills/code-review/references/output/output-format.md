# 出力フォーマット・レビュー結果

統合サマリの出力フォーマットと、最終判定（Ready to Merge / Needs Attention / Needs Work）の判定基準を定義する。
**毎回必ず同じレイアウトで出力すること**。セクション番号・見出し文言・ヘッダブロックの順序は固定。
統合サマリは規定の 9 セクションのみで構成し、**答えキー参照・自己採点・検出率の自己評価等のメタセクションを追加してはならない**（レビューはブラインドで行い、正解との照合結果を出力に含めない。評価は別途フレッシュエージェントが行う責務）。
各 H2 セクションは `<details><summary>` 折り畳み + 内部 HTML 記法（`<h2>`〜`<h4>` / `<table>` / `<code>` / `<pre><code>` 等）で出力する（タイトル行・ヘッダブロックは折り畳み対象外）。
セクションタイトルは **すべて日本語** を使用し、テンプレートは `template/review-summary.md` を参照する。

> **位置付け**: 本ファイルは「フォーマットの規範」、`template/review-summary.md` は「実体テンプレート」。
> 両者の差分が出た場合は **template が優先** され、本ファイルの記述を最新の template に合わせて更新する。

> **本ファイルの構成（索引）**: 本ファイルは索引であり、各セクションの詳細は同ディレクトリのサブファイルに分割している。
> 外部参照（`output-format.md セクション 1.5` 等）は下記セクションマップの番号で解決する。**セクション番号は改変しないこと**。
>
> - **[`output-format-details.md`](output-format-details.md)**: セクション 1（出力フォーマット・固定型）/ 1.5（Finding ID 採番規則）/ 2（指摘・改善提案ごとの必須項目）
> - **[`output-verdict.md`](output-verdict.md)**: セクション 3（レビュー結果）/ 4（未確認事項・制約）/ 5（ファイル出力）/ 6（出力例）

## セクションマップ

外部ファイルは本索引のセクション番号（`セクション 1.4` `セクション 2.5` 等）で参照する。番号を落とすと参照が壊れるため保持すること。

### [`output-format-details.md`](output-format-details.md) — 出力フォーマット・Finding ID・指摘項目

| セクション | 概要 |
|---|---|
| **1. 出力フォーマット（必須・固定型）** | 統合サマリの固定レイアウト全体の規範 |
| 1.1 全体構成（順序厳守） | 9 セクションの出力順序・`<details>` ブロック構成 |
| 1.2 ヘッダブロック（必須） | タイトル行 + メタデータ引用ブロック。「レビュー結果」統合フィールドの定義 |
| 1.3 件数ルール | 対応必須（全件）/ 改善提案（最大 10 件）/ スコープ外 / 重複統合の取り扱い |
| 1.4 集計セクションの必須項目 | 実施日時・モード・参加スキル・比較ブランチ・head SHA・参照規約・件数集計等の必須明記項目 |
| **1.5 Finding ID 採番規則（必須）** | `CR-NNN` の一意採番・連続通番・再レビュー起算・命名衝突（REV-NNN）・表記場所・採番例 |
| **2. 指摘・改善提案ごとの必須項目** | セクション1〜3 の 2 段構成（A. サマリー表 / B. 詳細補足） |
| 2.1 「対応が必要な指摘」の項目 | サマリー表の列（2.1.1）/ 詳細補足の項目（2.1.2） |
| 2.2 「改善提案」の項目 | サマリー表の列（2.2.1）/ 詳細補足の項目（2.2.2） |
| 2.3 「スコープ外指摘」の項目 | サマリー表の列（2.3.1）/ 詳細補足の項目（2.3.2） |
| 2.4 必須項目を満たせない場合の扱い | 該当行不明時の補完・致命度/信頼度の再評価（U15 / C24） |
| 2.5 コードスニペット引用の規範（必須） | 引用ブロック必須・言語識別子・範囲一致・過大引用禁止・自動リンク防止 |
| 2.6 PR インラインコメントへの URL（リンク方針・必須） | TFS/Azure DevOps・GitHub の URL 形式・HTML リンク表記 |

### [`output-verdict.md`](output-verdict.md) — レビュー結果・未確認事項・ファイル出力・出力例

| セクション | 概要 |
|---|---|
| **3. レビュー結果** | 最終判定（Ready to Merge / Needs Attention / Needs Work）の確定 |
| 3.1 判定マトリクス | Critical/High/Medium 件数 × test-runner ステータスの判定表 |
| 3.2 例外（より厳しい側を採用） | エージェント強制評価語（VULNERABLE / RETHINK REQUIRED / FAIL 等）による NG オーバーライド |
| 3.3 レビュー結果ごとの推奨アクション | 各判定に添える 1 文の推奨アクション |
| **4. 未確認事項・制約セクション（必須）** | 未実施項目を「問題なし」と誤認させない明示記載 |
| 4.1 状態語彙（SSOT・全プラグイン共通） | EXECUTED / PASS / FAIL / GREEN / RED / SKIPPED / 未実施 / 対象外 の統一語彙 |
| 4.2 SKIPPED 時の必須記載項目 | SKIPPED 理由語彙・記載例・未確認事項テーブル |
| **5. ファイル出力** | review-summary.md の出力先パス案内 |
| **6. 出力例（Ready to Merge / 簡略・折り畳み形式）** | 折り畳み形式の完全な出力サンプル |
