# コードレビューサマリ テンプレート（統一型）

> Step 8 で生成する統合サマリのテンプレート。**毎回このレイアウトと項目順序を厳守する**（PR コメント投稿時・テキスト返却時で共通）。
> `<...>` は Claude が実行時に差し替える。
> 指摘・提案の件数に上限はない。検出されたものはすべて記載する。
> セクション番号と見出し文言を勝手に変更してはならない（出力安定性のため）。
> 必須セクションは省略不可。**該当なし** の場合も `<details>` ブロックを残し本文に「該当なし」と記載する（読み手が「未記載なのか・該当ゼロなのか」を判別できるようにする）。
> **summary への状態記号**: セクション 1〜3 の `<summary>` には件数に応じた状態記号を付記する。折り畳んだまま要対応の有無を判断できるようにするため。`<h2>` 再掲側には付記しない（`（<X> 件）` のまま）。
> - 件数 >0: 「⚠」を付記する（例: `<summary>1. 対応が必要な指摘 （2 件 ⚠）</summary>`）
> - 件数 0: 「✓ + 状態語」を付記する（セクション 1 は `（0 件 ✓ 指摘なし）`、セクション 2・3 は `（0 件 ✓ 該当なし）`）
> **折り畳み形式**: 出力対象部（`# 🤖 ...` 以降）の各 H2 セクションは `<details><summary><見出し></summary>` + `<h2>` 再掲で折り畳み、内部は HTML 記法（`<h3>`/`<h4>` / `<table>` / `<code>` / `<pre><code>` / `<ul>` / `<a href>` 等）で出力する。`<details>` 内では Markdown のテーブル・見出し・コードフェンスがレンダリングされないため HTML タグへの変換を厳守する。タイトル行（H1）とヘッダブロック（`> **レビュー結果**: ...`）は折り畳み対象外。
> 本テンプレート中の引用ブロック（`> ...`）による記入指示はテンプレート利用者（Claude）向けであり、サマリ本文には出力しない。

## 採番規則（Finding ID）

各指摘・改善提案・スコープ外指摘には **必ず一意の Finding ID（`CR-NNN`）** を付与する。
規範詳細・採番例・ユーザー利用シナリオは **`${CLAUDE_SKILL_DIR}/references/output/output-format.md` セクション 1.5** を参照（SSOT・重複定義は廃止）。

要点:
- フォーマット: `CR-NNN`（3 桁ゼロ詰め連番）
- 採番範囲: 統合サマリ全体で連続採番（Issues → Suggestions → Scope-out の記載順）
- 採番責任: オーケストレーター（`code-review`）の Step 6 で一括採番
- 再レビュー: 新規発見指摘は前回最終 ID + 1 から採番（`finding-thread-map.json` で管理）

### 最終状態の目標

対応すべき指摘がすべて対応された時点で、PR の **active な未解決スレッドはサマリースレッド 1 件のみ** になっている状態を目指す。
インラインスレッドはすべて以下のいずれかになっている:

- **fixed**（コード修正で解消・Pattern A）
- **wontFix**（ユーザー指示でスコープ外了承・Pattern D）
- **closed**（旧サマリーが新サマリー投稿時に閉じられた等）

active のまま残っているインラインスレッドは「未対応」を示すため、完了前チェックリスト（`pr-review/references/completion-checklist.md` B-1.7）で件数と内訳を検証する。

## テンプレートの組み立て（Step 8 でのサマリ生成手順）

本テンプレート本体は 300 行超のため、以下の 3 ファイルに分割されている。**Step 8 でサマリを生成する際は、以下の順に逐語連結して 1 つのサマリを構成する**（PR コメント投稿時・テキスト返却時で共通）。

1. **本ファイル（`review-summary.md`）のヘッダブロック** — 下記の `# 🤖 ...` タイトル行〜`> **レビューモード**` までの冒頭固定ブロック（出力対象）。本ファイル冒頭の記入指示・採番規則・最終状態の目標・本セクションは **出力しない**。
2. **[`review-summary-body-1.md`](review-summary-body-1.md)** — セクション 1〜5（対応が必要な指摘／改善提案／スコープ外指摘／観点別の指摘なし／観点間の見解の差異）。
3. **[`review-summary-body-2.md`](review-summary-body-2.md)** — セクション 6〜9（既存指摘の解消判定／未確認事項・制約／集計／レビュー実施環境）。

各 body ファイルの `<details>`/`<summary>`/`<h2>` 構造・セクション番号・見出し文言は改変せず、そのまま出力する（出力安定性のため）。該当なしのセクションも `<details>` ブロックを残し本文に「該当なし」と記載する。
