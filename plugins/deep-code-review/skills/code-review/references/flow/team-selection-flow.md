## 0. 排他関係・コスト・運用前提（要点）

### 0.1 Step 4 / Step 4-T は排他

`code-review` Step 4（観点別スキル並列）と Step 4-T（Agent Teams 議論）は同時実行不可。Step 3.5 で Agent Teams 採用が決まれば Step 4 は **行わない**（観点別スキル経由ではなく前段サブエージェント直接呼び出し + チーム議論）。

| Step 3.5 判定 | 実行 |
|--------------|------|
| Agent Teams 採用 | Step 4-T のみ（観点別スキル並列なし） |
| サブエージェント方式 | Step 4 のみ |

二重起動を避ける目的: 同一エージェント（例: `dba`）が前段とチーム内で 2 回起動されるとトークン浪費・結果重複・コスト見積もり破綻が発生する。

### 0.2 コスト見積もり

Agent Teams 採用時の通常レビュー比倍率: **約 4.5〜6.0 倍**（前段サブエージェント + チームメンバー初期スポーン + 議論 3 ラウンド合算）。ユーザー承認時の `AskUserQuestion` では「最大で通常の 6 倍程度」と明示する。

### 0.3 前段サブエージェントとチームメンバーの違い

両者は同じエージェント定義（`${CLAUDE_PLUGIN_ROOT}/agents/*.md`）を共有するが、起動コンテキストが異なる:

- **前段サブエージェント**: メインコンテキストから単独起動（議論には参加せず、中間レポートを生成）
- **チームメンバー**: チームコンテキスト（共有タスクリスト + メッセージ交換）で起動・議論ラウンドに参加

役割が独立しているため二重起動は発生しない。

### 0.4 Agent Teams 採用時の実行手順（Step 4-T）

1. 前段サブエージェントを `Agent` ツールで並列起動（観点別スキル経由ではない）
2. 中間レポート取得
3. `TeamCreate` でチーム作成 → メンバーに中間レポートを渡してスポーン
4. 議論 3 ラウンド以上で合意形成
5. `TeamDelete` でクリーンアップ

### 0.5 環境前提

チームメイトの `subagent_type` は `${CLAUDE_PLUGIN_ROOT}/agents/` から解決される前提（Team API がプラグインスコープのエージェント定義を読む）。Team API がプラグイン定義を参照できない古い環境では、グローバル `~/.claude/agents/` への同名コピーが必要。エラー時は `env-setup` スキル経由でフォールバック対応。

## 3. パターン共通の運用ルール

### 3.1 ユーザー承認（必須）

`agent-teams.md` セクション 2 の規約に従い、**チーム起動前に必ずユーザー承認を取る**。

#### Step 1: テキストでメリット・デメリットを提示

メリットはデメリット（コスト倍率）と同じ具体性で書く。「品質が上がる」のような抽象表現は禁止し、**今回の差分内容に固有の検証効果**を 1〜2 行で明示する。

```
このタスクは「{{パターン名}}」チーム（{{メンバー数}}名: {{メンバー一覧}}）での実行が効果的です。

メリット: {{今回の差分に固有の具体的効果。何が議論され、どの見落としを防げるかを明示}}
  - 例: 認証ロジックの変更 {{N}} ファイルに対し、sec が提示する攻撃シナリオを impl/arch が相互反証することで、単独レビューで見落としやすい権限昇格経路を検出できる
デメリット: メンバー{{N}}名分のトークンを消費（議論ラウンド込みで通常レビューの最大 6 倍程度のコスト）・実行時間が長い
```

#### Step 2: AskUserQuestion で選択 UI を表示

```
AskUserQuestion({
  questions: [{
    question: "Agent Teams（{{パターン名}}: {{メンバー数}}名）を利用しますか？",
    header: "Agent Teams",
    options: [
      {
        label: "利用する",
        description: "{{N}}名のメンバーが議論・反論し、合意形成された成果を導出。トークン消費は通常の最大 6 倍程度"
      },
      {
        label: "利用しない（サブエージェント）",
        description: "現状の観点別スキル並列実行にフォールバック。コスト効率は高いが、メンバー間の議論は行われない"
      }
    ],
    multiSelect: false
  }]
})
```

「利用しない」選択時は **サブエージェント方式（観点別スキル並列）にフォールバック**。

### 3.2 起動・進行・終了

`agent-teams.md` セクション 5 の手順に従う:

1. `TeamCreate({ team_name: "code-review-{{パターン名}}-<timestamp>", description: "..." })`
2. `TaskCreate` で各メンバーのタスクを作成（1メンバーあたり 5〜6 タスク）
3. `Agent` ツールでメンバーをスポーン（並列起動）
4. リードがタスクをアサイン or メンバーがセルフクレーム
5. 最低 3 ラウンドの議論を経て合意形成
6. 合意に至らない項目はトレードオフとして明記
7. 完了後 `shutdown_request` 送信 → `TeamDelete`

### 3.3 進捗管理

`progress-management.md` のルールに従い、`progress.md` で進捗管理する。
担当者欄は `Team: code-review-{{パターン}} / {{メンバー名}}` と記載。

### 3.4 ファイル競合の防止

本プラグインはレビュー専用で **書き込みなし** のため、ファイル競合リスクは低い。
ただし、レビュー結果ファイル（`.claude/.local/plugins/deep-code-review/{branch}/{timestamp}/review-summary.md` 等）への書き込みは **オーケストレーターのみ** が行い、メンバーは生成しない。

## 4. フォールバック条件（サブエージェント方式に切替）

以下のいずれかを満たす場合は **Agent Teams を採用せず**、観点別スキル（`code-review-implementation` / `code-review-testing` / `code-review-security` / `code-review-architecture` / `code-review-frontend`）の並列実行（Independent 型サブエージェント）にフォールバックする。

| 条件 | 理由 |
|------|------|
| 簡易モード（`mode=quick`） | 軽量レビュー目的とトークン4倍は不釣り合い |
| 軽微な変更（10ファイル未満 かつ 1,000行未満 かつ 単純変更のみ） | 議論オーバーヘッドが成果に見合わない |
| `TeamCreate` ツールが利用不可 | 環境制約（CI/CD・SDK経由・Web版等） |
| 非対話モード | ユーザー承認が取れない |
| ユーザーが「サブエージェントで」を選択 | ユーザー意思を尊重 |
| `TeamCreate` がエラーで失敗 | 実行可能性の確保 |

フォールバック時は本オーケストレーターの通常フロー（観点別スキルへの `Skill` ツール並列委譲）で続行する。

## 6. 将来の拡張

新しいパターンが必要になった場合の手順:

1. 本ファイル（`team-selection.md`）の選定フローとパターン定義に追加
2. 既存チームで対応できる場合は前段サブエージェント構成のみ追加
3. 既存チームで対応できない場合は `~/.claude/rules/claude/agent-teams.md` への新チーム追加を提案（ユーザー承認必須・グローバルルール変更のため）
