# case-08 防御テストコード削除の回帰検出（U16: テストガード / アサーション削除）

リファクタリングの差分の削除側（`-` 行）で、例外を検証するアサーションや境界値テストケースといった既存の防御的テストコードが失われた回帰を test-engineer が指摘するケース。新規テストの不足ではなく、既存の防御テストがリファクタで削られた回帰（U16）を検証する。

## 入力

| 項目 | 内容 |
|-----|------|
| 委譲 args | `<差分スコープ（テストコードのリファクタリング）> <プロジェクト規約サマリ> mode=standard` |
| 起動形態 | 委譲（code-review オーケストレーターから Skill ツール経由） |
| 変更分類 | リファクタリング（テストクラスの整理・重複統合） |
| 差分内容 | テストの整理に伴い、不正入力で例外送出を検証する `Assert.Throws<ArgumentException>(...)`（例外検証アサーション）と、最大値 / 最小値 / null を検証する境界値テストメソッドが削除側（`-` 行）に含まれ、追加側（`+` 行）では正常系テストのみに置換され同等のアサーション・境界値ケースが再導入されていない |

## 分岐の根拠

`${CLAUDE_PLUGIN_ROOT}/references/skill-rules-matrix.md` U16（差分の削除側で既存の防御コード（例外処理・入力検証・リソース解放・a11y 属性・認可・エラー表示 UI）が失われていれば回帰として指摘する）、`${CLAUDE_PLUGIN_ROOT}/references/universal-rules.md` U16「対象とする防御コード」（例外処理 / 入力検証・境界チェック・ガード節）・「判定」（削除行の防御が追加行で再導入されていなければ回帰・意図と区別できない場合は信頼度中程度で意図確認）、references/checklist.md セクション A U16。ドメイン固有の回帰パターンとして、例外送出・境界値を検証するアサーションは U16 の「例外処理」「境界チェック」防御のテスト側担保にあたり、その削除は防御の網羅性（test-engineer 観点: 網羅性・エッジケース。SKILL.md「前提」の観点表）の後退として扱う。

**既存ケースとの差別化**: U16 は「リファクタで既存の防御（テスト）が削られる」ケースを扱い、新規テスト不足を扱う通常の網羅性評価とは別物（universal-rules.md U16 規範に明記）。case-04 は test-engineer によるテストコード品質（網羅性・AAA）の通常静的レビュー、case-01 は test-runner の実行結果報告を主眼とするのに対し、本ケースは削除側（`-` 行）の防御テスト消失検出という U16 固有の分岐を検証する。

## 期待動作

- test-engineer が差分の削除側（`-` 行）を精査し、例外検証アサーション（`Assert.Throws` / `assertRaises` / `expect().toThrow()` 等）・境界値テストケースが失われていないか確認する（universal-rules.md U16 / checklist.md セクション A U16）
- 削除された防御テストが追加側（`+` 行）で同等に再導入されていない場合、回帰（regression）として指摘する（universal-rules.md U16「判定」）
- 具体的には、例外検証アサーションの消失を「例外送出パスの検証欠落の回帰」、境界値テストの消失を「エッジケース（最大 / 最小 / null）網羅の後退の回帰」として指摘する（universal-rules.md U16「対象とする防御コード」・SKILL.md「前提」の観点表）
- 新規テストの不足観点とは切り分け、あくまで「リファクタで既存の防御テストが削られた」回帰として位置づける（universal-rules.md U16 規範）
- 意図的削除（対象仕様が廃止され当該テストが不要になった正当理由）と区別できない場合は、信頼度を中程度にし「回帰の可能性・意図確認」として提示する（universal-rules.md U16「判定」/ U15 信頼度付与）
- 各指摘に重要度・信頼度・スコープ内/外フラグを付与する（checklist.md U11 / U15 / O5）
- 中間レポートは「## テスト観点レビュー結果」+「### test-engineer」「### test-runner」の構造で返却する（SKILL.md「出力フォーマット」/ checklist.md C-Auto-1）
- Finding ID（CR-NNN）の採番・Verdict 判定は行わない（checklist.md O9。オーケストレーター責務）
