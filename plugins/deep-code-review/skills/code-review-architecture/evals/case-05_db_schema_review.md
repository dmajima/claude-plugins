# case-05 DB スキーマ変更のレビュー

DB スキーマ・マイグレーションのトリガーフレーズで本スキルが起動し、architect + dba を並列起動してデータ層を評価することを検証するケース。

## 入力

| 項目 | 内容 |
|-----|------|
| 起動フレーズ | "DB スキーマの変更をレビューして、マイグレーションも確認して" |
| 起動形態 | 単独（オーケストレーター不在・ユーザー直接起動） |

## 分岐の根拠

SKILL.md「トリガー条件」の「「DB スキーマ変更をレビューして」…と言われた場合」、SKILL.md「動的に省略可（責務はオーケストレーター）」の表（dba: SQL・DB スキーマ・マイグレーション変更がある場合に起動）、SKILL.md「実行フロー」手順 2〜3（DB 変更判定 → architect / dba を 1メッセージ内で並列起動）、SKILL.md「出力フォーマット」の「### dba（DB変更あり時のみ）」、references/checklist.md セクション B O1 / セクション C C-Auto-2。

**既存ケースとの差別化**: case-04 は DB 変更なしで dba を内部省略する分岐、case-01 は委譲経路の DB 変更あり分岐を検証する。本ケースは対話フレーズ「DB スキーマ変更をレビューして」がトリガーとなり dba が起動する分岐（トリガー検証）を主眼とする。

## 期待動作

- 起動フレーズ「DB スキーマの変更をレビューして、マイグレーションも確認して」から code-review-architecture スキルが起動する（SKILL.md「トリガー条件」）
- 差分に DB スキーマ / マイグレーション変更が含まれると判定し、architect / dba の 2 エージェントを 1 メッセージ内で並列起動する（SKILL.md「実行フロー」手順 2〜3 / checklist.md O1）
- dba がスキーマ変更の安全性評価・マイグレーション戦略・インデックス / クエリ最適化提案を報告する（SKILL.md「出力フォーマット」）
- architect が設計上の問題・技術的負債・コンポーネント境界 / 依存方向を報告する（SKILL.md「出力フォーマット」）
- 「## アーキテクチャ観点レビュー結果」+「### architect」「### dba（DB変更あり時のみ）」の両セクションを含む中間レポートを返却する（SKILL.md「出力フォーマット」/ checklist.md C-Auto-1 / C-Auto-2）
- Finding ID（CR-NNN）の採番・Verdict 判定は行わない（checklist.md O9）
