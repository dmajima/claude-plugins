# case-04 アーキテクチャ観点のレビュー

アーキテクチャ観点のトリガーフレーズ（「アーキテクチャに影響ないか確認して」）で本スキルが起動し、architect を起動して設計影響を評価（DB 変更なしなら dba 省略）することを検証するケース。

## 入力

| 項目 | 内容 |
|-----|------|
| 起動フレーズ | "今回の変更がアーキテクチャに影響ないか確認して" |
| 起動形態 | 単独（オーケストレーター不在・ユーザー直接起動） |

## 分岐の根拠

SKILL.md「トリガー条件」の「「アーキテクチャ観点でレビューして」「設計影響を確認して」…と言われた場合」、SKILL.md「動的に省略可（責務はオーケストレーター）」の表（architect: 常に起動 / dba: SQL・DB スキーマ・マイグレーション変更が一切ない場合のみ内部で省略）、SKILL.md「実行フロー」手順 2「DB 変更があるか判定し、`dba` の起動可否を決定」、references/checklist.md セクション B O1 / セクション C C-Auto-3。

**既存ケースとの差別化**: case-05 は「DB スキーマ変更をレビューして」フレーズで dba を起動するのに対し、本ケースは DB 変更を含まない設計変更フレーズで architect のみを起動し dba を内部省略する分岐を検証する。case-03 は同種フレーズだが DB 変更あり + progress.md 自スキル作成を主眼とする（単独起動）。

## 期待動作

- 起動フレーズ「今回の変更がアーキテクチャに影響ないか確認して」から code-review-architecture スキルが起動する（SKILL.md「トリガー条件」）
- architect を起動してシステム構造・コンポーネント境界・依存方向・技術的負債を評価する（SKILL.md「前提」の観点表）
- 差分に DB 変更がなければ dba を内部省略し、省略した旨と理由（DB 変更なし）を中間レポートに明記する（SKILL.md「動的に省略可」の表 / checklist.md C-Auto-3）
- architect は常に起動する（「呼ばれたが何もしない」判断はしない。SKILL.md「動的に省略可」注記）
- 「## アーキテクチャ観点レビュー結果」+「### architect」の構造で観点別中間レポートを返却する（SKILL.md「出力フォーマット」/ checklist.md C-Auto-1）
- Finding ID（CR-NNN）の採番・Verdict 判定は行わない（checklist.md O9）
