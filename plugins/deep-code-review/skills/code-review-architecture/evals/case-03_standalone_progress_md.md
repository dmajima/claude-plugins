# case-03 単独起動（progress.md 自スキル作成）

ユーザーが本スキルを直接起動するケース。オーケストレーター不在時に本スキル自身が progress.md を作成・維持すること（O8）と、委譲時と同一の中間レポート構造で返却することを検証する。

## 入力

| 項目 | 内容 |
|-----|------|
| 起動フレーズ | "アーキテクチャ観点でレビューして" |
| 起動形態 | 単独（オーケストレーター不在・ユーザー直接起動） |
| 前提 | 差分に DB スキーマ変更（マイグレーション SQL）を含む |

## 分岐の根拠

SKILL.md「トリガー条件」の「「アーキテクチャ観点でレビューして」「設計影響を確認して」「DB スキーマ変更をレビューして」と言われた場合」、references/checklist.md セクション B O8（オーケストレーター不在で単独実行された場合、本スキル自身で progress.md を作成・維持している）、`${CLAUDE_PLUGIN_ROOT}/references/common-references.md` セクション 4（オーケストレーター不在時は本スキル自身で progress.md を作成・維持する）、SKILL.md「実行フロー」手順 2〜3（DB 変更判定 + 1 メッセージ内並列起動）。

## 期待動作

- トリガーフレーズ「アーキテクチャ観点でレビューして」から本スキルが単独起動する（SKILL.md「トリガー条件」）
- オーケストレーター不在のため、本スキル自身で progress.md を作成・維持する（checklist.md O8 / common-references.md セクション 4）
- 差分に DB スキーマ変更があると判定し、architect / dba を 1 メッセージ内で並列起動する（SKILL.md「実行フロー」手順 2〜3 / checklist.md O1）
- 中間レポートは委譲時と同一の「## アーキテクチャ観点レビュー結果」+「### architect」「### dba」構造で返却する（SKILL.md「出力フォーマット」/ checklist.md O2、C-Auto-1 / C-Auto-2 で自動確認）
- 統合サマリの最終フォーマット・Verdict 判定は行わない（オーケストレーター責務。SKILL.md「重要な制約」）
- Finding ID（CR-NNN）を自スキルで採番しない（checklist.md O9）
