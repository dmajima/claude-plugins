# case-02 DB 変更なし（dba 内部省略・省略理由の明記）

レビュー対象の差分に SQL / DB スキーマ / マイグレーション変更が一切含まれないケース。dba のみを内部省略し、architect は常に起動すること、および省略の旨を中間レポートに明記することを検証する。

## 入力

| 項目 | 内容 |
|-----|------|
| 委譲 args | `<差分スコープ（アプリケーション層のリファクタリングのみ・DB 変更なし）> <プロジェクト規約サマリ> mode=standard` |
| 起動形態 | 委譲（code-review オーケストレーターから Skill ツール経由・標準モード） |

## 分岐の根拠

SKILL.md「動的に省略可（責務はオーケストレーター）」の注記「本スキルが呼ばれたら 必ず両エージェントを起動する（DB変更なしの場合のみ dba を内部で省略）。…本スキル単独で「呼ばれたが何もしない」という判断はしない」および同セクションの表（architect: 常に起動 / dba: SQL / DB スキーマ / マイグレーション変更が一切ない場合のみ内部で省略）、SKILL.md「実行フロー」手順 2「DB 変更があるか判定し、`dba` の起動可否を決定」、references/checklist.md セクション C C-Auto-3（dba 省略時にその理由が明示されているか）。

## 期待動作

- 差分に SQL / DB スキーマ / マイグレーション変更が一切ないことを判定し、dba を内部省略する（SKILL.md「動的に省略可」の表 / 「実行フロー」手順 2）
- architect は省略せず必ず起動する（SKILL.md「動的に省略可」の表「architect | 常に起動」）
- 「呼ばれたが何もしない」という判断はしない（本スキル自体を省略する判断はオーケストレーター責務。SKILL.md「動的に省略可」注記）
- 中間レポートに dba を省略した旨とその理由（DB 変更なし）を明記する（references/checklist.md C-Auto-3）
- 中間レポートは「## アーキテクチャ観点レビュー結果」+「### architect」の構造で返却する（SKILL.md「出力フォーマット」/ checklist.md C-Auto-1）
- アーキテクチャ全体整合性（システム設計・技術選定・拡張性・技術的負債・コンポーネント境界・依存方向）の評価は通常通り実施する（SKILL.md「前提」の観点表）
