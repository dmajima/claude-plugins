# case-07 スコープ外観点の他スキル誘導（O4: 実装/テスト/セキュリティ混在）

アーキテクチャレビュー中に、実装詳細・テスト・セキュリティといった他観点の指摘が混在するケース。O4 のスコープ外誘導を検証する。

## 入力

| 項目 | 内容 |
|-----|------|
| 起動フレーズ | "この設計をアーキテクチャ観点でレビューして。ついでにコードのバグ・テスト不足・SQL インジェクションも全部見て" |
| 起動形態 | 単独（ユーザー直接起動） |

## 分岐の根拠

references/skill-rules-matrix.md O4（自スキルのスコープ外は対応スキルへ誘導）、`${CLAUDE_PLUGIN_ROOT}/references/common-references.md` セクション 5（スコープ外振分けルール: architecture → 実装一般は implementation / テストは testing / セキュリティは security / UI は frontend）。

## 期待動作

- architect / dba による **アーキテクチャ観点**（システム構造・コンポーネント境界・技術選定・技術的負債・DB スキーマ設計・マイグレーション安全性）を評価する
- 実装詳細のバグ・コード品質の指摘は **implementation スキルのスコープ**として、`code-review-implementation` への誘導を明示する（common-references.md セクション 5）
- テスト不足の指摘は `code-review-testing`、SQL インジェクション等のセキュリティ指摘は `code-review-security` へ誘導する
- ただし、設計レベルでセキュリティ・性能に重大な影響がある構造的問題（例: 認可境界の設計欠陥・N+1 を誘発する設計）は architect の観点として指摘してよい（実装詳細と設計問題の切り分け）
- スコープ外と判断した指摘はスコープ外フラグ付きで返却し、「別 PR で対応」等の禁止文言は使わない（U8）
