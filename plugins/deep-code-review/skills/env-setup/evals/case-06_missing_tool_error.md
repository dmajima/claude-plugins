# case-06 ツール不在エラー報告フレーズでの起動（トリガー検証）

「gh コマンドが見つからないのでインストールして」の自然言語エラー報告フレーズで env-setup が起動することを検証するトリガーケース。構造化委譲 args による起動（case-03）と異なり、エラー報告文からの起動と単一ツールの承認〜結果返却を検証する。

## 入力

| 項目 | 内容 |
|-----|------|
| 起動フレーズ | "gh コマンドが見つからないのでインストールして" |
| モード | 対話 |

## 分岐の根拠

SKILL.md description / トリガー条件「『gh / az / csharp-ls がない』等のエラーが報告された場合」「他スキルが必要ツールの不在を検知して呼び出した場合」に合致し env-setup が起動する。case-03 の構造化委譲 args（操作 / 対象 / 呼び出し元）と異なり、自然言語のエラー報告フレーズからの起動を検証する。単一ツール（gh）のインストール承認〜結果返却の分岐。

## 期待動作

- 「gh コマンドが見つからないので…」のエラー報告フレーズで env-setup スキルが起動する（トリガー条件）
- 指定ツール（gh）の存在を `where gh` で確認する（SKILL.md 実行フロー 2）
- 不在確認後、AskUserQuestion でユーザーにインストール承認を取る（E2・承認は委譲経由でも省略しない）
- winget を最優先で使用する（`winget install --id GitHub.cli --accept-package-agreements --accept-source-agreements`。E4 優先順位 1）
- 管理者昇格が必要でも自動昇格しない（E3）
- インストール後に `gh --version` で再確認し、結果を呼び出し元（依頼スキル）に返却する（実行フロー 6・出力フォーマット）
