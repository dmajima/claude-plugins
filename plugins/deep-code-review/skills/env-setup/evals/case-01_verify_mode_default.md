# case-01 確認モード（既定・存在確認のみ）

ユーザーが「インストールして」と明示せず、ツールが揃っているかの確認のみを依頼するケース。既定の確認モードで動作し、インストールは実行しない。

## 入力

| 項目 | 内容 |
|-----|------|
| 起動フレーズ | "deep-code-review プラグインに必要なツールが揃っているか確認して" |
| モード | 対話 |

## 分岐の根拠

SKILL.md「実行モード判定」1（確認モード（既定））「ユーザーから明確な『インストールして』指示がない場合は、まず存在確認のみを行う」「存在しないツールがあれば、ユーザーにインストール可否を確認してから実行する」、references/checklist.md セクション B の E1「明示指示なしの場合は確認モード（存在確認のみ）で動作している」、SKILL.md「重要な制約」（ユーザー承認なしでのインストール実行の禁止）。

## 期待動作

- 「確認して」という依頼にインストールの明示がないため、確認モード（既定）と判定する
- SKILL.md「実行フロー」2 に従い `where <tool>` で管理対象ツールの存在確認を行う（一括確認の例: `where gh az node npm python dotnet pwsh`）
- 確認結果（インストール済み / 不足）を一覧でユーザーに提示する（実行フロー 3）
- 不足ツールがあってもインストールは実行せず、インストール可否の確認に留める（E1）
- 管理者権限への自動昇格も実施しない（SKILL.md「重要な制約」。確認モードでは昇格を要する操作自体が発生しない）
- 完了報告は SKILL.md「出力フォーマット」に従い「## env-setup 結果」見出しと「### 既にインストール済み」等のセクションで構成する（references/checklist.md セクション C の C-Auto-1）
- 認証情報の値（password / token 等）を完了報告に含めない（checklist C-Auto-3）
- `gh auth login` / `az login` 等の認証設定は実施しない（SKILL.md「責務外」）
