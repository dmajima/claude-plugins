# case-07 生成スクリプトの失敗（非 0 終了）→ エラー提示して中断

最終バリデーション・監査を通過した後、報告書生成スクリプト（generate_excel.py / generate_markdown.py）が非 0 で終了したケース。エラー内容を提示して中断し、握りつぶしや空報告書の生成をしないことを検証する。

## 入力

| 項目 | 内容 |
|-----|------|
| 起動 | オーケストレータ `test` の report フェーズから委譲、または単独起動（対話 / 非対話いずれでも同一挙動） |
| 前提 | 実績 YAML は完全でバリデーション（validate）と evidence-auditor 監査を通過する。形式選択後に generate スクリプトが非 0 終了する（例: 依存パッケージ不足・書き込み権限・スクリプト内例外） |

## 分岐の根拠

SKILL.md「検証」（生成スクリプトの exit code = 0 と出力ファイルの実在を確認する / 生成失敗〔exit code != 0〕時はエラー内容を提示して中断する。形式を変えた再試行で失敗を握りつぶさない）、`${CLAUDE_SKILL_DIR}/references/procedures.md` 2 章（終了コード 0 で成功）・4 章（トラブルシュート）、`${CLAUDE_PLUGIN_ROOT}/references/report-format.md` 1 章（報告は 1 ファイル・派生物）。

## 期待動作

- 最終バリデーション（validate）と evidence-auditor 監査は通過している（case-03 の差し戻しとは異なる段階での失敗）
- 形式選択後に generate スクリプトを venv で実行し、**exit code != 0** を検出する
- エラー内容（stderr・終了コード・想定原因）を提示して**中断**する
- 空の報告書・部分生成物を「生成成功」として返さない（握りつぶし禁止。SKILL.md「検証」）
- 形式を変えた再試行（Excel→Markdown 等）で失敗を隠蔽しない。原因（依存不足・権限・スクリプト例外）の切り分けを促す（procedures.md 4 章のトラブルシュート観点）
- test-results.yaml を Edit / Write で修正しない（読み取りのみ）

## 期待出力

| 区分 | 内容 |
|-----|------|
| 生成ファイル | なし（生成失敗のため報告書ファイルは作成されない・部分生成物は成果物として扱わない） |
| 標準出力（要約） | 生成失敗の報告: 実行したスクリプト・exit code・stderr 要約・想定原因と対処（venv 再構築・権限確認等）。正常時「引き渡し」フォーマットは用いない |
| 終了状態 | バリデーション通過後の生成段階で中断（報告書未生成） |

## 関連ケース

- case-01 / case-02: 生成成功の正常系（exit code 0）との対比
- case-03: 生成前の最終バリデーション違反による差し戻し（中断段階の違い）
