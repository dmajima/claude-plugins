# case-06 単独起動・必須入力欠落 → 実行せず案内

ユーザーがオーケストレータを経由せずに直接起動し、必須入力（target-slug / run_id / 対象ケース）が欠落しているケース。実行せずオーケストレータ経由の起動を案内することを検証する。

## 入力

| 項目 | 内容 |
|-----|------|
| 起動フレーズ | 「ユニットテストレベルのケースを実行して」（run_id・target-slug・対象ケースの指定なし） |
| 起動形態 | 単独（ユーザー直接起動） |
| 前提 | オーケストレータの start-run が実行されておらず run_id が存在しない |

## 分岐の根拠

SKILL.md「実行モード判定」（単独起動で必須入力欠落 → 実行せず案内）・「重要な制約」（run_id を採番しない）、`${CLAUDE_PLUGIN_ROOT}/references/yaml-schema.md` 2.2（run_id は results_manager.py start-run が採番・LLM の手動採番禁止）。

## 期待動作

- テスト実行を開始しない（テストランナーの実行・エビデンス生成を行わない）
- run_id を自前で採番しない（採番は results_manager.py start-run の責務）
- `/deep-test:test`（必要に応じて run-only モード等）経由での起動を案内する
- 単独実行では実績（test-results.yaml）が記録されない旨を説明する（実績記録はオーケストレータの責務）
- 憶測で target-slug を新規作成したり、test-results.yaml を直接操作したりしない

## 期待出力

| 区分 | 内容 |
|-----|------|
| 生成ファイル | なし（実行しないためエビデンス生成なし。test-results.yaml も操作しない） |
| 標準出力（要約） | オーケストレータ `/deep-test:test` 経由での起動案内と、単独実行では実績（test-results.yaml）が記録されない旨の説明 |
| 終了状態 | テスト実行せず案内に留める（run_id 未採番のまま。中間結果 JSON も返さない） |
