# case-05 API 補助確認に認証が必要 → credentials-manager 案内・フル値非出力

IT-b の API 直接確認に認証情報（API キー・トークン）が必要なケース。credentials-manager 系スキルの利用案内と、認証情報のフル値を一切扱わない・出力しないことを検証する。

## 入力

| 項目 | 内容 |
|-----|------|
| 委譲 args | target-slug=sample-web / run_id=R20260717-190000 / 対象ケース TC-ITB-004（認証付き外部 API の応答をデータ反映の裏取りとして直接確認する必要があるケース）/ 対象 URL・外部接続先情報（認証必須） |
| 起動形態 | 委譲（オーケストレータ test から Skill ツール経由・MCP ゲート通過済み・対話モード） |
| 前提 | 外部エンドポイントは疎通可だが Authorization ヘッダが必要。認証情報は会話中に提示されていない |

## 分岐の根拠

SKILL.md「実行モード判定」（認証が必要な場合の扱い）・「責務外」（認証情報の保存・解決・適用は credentials-manager 系スキル）・「重要な制約」（フル値を扱わない）、references/integration-execution.md 4.3（認証が必要な場合）・4.4（マスキング手順）、`${CLAUDE_PLUGIN_ROOT}/references/evidence-policy.md` 5 章（マスク形式・対象・チャット出力への生の値記載禁止）。

## 期待動作

- 認証が必要と判明した時点で、**credentials-manager 系スキルの利用をユーザーに案内**し、認証情報の解決・適用をそちらに委ねる（本スキルで認証情報の保存・管理を行わない）
- 認証情報のフル値をチャット出力・ログ・reason / actual・エビデンス・コマンド文字列の記録に含めない
- コマンド例・再現手順に認証を含める場合は Authorization ヘッダ等の値をマスクした形で記載する（マスク形式は evidence-policy.md 5 章に従う）
- マスクにより再現に必要な情報が欠ける場合は、値そのものではなく「値の取得方法・格納場所」を reproduction_steps に記載する
- 非対話等で認証が解決できない場合は、当該 API 直接確認を実施せず、その旨（API 補助確認未実施と理由）を actual / reason・返却時の特記事項に記録する（画面経由の確認だけで判定できる範囲は通常どおり判定する）
- エビデンス保存前にマスキングを実施し、保存後に Grep でマスク漏れを確認する

## 期待出力

| 区分 | 内容 |
|-----|------|
| 生成ファイル | 画面確認分のスクリーンショットを `evidence/R20260717-190000/TC-ITB-004/` 配下へ移送（API 証跡を保存する場合はマスキング実施・Grep でマスク漏れ確認後に限る）。test-results.yaml へは書き込まない |
| 標準出力（要約） | 中間結果 JSON（skill: "test-run-integration" / 受領 run_id / results 1 件）。「引き渡し（中間結果 JSON 返却）」に準拠し、特記事項に credentials-manager 系スキルの利用案内（未解決時は API 補助確認未実施と理由）を含め、認証情報のフル値は一切出力しない |
| 終了状態 | scope 全 1 件を 1 エントリずつ返却。画面経由で判定できる範囲の status を確定し、認証未解決の場合は API 補助確認未実施を actual / reason に記録 |
