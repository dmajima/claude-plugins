# case-02 IT-b 外部接続不可 → スタブポリシー判断

外部結合（IT-b）のケースで外部テスト用エンドポイントに接続できないケース。即座に skipped とせず、ケースの検証目的に応じてスタブポリシー（test-levels.md 5 章）で「スタブ実行 / skipped」を使い分けることを検証する。

## 入力

| 項目 | 内容 |
|-----|------|
| 委譲 args | target-slug=sample-web / run_id=R20260717-173000 / 対象ケース TC-ITB-001（外部決済 API の異常応答時に自システムがエラーハンドリングすることの検証。プロジェクトにモックサーバー設定あり）・TC-ITB-002（実外部システムとの疎通・契約整合そのものの検証）/ 対象 URL・外部接続先情報 |
| 起動形態 | 委譲（オーケストレータ test から Skill ツール経由・MCP ゲート通過済み） |
| 前提 | MCP 利用可・対象アプリ稼働中。外部テスト用エンドポイントが停止しており疎通不可 |

## 分岐の根拠

SKILL.md「実行フロー」手順 3（IT-b: 接続不可時はスタブポリシーに従い判断）・「重要な制約」（スタブ実行の pass を実接続の検証完了と混同しない）、references/integration-execution.md 2.1（外部疎通の事前確認）・3 章（スタブ判断の運用手順・記録）、`${CLAUDE_PLUGIN_ROOT}/references/test-levels.md` 5.2（スタブ利用ポリシー: 判断基準の SSOT）。

## 期待動作

- ケース実行前に外部接続先の疎通を確認し、接続不可を検出する（即座に skipped とせず、まずポリシー判断を行う）
- 各ケースの検証目的を title / requirement / expected から特定し、test-levels.md 5.2 の表に照らして判断する:
  - TC-ITB-001（目的 = 自システム側の外部 IF 処理の検証・スタブあり）→ **スタブ実行**し pass / fail を判定する。actual に「スタブ応答による確認・実接続未検証」を明記し、返却時の特記事項にも含める
  - TC-ITB-002（目的 = 実疎通そのものの検証）→ **skipped** とし、reason に「実接続でのみ検証可能なためスタブでは目的を達成できない」の趣旨を記録する
- スタブの存在確認は Glob / Grep でプロジェクト内のモック設定を探索して行う
- スタブ実行で pass しても IT-b の実接続検証が完了したとは扱わない（報告書の未確認事項への転記材料を返却に含める）
- スタブ判断の基準を自前で創作せず、test-levels.md 5 章の基準に従う（複製もしない）
- scope 全件（2 エントリ）を返却する

## 期待出力

| 区分 | 内容 |
|-----|------|
| 生成ファイル | スタブ実行した TC-ITB-001 のスクリーンショットを `evidence/R20260717-173000/TC-ITB-001/` 配下へ移送（actual にスタブ利用・実接続未検証を明記）。skipped の TC-ITB-002 はなし。test-results.yaml へは書き込まない |
| 標準出力（要約） | 中間結果 JSON（skill: "test-run-integration" / 受領 run_id / results 2 件）。「引き渡し（中間結果 JSON 返却）」に準拠し、特記事項にスタブ利用（実接続未検証・報告書の未確認事項への転記材料）を含める |
| 終了状態 | scope 全 2 件を 1 エントリずつ返却。TC-ITB-001 はスタブ実行による pass / fail 判定、TC-ITB-002 は skipped + reason（実接続でのみ検証可能） |
