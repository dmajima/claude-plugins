# case-16 設計レビュー修正ループの上限超過（対話 3 択）

設計レビューの修正ループが上限 3 回を超過した場合に、対話モードでは AskUserQuestion による 3 択（続行 / 中断 / 指摘を許容して進行）を提示し、選択に応じた帰結を正しく実行することを検証する。

## 入力

| 項目 | 内容 |
|-----|------|
| ユーザー発話 | 「このアプリをテストして」（フルフロー・対話モード） |
| 前提 | test-review（設計文脈）が 3 回連続 NEEDS REVISION を返し、test-design への差し戻しを 3 回実施済み（= ループ上限到達）。4 回目の差し戻しが必要な状態 |

## 分岐の根拠

SKILL.md「実行フロー」Phase 3（NEEDS REVISION → 差し戻し上限 3 回・超過時は対話 = AskUserQuestion / 非対話 = エラー中断）、references/flow.md 4.1（ループ回数の数え方 =「test-design への差し戻し」を 1 回と数える〔初回設計は 0 回目〕/ 超過時の AskUserQuestion 選択肢の文言例: 続行〔追加ループ〕・中断〔test-cases.yaml は draft のまま保存済み。resume 対象ではなく design-only 等での再開になる〕・指摘を許容して進行〔未解消の指摘は引き渡しと報告書の未確認事項に記録〕）、プラグイン共通 references/execution-policy.md 1.1（設計レビューゲート: 修正ループ上限 3 回・超過時の対話 / 非対話分岐）。

## 期待動作

- ループ回数を「test-design への差し戻し」の回数で数える（test-review の実行回数 − 1。初回設計は 0 回目）
- 差し戻し 3 回実施済みで 4 回目が必要になった時点で、自動でループを続けず AskUserQuestion を発行する
- 選択肢は「続行（追加ループ）/ 中断 / 指摘を許容して進行」の 3 択とし、各選択肢に帰結を 1 行で添える（flow.md 4.1 の文言例）
- 「続行（追加ループ）」選択時: 指摘の修正（test-design 差し戻し）と再レビューをもう 1 回実施する
- 「中断」選択時: 処理を終了する。test-cases.yaml は draft のまま保存済みであること・resume 対象ではなく design-only 等での再開になることを案内する（run 未着手のため中断 run は存在しない）
- 「指摘を許容して進行」選択時: 未解消の指摘を**引き渡しと報告書の未確認事項に必ず転記**したうえで Phase 4 へ進む（指摘を黙殺しない）
- 上限超過の判断までオーケストレータ自身が test-cases.yaml を編集して指摘を解消しない（修正は test-design の責務）

## 期待出力

| 区分 | 内容 |
|-----|------|
| 生成ファイル | 「中断」時は test-cases.yaml（draft のまま）以外を生成しない。「指摘を許容して進行」時は後続フェーズで test-results.yaml（results_manager.py 経由）と報告書（未確認事項に未解消指摘を転記）を生成 |
| 標準出力（要約） | 上限到達の説明と AskUserQuestion の 3 択（各帰結 1 行付き）。「中断」時は draft 保存済みと design-only 等での再開手段の案内。「指摘を許容して進行」時は未解消指摘を未確認事項へ転記した引き渡し |
| 終了状態 | ユーザー選択に従う: 続行 = 追加ループ 1 回 / 中断 = run 未着手のまま停止 / 許容 = Phase 4 以降へ進行（未解消指摘は転記済み） |
