# case-11 人間承認ゲート否認（「中断する」選択）

Phase 4 の人間承認ゲートでユーザーが「中断する」を選択した場合に、scope・実績とも未変更のまま中断し、run を開始しない（start-run 未実行）こと・再開手段を案内することを検証する。

## 入力

| 項目 | 内容 |
|-----|------|
| ユーザー発話 | 「このアプリをテストして」（フルフロー・対話モード） |
| 前提 | 設計・設計レビューは PASS 済み（全ケース approved）。`select --mode full` で scope 確定済み・承認済みケースゲート通過済み。人間承認ゲートの AskUserQuestion に対しユーザーが「中断する」を選択する |

## 分岐の根拠

SKILL.md「実行フロー」Phase 4（人間承認ゲート: AskUserQuestion。非対話はスキップ）と「引き渡し」停止・中断時（その他の中断: 中断位置・test-results.yaml の記録状況・再開手段を報告する）、プラグイン共通 references/execution-policy.md 1 章（ゲート配置図: 人間承認ゲート否認 → 中断）・1.3（人間承認ゲート: 提示必須項目・選択肢文言例「中断する」= 実績未変更のまま終了する）、references/flow.md 1 章（Phase 4 → 中断: 人間承認ゲート否認）・3 章（人間承認ゲート不通過時の遷移 = 中断〔scope・実績は未変更のまま〕、`start-run` は全ゲート通過後にのみ実行〔未実行の run レコードを残さないため〕）。

## 期待動作

- AskUserQuestion で提示必須項目（実行ケース数 / 対象テストレベル / 想定所要時間 / 破壊的操作を含むケースの有無）を提示し、各選択肢（実行する / 対象を見直す / 中断する）に帰結を 1 行で添える（execution-policy.md 1.3 の文言例）
- 「中断する」選択を受けたら、MCP ゲート以降へ進まず**中断**する
- `start-run` を実行しない（未実行の run レコードを test-results.yaml に残さない。flow.md 3 章）
- test-results.yaml・test-cases.yaml とも変更しない（scope 確定は select の出力を受領しただけであり、承認状態・実績に書き込みが発生していないことを前提に維持する）
- 実行スキル（test-run-*）を Skill 起動しない
- 中断報告に（1）中断位置（Phase 4 人間承認ゲート）、（2）記録状況（実績未変更・run 未作成のため resume 対象の中断 run は存在しない）、（3）再開手段（同モード〔フル等〕での再実行。scope の見直しが目的なら select からやり直せる旨）を含める（SKILL.md「引き渡し」停止・中断時）
- 中断をエラーとして扱わない（ユーザーの正当な選択として整然と終了する）

## 期待出力

| 区分 | 内容 |
|-----|------|
| 生成ファイル | なし（start-run 未実行のため test-results.yaml に run レコードを追加しない。test-cases.yaml も変更しない。報告書も生成しない） |
| 標準出力（要約） | SKILL.md「引き渡し」停止・中断時のフォーマット: 中断位置（人間承認ゲート）・記録状況（scope・実績とも未変更・run 未開始）・再開手段（同モードでの再実行。resume 対象ではない旨） |
| 終了状態 | Phase 4 で中断（run 未開始・実績未変更）。再実行すれば select から同じ手順でやり直せる状態を保つ |

## 関連ケース

- case-05: 非対話時は人間承認ゲート自体をスキップする（本ゲートが働くのは対話時のみ）
- case-12: 同ゲートで提示する「破壊的操作を含むケースの有無」の判定材料
