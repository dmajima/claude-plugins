# case-07 テスト対象（対象説明= / 位置引数）が完全未指定 × 対話（AskUserQuestion で確認）

テスト対象そのもの（`対象説明=` または位置引数）が完全に未指定で、`spec=` もリポジトリパスも与えられていない場合、分析材料が無いため設計に進まず、**対話時は AskUserQuestion で対象を確認**すること（誤った対象への設計を防ぐ）を検証する。target-slug（既存テストデータ領域）の解決分岐（case-05 / 06）とは別軸であることに注意する。非対話モード（エラー中断）は case-08 で扱う。

## 入力

| 項目 | 内容 |
|-----|------|
| 委譲 args | `target-slug=orderapp-web base=<base>`（`対象説明=` も位置引数も `spec=` も無し。対象の実体を示す情報が皆無・`--non-interactive` なし = 対話） |
| 起動形態 | 委譲（オーケストレータ `test` の design フェーズ）/ 単独起動でも同一挙動 |
| 前提 | target-slug は解決済み（データ配置先は確定）だが、何をテスト対象とするか（アプリ URL・リポジトリパス・対象名）の入力が一切ない。既存 test-cases.yaml も無い（新規設計） |

## 分岐の根拠

SKILL.md「受け取る引数」（`対象説明=` または位置引数が未指定時: 対話時は AskUserQuestion で確認）・「実行モード判定」（対話: 対象の不足情報も AskUserQuestion で確認）、`${CLAUDE_SKILL_DIR}/references/design-procedures.md` 2 章（テスト対象〔`対象説明=` または位置引数〕が未指定の場合: 対話時は AskUserQuestion で確認する〔誤対象への設計を防ぐ〕）・3.1 章（入力別の分析方法。分析材料が spec / リポジトリ / URL のいずれかを要する）。

## 期待動作

- 対象の実体を示す情報が無いことを検出し、**AskUserQuestion でテスト対象（アプリ URL・リポジトリパス・対象名・仕様書の所在等）を確認**する。憶測で target-slug 名から対象を推定して分析を始めない
- ユーザーが対象を提示したら通常の分析（design-procedures.md 3 章）へ進む。提示が得られなければ設計に進まない
- 対象未確定のまま test-plan.md / test-cases.yaml を生成・変更しない（誤った対象への設計・空の計画の生成をしない）
- target-slug 解決の分岐（既存 slug の有無・複数）とは独立した検証であり、slug が確定していても対象説明が無ければ本分岐に入る
- test-results.yaml へは書き込まない

## 期待出力

| 区分 | 内容 |
|-----|------|
| 生成ファイル | なし（対象未確定のまま test-plan.md / test-cases.yaml を生成・変更しない。test-results.yaml へも書き込まない） |
| 標準出力（要約） | AskUserQuestion でテスト対象（アプリ URL・リポジトリパス・対象名・仕様書の所在等）を確認する問い |
| 終了状態 | 対象確認待ち（提示後に設計継続・対象を推測しない） |
