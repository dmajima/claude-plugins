# 言語スキル追加ガイド（テンプレート）

新しい言語スキル `coding-{lang}` を追加する際の構成と、規約リファレンス（`conventions.md`）の共通章構成を定義する。
章構成が統一されていることで、オーケストレーター（`orchestrator-coding` / `orchestrator-design`）は言語を問わず同一手順で言語スキルを参照できる。

## 1. 言語スキルの構成

```text
skills/coding-{lang}/
├── SKILL.md                 # 言語スキル定義（既存の coding-* スキルの構成に合わせる）
├── README.md                # 人間向けリファレンス
└── references/
    ├── conventions.md       # 言語規約（本ファイルの章構成テンプレートに従う）
    └── frameworks/          # 単一言語専用 FW プロファイル（該当がある場合のみ）
        └── {fw}.md
```

追加手順:

1. `conventions.md` を下記テンプレートの章構成で作成する
2. `SKILL.md` を既存言語スキル（例: `skills/coding-python/SKILL.md`）と同じセクション構成で作成する。必須セクション（ai-readability 正典順）: 責務 / 責務外 / トリガー条件 / 前提 / 利用モード / **実行モード判定**（`--non-interactive` の非対話分岐を含む）/ 実行フロー（単独実行モード）/ 重要な制約 / 参照
3. `evals/` を作成する（最低: 単独実行モードの基本フロー + スコープエスカレーションの 2 ケース。既存言語スキルの evals を雛形にする）
4. [skill-index.md](skill-index.md) の言語スキル一覧に検出マーカーとともに登録する
5. 複数言語で共有する FW プロファイルは言語スキル内ではなく SSOT の [frameworks/](frameworks/) に配置する

## 2. 記載ルール

- デファクトスタンダード規約は **出典（規約名・公式 URL）を必ず明記** する
- 確信の持てない規則・数値・コマンドは記載しない（不正確な規約の記載は空欄より有害）
- 規約は「プロジェクト独自規約が存在しない場合のデフォルト」である。優先順位の解決は
  [conventions-resolution.md](conventions-resolution.md) に従う
- フレームワーク固有の規約は `frameworks/` 配下の対応プロファイルに分離する（`conventions.md` には書かない）

### 例外（単一のデファクト規約が存在しない言語）

JavaScript・SQL のように言語公式の単一標準スタイルガイドが存在しない言語では、`**準拠規約**:` の 1 行の代わりに **「単一標準が存在しない」旨の明示 + 基準とする出典のリスト（規約名・URL 付き）** を章 2 冒頭に記載する（存在しない「標準」を捏造しない）。
また SQL の方言リファレンス（`mysql.md` 等）は章 2 を「方言仕様」（識別子クォート / 大文字小文字 / 主要構文 / データ型）に置き換えてよい（章番号体系は維持し、方言間で構成を一貫させる）。

## 4. フレームワークプロファイルの章構成テンプレート

```markdown
# {FW 群名} フレームワークプロファイル

対象言語プロファイル: {対象言語スキルの conventions.md へのリンク}（言語規約はそちらに従う。本ファイルは FW 固有規約のみ）
```
