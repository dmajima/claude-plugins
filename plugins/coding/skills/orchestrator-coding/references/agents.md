# エージェント運用定義

`coding` スキルが利用するサブエージェントとフェーズ別の起動定義。
定義本体はプラグインの `agents/` に同梱（下表の subagent_type で起動する）。

## このスキルで使用するエージェント

| ID | subagent_type | 役割 | 主なツール |
|----|---------------|------|----------|
| implementer | `coding:code-implementer` | 設計と規約に従った実コード実装・修正 | Read, Grep, Glob, Edit, Write, Bash |
| reviewer | `coding:impl-reviewer` | 実装品質・規約準拠のレビュー（読み取り専用） | Read, Grep, Glob |
| test | `coding:test-engineer` | テスト十分性・回帰リスクの評価、テスト実行 | Read, Grep, Glob, Bash |
| arch | `coding:architect` | 設計妥当性・構造・技術的負債のレビュー（読み取り専用） | Read, Grep, Glob |

設計原則: **実装（書ける）とレビュー（読むだけ）でエージェントを分離** する。レビュー系エージェントに Edit / Write を持たせない。

## フェーズ定義

### Phase 2: Analyze — 影響範囲調査の委譲（任意）

- 実行エージェント: 汎用探索エージェント（`Explore` 等の read-only 系）
- 目的: 依存関係・呼び出し元の追跡が大量になる場合の調査委譲
- 入力: 変更対象の候補パス・シンボル名
- 出力: 影響範囲の要約（ファイル一覧 + 依存の説明）
- 起動条件: 3 回以上の探索が見込まれる場合。少量ならメインが直接調査する

### Phase 3: Design — 設計レビュー（条件付き）

- 実行エージェント: arch（単体）
- 目的: 大規模・高リスク変更の設計妥当性検証
- 入力: implementation-design.md + impact-analysis.md のパス + 適用言語スキルの references パス一覧（FW 構造規約プロファイル）
- 出力: 設計レビュー結果（指摘 + 重大度）
- 起動条件: `../../../references/design-principles.md` 節 2.3 の判定基準に該当する場合（条件は SSOT 側を参照。本ファイルには再掲しない）

### Phase 4: Implement — 実装の委譲（任意）

- 実行エージェント: implementer（単体、大規模時は変更ファイルの独立性が保てる単位で複数並列）
- 目的: 設計に従った実コードの実装
- 入力: implementation-design.md のパス + 適用規約サマリ（プロンプトに全文含める）+ 担当ファイルリスト
- 出力: コード変更 + 変更概要
- 起動条件: 実装量が大きい場合。小規模ならメインが直接実装する
- 制約: 複数並列時は担当ファイルを重複させない（同一ファイルは 1 エージェントのみ）

### Phase 5: Self-Review — 多角レビュー（必須）

- 実行エージェント: reviewer + test（**並列**）。クイックモードでは reviewer のみ
- 目的: 独立した視点での品質検証
- 入力: file-list.md 記載の変更ファイル + 適用規約サマリ + implementation-design.md のパス
- 出力: 指摘一覧（重大度 Critical / High / Medium / Low + 根拠 + 修正提案）
- 統合: メインが両者の指摘を統合し、矛盾があれば内容を精査して採否を判断する

## 起動プロンプトの必須要素

エージェント起動時のプロンプトには以下を必ず含める:

1. 担当フェーズと目的
2. 入力成果物の **絶対パス**（エージェントは会話コンテキストを引き継がない）
3. **適用規約サマリ**（impact-analysis.md から転記。レビュー・実装の判定基準を規約サマリに固定するため）
4. **適用言語スキルの `references/conventions.md` 絶対パス**（規約サマリに無い項目のフォールバック参照先。FW プロファイルパスも該当時に併記）
5. 出力形式（重大度分類・品質ゲート判定の形式）
6. レビュー系には「変更ファイル以外の修正提案はスコープ外の参考意見として分離すること」
7. 書き込み権限を持つエージェント（implementer）には「**git commit / push / マイグレーション実行等の不可逆操作の禁止**（コード変更とローカル検証のみ）」

## 結果の取り込み

- エージェントの生出力をそのまま成果物に貼らず、要約して該当セクションに記録する
- レビュー指摘の重大度は次で判定する: Critical = 動作不正・データ破壊・脆弱性 / High = 規約違反・明確なバグリスク / Medium = 保守性・性能の懸念 / Low = 好みの範囲
- reviewer と test の指摘が矛盾した場合は、両論を記録した上でメインが採否を決め、判断根拠を残す
