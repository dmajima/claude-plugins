# Case 04: 言語スキル未収録言語の検出

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | 「この CLI ツールにサブコマンドを追加して」 |
| 引数 | なし |
| フラグ | なし |
| 既存状態 | Go プロジェクト（`go.mod` あり）。skill-index.md に Go は未収録 |

## 期待動作

### Phase 2: Analyze
- `go.mod` から Go を検出するが、skill-index.md に対応する言語スキルが無いことを確認
- **未対応言語であることをユーザに明示**（推測規約で黙って進めない）
- プロジェクト独自規約（CLAUDE.md / .editorconfig / 既存コードの一貫した慣習）を走査:
  - 独自規約あり → それのみを根拠に継続してよい（規約サマリの根拠ソースに記録）
  - 独自規約なし → 進め方（既存慣習準拠で続行 / 中止）を `AskUserQuestion` で確認
- `language-skill-template.md` に従う Go 言語スキルの追加を提案する

### 以降のフェーズ
- 継続が選ばれた場合、確定した規約ソース（既存慣習等）に基づいて通常フローを実施
- impact-analysis.md の「未対応言語」欄に明示内容と対応方針を記録

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| ユーザへの通知 | 「Go の言語スキルは未収録」の明示 + 対応方針の確認 or 記録 |
| 生成ファイル | impact-analysis.md（未対応言語欄に記録あり） |
| 「中止」選択時の挙動 | 実装は行わず、検出結果（Go 未収録）と提示した選択肢・ユーザ判断を impact-analysis.md に記録して報告し、以降のフェーズ（Phase 3 以降）に進まない |
| 終了状態 | 成功（ユーザ確認を経て継続）または中止（ユーザ判断） |

## 分岐の根拠

このケースが分岐するトリガーは 検出言語の言語スキル有無 = なし である。language-detection.md（SSOT）の「未対応言語の扱い」が適用される。
