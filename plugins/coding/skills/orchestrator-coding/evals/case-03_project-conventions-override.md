# Case 03: プロジェクト独自規約がデファクトより優先

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | 「注文集計 API を実装して。なお命名はこのプロジェクトの流儀に合わせること」 |
| 引数 | なし |
| フラグ | なし |
| 既存状態 | JavaScript プロジェクト。`.editorconfig` に `indent_size = 4`、`CLAUDE.md` に「コメントは日本語」「関数名は動詞始まり」、既存コードは一貫して 4 スペース + セミコロンなし |

## 期待動作

### Phase 2: Analyze（規約解決が焦点）
- `coding-javascript` のデファクト規約（2 スペース・セミコロンあり）を検出しつつ、上位ソースで **項目単位にオーバーライド**:
  - インデント 4 スペース（根拠: `.editorconfig` = 優先度 2）
  - コメント日本語・関数名動詞始まり（根拠: `CLAUDE.md` = 優先度 3）
  - セミコロンなし（根拠: 既存慣習 = 優先度 4）
- 適用規約サマリの「根拠ソース」列に上記の出典を明記
- 言語スキルの規定が残る項目（camelCase 等、上位に規定なし）はデファクトを適用

### Phase 4: Implement
- 解決後の規約（4 スペース・セミコロンなし・日本語コメント）で実装する。言語スキルのデファクトで上書きしない

### Phase 5: Self-Review
- レビューエージェントへのプロンプトに適用規約サマリを含め、「2 スペースでない」等のデファクト基準による誤指摘を防ぐ

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| 生成ファイル | impact-analysis.md の適用規約サマリに優先度 2/3/4 のオーバーライドが根拠付きで記録される |
| 生成コード | プロジェクト独自規約に準拠（デファクトと異なる部分が独自規約側に揃う） |
| 終了状態 | 成功 |

## 分岐の根拠

このケースが分岐するトリガーは プロジェクト独自規約の存在 = あり（機械設定 + 文書規約 + 既存慣習）である。conventions-resolution.md の優先順位（ユーザ指示 > 機械設定 > 文書規約 > 既存慣習 > 言語スキル）が適用される。
