# Case 05: 言語境界のルーティング（スタイル変更 → coding-css）

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | 「このカードの見た目を角丸にして影を付けて」（`coding-html` を直接起動） |
| 引数 | なし |
| フラグ | なし |
| 既存状態 | 依頼内容はスタイル（`border-radius` / `box-shadow`）の変更であり、マークアップ構造（要素・階層）の変更を伴わない |

## 期待動作

### 責務境界の検出
- `coding-html` の責務は文書構造・マークアップである。依頼は見た目（角丸・影）= スタイルの変更である
- 責務外表「CSS / スタイルの実装 → `coding-css`」・起動しないケース「スタイルの変更（→ `coding-css`）」に該当することを把握する

### ルーティング
- スタイル実装（`border-radius` / `box-shadow`）は `coding-css` が担当する旨をユーザに案内する（`coding-html` ではスタイルを実装しない）
- スタイル適用のためにクラス付与などマークアップ側の最小調整が必要な場合のみ、その部分を `coding-html` が担当し、スタイル本体は `coding-css` に委ねる

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| ルーティング | スタイル実装は `coding-css` を案内 |
| 生成ファイル | `coding-html` としてはスタイル変更なし（必要時にクラス付与等のマークアップ調整のみ） |
| 終了状態 | 成功（適切なスキルへ案内） |

## 分岐の根拠

このケースが分岐するトリガーは 責務境界 = スタイル（`coding-css` の担当）である。
`coding-html` の責務外表・起動しないケースに定義されたマークアップ / スタイルの境界を検証する。
