# Case 01: 単独実行モードの基本フロー

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | 「この一覧ページにフォームを追加して」 |
| 引数 | なし |
| フラグ | なし |
| 既存状態 | 静的 HTML サイト（`.html` + `.editorconfig`）。対象は `list.html` の 1 ファイル。変更見込み 1 ファイル |

## 期待動作

単独実行モードの軽量フロー（規約解決 → FW 確認 → 実装 → 検証 → 報告）を実施する。

### 手順 1: 規約解決
- 規約優先順位の SSOT（`conventions-resolution.md`）に従い、プロジェクト独自規約（`.editorconfig` / `.prettierrc*` / `.htmlvalidate.json` / `CLAUDE.md` / 既存慣習）を走査する
- 独自規約がない項目は `references/conventions.md` のデファクト規約で補完する（スペース 2、属性値はダブルクォート、要素名・属性名は小文字、セマンティック要素、任意タグは非省略）
- 規約の矛盾があれば `AskUserQuestion` で確認する（対話モード）。本ケースは方針が自明なため確認なしで進む

### 手順 2: FW 確認
- 対象が素の `.html`（テンプレート `.jsx` / `.tsx` / `.vue` / `.blade.php` ではない）ため、FW 固有構文は非該当

### 手順 3: 実装
- `form` / `fieldset` / `label` で構造化し、各入力を `<label for="id">` で関連付ける（`for` と `id` を一致させる）
- 既存の `<!DOCTYPE html>` / `lang` 属性 / `<meta charset="utf-8">` と見出し階層を壊さない
- 既存ファイルの編集のため、周辺コードのスタイル・エンコーディング・改行コードを維持する

### 手順 4: 検証
- `npx html-validate "**/*.html"`（利用可能な場合）、ブラウザ表示確認、アクセシビリティ基本チェック（`img` の `alt` / `label` 関連付け / 見出し階層）を行う
- 実行不能な検証は SKIPPED として報告する

### 手順 5: 報告
- 変更ファイル・適用規約の根拠（`.editorconfig` / `.htmlvalidate.json` の該当設定 or デファクト）・検証結果を報告する
- 変更見込みが 4 ファイル未満のため `orchestrator-coding` への切替提案は行わない

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| 変更ファイル | `list.html` |
| 標準出力（要約） | 追加したフォーム構造・アクセシビリティ確認結果・適用規約の根拠 |
| 終了状態 | 成功（単独実行モードで完結） |

## 分岐の根拠

このケースが分岐するトリガーは タスク規模が小さく（変更 1 ファイル）言語が HTML で明確 である。
このため `orchestrator-coding` の 6 フェーズ統括ではなく、言語スキル単独の軽量フローで処理する。
境界: フェーズ統括・複数言語の併用（スタイルは `coding-css`、スクリプトは `coding-javascript` 等）・設計判断が必要なら `orchestrator-coding` に委ねる。
