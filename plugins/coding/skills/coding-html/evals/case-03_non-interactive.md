# Case 03: 非対話モードでの単独実行

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | 「この問い合わせフォームに電話番号の入力欄を追加して --non-interactive」 |
| 引数 | タスク説明 |
| フラグ | `--non-interactive` |
| 既存状態 | 静的サイト（素の HTML）。ラベル文言・入力の必須/任意が未指定。ユーザの直接依頼で `coding-html` を単独起動（orchestrator を経由しない） |

## 期待動作

単独実行モードの実行フロー 5 段を、実行モード判定表の非対話行（`--non-interactive` → 確認をスキップし、最も保守的な解釈を採用して進行する。採用した判断は報告に記録する）に従って実施する。

### 全ステップ共通
- `AskUserQuestion` を発火させず、不明点（ラベル文言・必須/任意）は最も保守的な解釈を採用して進行する
- 採用したデフォルト判断を報告に必ず記録する

### ステップ1〜2: 規約解決・FW 確認
- 独自規約（`.editorconfig`・`.prettierrc*`・`.htmlvalidate.json`・`CLAUDE.md`）を走査する
- 規約に矛盾があっても確認せず、SSOT `../../../references/conventions-resolution.md` の優先順位で機械的に解決し、採用理由を記録する
- テンプレート（JSX / SFC / Blade 等）ではなく素の HTML のため FW 固有構文の参照は不要と判断する

### ステップ3: 実装
- 電話番号欄は既存フォームのマークアップ様式に合わせる保守的判断を採用する（`type="tel"`・`label` の関連付けを付与し、必須/任意は既存欄の傾向に合わせる）
- `img` の `alt` / `label` 関連付け / 見出し階層など [references/conventions.md](../references/conventions.md) の必須事項を維持する

### ステップ4〜5: 検証・報告
- 利用可能な範囲でブラウザ表示確認・`npx html-validate`（利用可能な場合）・アクセシビリティ基本チェックを行う。実行不能な検証は SKIPPED として報告する
- 採用したデフォルト判断・適用規約の根拠・検証結果を報告する

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| ユーザへの確認 | 0 回（AskUserQuestion 不発火） |
| 生成ファイル | リポジトリへのマークアップ変更。報告にデフォルト判断（ラベル文言・必須/任意）の記録あり |
| 終了状態 | 成功（保守的解釈で完了） |

## 分岐の根拠

このケースが分岐するトリガーは フラグ = `--non-interactive` である。
実行モード判定表の非対話行「確認をスキップし、最も保守的な解釈を採用して進行する（採用した判断は報告に記録）」を単独実行フロー全体に適用する。
