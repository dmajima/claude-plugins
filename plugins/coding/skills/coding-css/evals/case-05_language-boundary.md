# Case 05: 言語境界のルーティング（マークアップ構造の変更 → coding-html）

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | 「このリストをカード型のグリッドにして。必要ならマークアップ要素も足して」（`coding-css` を直接起動） |
| 引数 | なし |
| フラグ | なし |
| 既存状態 | 依頼はグリッドレイアウト（CSS）に加え、カードを構成する新規マークアップ要素・階層の追加を含む |

## 期待動作

### 責務境界の検出
- `coding-css` の責務はスタイルである。依頼のうち「カード型グリッドのレイアウト」はスタイル（`display: grid` 等）だが、「マークアップ要素の追加」は文書構造の変更である
- 責務外表「マークアップ構造の変更 → `coding-html`」・起動しないケース「マークアップ構造の変更（→ `coding-html`）」に該当することを把握する

### ルーティング（担当分割）
- スタイル（Grid レイアウト・カードの見た目）は `coding-css` が担当する
- マークアップ構造の追加（新規要素・階層）は `coding-html` の担当である旨をユーザに案内する（`coding-css` では構造を変更しない）

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| ルーティング | マークアップ構造の追加は `coding-html` を案内、スタイルは `coding-css` が担当 |
| 生成ファイル | `coding-css` としてはスタイル変更のみ（マークアップ構造の追加は行わない） |
| 終了状態 | 成功（担当分割・適切なスキルへ案内） |

## 分岐の根拠

このケースが分岐するトリガーは 責務境界 = マークアップ構造（`coding-html` の担当）である。
`coding-css` の責務外表・起動しないケースに定義されたスタイル / マークアップの境界を検証する。
