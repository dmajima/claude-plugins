# SQL: PostgreSQL 方言プロファイル

PostgreSQL 固有の仕様を扱う。方言によらない共通の慣習・安全性・パフォーマンス基本は
[conventions.md](conventions.md)（SQL 共通）に従い、本ファイルは **PostgreSQL 固有の確実な仕様のみ** を記載する。
記載内容は PostgreSQL 公式ドキュメント（<https://www.postgresql.org/docs/current/>）に基づく。

## 1. 識別（プロジェクト検出）

| 項目 | 値 |
|------|-----|
| 接続設定 | `postgres://` / `postgresql://`、接続文字列に `postgres:` / `Host=...;Database=...`、ドライバ `psycopg`(`psycopg2`) / `asyncpg` / `pg` / `Npgsql` |
| 既定ポート | `5432` |
| コンテナ | `docker-compose.yml` / Dockerfile の `postgres` イメージ |
| その他 | `postgresql.conf` / `pg_hba.conf`、`SERIAL` や `GENERATED ... AS IDENTITY`、`JSONB`/`TIMESTAMPTZ` を含む DDL、`RETURNING` 句、`ON CONFLICT` |

## 2. 方言仕様

### 2.1 識別子クォート

- 識別子のクォートは **ダブルクォート** `"identifier"`（文字列リテラルはシングルクォート `'...'`）。
- **引用符なしの識別子は自動的に小文字へ畳み込まれる（fold to lower-case）**。これは SQL 標準（大文字へ畳み込む）からの PostgreSQL 独自の逸脱。
  ```sql
  CREATE TABLE MyTable (...);   -- 実体は "mytable" になる
  SELECT * FROM MyTable;        -- "mytable" として解決され成功
  SELECT * FROM "MyTable";      -- 引用符付きで大文字混在の別名を要求 → 存在せずエラー
  ```
- 大文字混在名でテーブルを作ると **以後すべての参照でダブルクォートが必須** になり、事故の温床になる。
- **対策**: 識別子は **引用符なしの小文字 `snake_case`** で作成・参照する（[conventions.md](conventions.md) 2.1 の強い根拠）。

### 2.2 大文字小文字の扱い

- 識別子は 2.1 のとおり引用符なしなら小文字化される。データ（文字列値）の比較は既定で大文字小文字を **区別する**。非区別比較が必要なら `LOWER()` や `ILIKE`、`citext` 拡張を用いる。

### 2.3 主要構文

| 用途 | PostgreSQL 構文 |
|------|----------------|
| 連番主キー | `id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY`（現行推奨・下記） |
| ページング | `LIMIT <count> OFFSET <offset>` |
| UPSERT | `INSERT ... ON CONFLICT (...) DO UPDATE` / `DO NOTHING`（下記） |
| 挿入・更新結果の取得 | `RETURNING`（下記） |

連番主キー（`SERIAL` より IDENTITY 列）:

- 現行の推奨は **`GENERATED ALWAYS AS IDENTITY`**（SQL 標準準拠の ID 列）。旧来の擬似型 `SERIAL`/`BIGSERIAL` は内部的にシーケンス＋既定値で実現され、所有権・権限・スキーマダンプ挙動で扱いにくい面がある。新規設計では IDENTITY 列を選ぶ。
  - アプリ側で明示的に値を差し込む余地を残したい場合は `GENERATED BY DEFAULT AS IDENTITY` を使う。

UPSERT:

```sql
INSERT INTO stock (product_id, qty)
VALUES (10, 5)
ON CONFLICT (product_id) DO UPDATE
    SET qty = stock.qty + EXCLUDED.qty;
```

- `ON CONFLICT` の対象は一意制約／一意インデックスの列。挿入しようとした行は `EXCLUDED` で参照する。衝突時に何もしないなら `DO NOTHING`。

`RETURNING` 句:

- `INSERT`/`UPDATE`/`DELETE` に `RETURNING` を付けると、影響を受けた行の値（採番された `id` 等）を同一文で取得できる。追加の `SELECT` 往復を省ける。
  ```sql
  INSERT INTO orders (customer_id) VALUES (42) RETURNING id;
  ```

### 2.4 データ型の注意点

- **`TIMESTAMPTZ`（`timestamp with time zone`）を推奨**。値は UTC で格納され、取得時にセッションの `TimeZone` に変換される。タイムゾーンを持たない `TIMESTAMP`（`without time zone`）は変換されず、地域をまたぐと解釈が曖昧になる。時刻はタイムゾーン安全な `TIMESTAMPTZ` を既定にする。
- **`TEXT` で十分**。PostgreSQL では `TEXT` と `VARCHAR(n)` に性能差はなく、`VARCHAR(n)` の `n` は長さ制約（バリデーション）としてのみ意味を持つ。明確な上限がある場合のみ `VARCHAR(n)`、それ以外は `TEXT` を使う。
- 豊富な組み込み型を活用する:
  - `JSONB`（バイナリ JSON。索引可能・演算子豊富。`JSON` 型より通常はこちら）
  - `ARRAY`（配列型）
  - `UUID`（一意識別子。`gen_random_uuid()` で生成）
  - `NUMERIC(p, s)`（金額など正確な小数）
  - `ENUM`、範囲型（`int4range` 等）、ネットワーク型（`inet`/`cidr`）ほか
- 金額に `FLOAT`/`DOUBLE PRECISION` を使わず `NUMERIC` を使う。

## 3. ツールチェーン

| 用途 | コマンド／方法 | 備考 |
|------|--------------|------|
| 実行計画（見積り） | `EXPLAIN <statement>` | 実行せずプランを表示 |
| 実行計画（実測） | `EXPLAIN (ANALYZE, BUFFERS) <statement>` | 実際に実行し、実測時間・行数・バッファ使用量を出力（`ANALYZE` は実行を伴うため副作用のある文に注意） |
| 統計更新 | `ANALYZE [table]` | プランナ統計を更新 |
| クライアント | `psql` CLI、pgAdmin | |

## 4. イディオム・ベストプラクティス（PostgreSQL 固有）

- **VACUUM / ANALYZE の理解**: PostgreSQL は追記型（MVCC）のため、更新・削除で発生する不要行（dead tuple）を `VACUUM` が回収し、`ANALYZE` がプランナ統計を更新する。通常は **autovacuum** が自動実行するが、大量更新テーブルでは統計の陳腐化・肥大化（bloat）に注意し、必要に応じて手動 `VACUUM (ANALYZE)` を行う。`VACUUM FULL` はテーブルを再構築し排他ロックを取るため運用時間帯に注意。
- 大文字混在の識別子・予約語の使用を避け、引用符不要な `snake_case` に統一する（2.1）。
- 部分インデックス（`WHERE` 付きインデックス）・式インデックス・`JSONB` の GIN インデックスなど、PostgreSQL 固有の索引機能を条件に応じて活用する。
- 多くの DDL が **トランザクション内で実行・ロールバック可能**（`CREATE TABLE` 等）。マイグレーションをトランザクションで囲みやすい。ただし `CREATE INDEX CONCURRENTLY` などトランザクション内で使えない文もある点に注意。

## 5. 典型エラーパターンと対処

PostgreSQL は標準の **SQLSTATE**（5 文字コード）でエラーを分類する。代表例:

| SQLSTATE | 条件名 | 原因 | 対処 |
|----------|-------|------|------|
| `23505` | `unique_violation` | 主キー／一意制約の重複 | 事前存在確認、または `INSERT ... ON CONFLICT` |
| `23503` | `foreign_key_violation` | 親行不在の子行挿入／被参照の親行削除 | 挿入順序・`ON DELETE` 方針を見直す |
| `23502` | `not_null_violation` | NOT NULL 列に NULL を挿入 | 値を与える、または既定値／列定義を見直す |
| `23514` | `check_violation` | CHECK 制約違反 | 入力値・制約条件を確認 |
| `42P01` | `undefined_table` | テーブルが存在しない（スキーマ・search_path・大文字小文字） | 名前・`search_path`・引用符を確認 |
| `42703` | `undefined_column` | 列が存在しない | 列名・引用符（大文字混在）を確認 |
| `40P01` | `deadlock_detected` | デッドロック検出 | ロック取得順序を統一、トランザクションを短くしてリトライ |
