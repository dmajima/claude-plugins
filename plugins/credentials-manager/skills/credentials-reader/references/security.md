# セキュリティ注意

`credentials-reader` スキルが守るべき・利用者に伝えるべきセキュリティ上の制約。書き込み系の制約は `credentials-manager` 側 `references/security.md` を参照すること。

## 1. 値の表示制約

| 場面 | 表示 |
|-----|------|
| ユーザへの会話出力 | マスク済み値（`<先頭4>****<末尾4>`）のみ |
| ログ・コミットメッセージ | フル値・マスク済み値ともに含めない |
| プログラム利用（API 呼び出し時） | フル値で利用してよいが、結果出力にエコーしない |

8 文字以下の短い値は部分露出せず全マスク `****` とする。

## 2. プロアクティブ検出時の注意

API キー風文字列を会話中で検出した場合、検出文字列そのものを再表示せず、マスクした上で保存提案する。提案を断られた場合はその旨だけ記録し、引き継ぎは行わない。

## 3. クロスセッション漏洩防止

| 項目 | 動作 |
|-----|------|
| `progress.md` 等の作業ログへの値転記 | 禁止 |
| 別スキルへの引き渡し | マスク済み値 + 認証情報名のみ。フル値は呼び出し元の API 適用時に直接利用 |
| `inputs/` フォルダへの平文転記 | 禁止 |
| `credentials-manager` への引き継ぎ時 | フル値は渡さず、ユーザ再入力 or ストア参照に委ねる（[`handoff.md`](handoff.md) 節 3） |

## 4. グローバル設定との関係

| 設定 | 影響 |
|-----|------|
| `~/.claude/rules/security/credentials-management.md` | 存在すればグローバルに認証情報問い合わせ先として本スキルが参照される。**不在でも本スキルは自身の description によって URL/API アクセス時に自動起動するため、利用者環境に同ルールがある必要はない** |

## 5. 暗黙トリガー時のフェイルセーフ

| 状況 | 動作 |
|-----|------|
| `credentials.json` 読み取り権限なし | 「アクセス権限がありません」とユーザに通知し、フローを停止 |
| `credentials.json` パース失敗 | バックアップ + 再初期化は `credentials-manager` の責務。reader は読み取り失敗を通知して引き継ぎを提案 |
| URL 抽出失敗（曖昧表現） | 自動マッチをスキップしユーザに対象 URL を確認 |
| ユーザ明示の「認証なしでアクセス」 | 自動マッチをスキップ |

## 6. 利用者への注意喚起

参照のみでは平文値の転記やコピーが発生しない。書き込み発生時は `credentials-manager` 側で平文保存に関する通知を行う（同一セッション内では繰り返さない）。
