# Case 12: URL アクセス時の自動マッチ（ホスト部のワイルドカード → 確認）

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | "https://eu.example.com/api から取得して。" |
| 引数 | なし |
| フラグ | なし |
| 既存状態 | `credentials.json` に `example-key`（urls=`["https://*.example.com/api"]`、domains なし）が 1 件だけ保存済み |

## 期待動作

### Phase 1: ホスト名の取り出し

- スキームは `https://`、authority は `eu.example.com`（`\` `@` `%` 等を含まない）。ホスト名は `eu.example.com`

### Phase 2: マッチング

- パターンのホスト部 `*.example.com` の `*` は 1 つのラベルにだけ一致する。`eu` が 1 つのラベルとして一致し、スキーム・パスも一致する
- ホスト部に `*` を含むパターンでの一致のため **弱い一致**

### Phase 3: 確認

- 自動適用しない
- `AskUserQuestion` で「`example-key` (`****`) が `eu.example.com` に一致しうる（ワイルドカードのホスト）。適用しますか？」と確認し、承諾されたときだけ付与する

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| `AskUserQuestion` | 発火する（マスク済み値・一致の根拠を表示） |
| 自動適用の通知 | 出ない |
| フル値 | 会話に出ない |

## 合否の基準

承諾前に認証情報を付与しない・確認の選択肢に「適用しない」がある・一致の根拠として「ワイルドカードのホスト」を示す、の 3 つをすべて満たせば合格。

## 分岐の根拠

ワイルドカードのホストは、保存した時点で送り先のホストを確定しない。一致しても確認を求め、確認なしで使いたい場合は
`domains[]` に完全なホスト名を入れる（auto-match.md 3 章）。
