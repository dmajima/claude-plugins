# Case 16: 非対話モードでの自動マッチ（弱い一致だけ → 適用しない）

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | "--non-interactive で https://eu.example.com/api を呼び出して。" |
| 引数 | URL あり |
| フラグ | `--non-interactive` 相当 |
| 既存状態 | `credentials.json` に `example-key`（urls=`["https://*.example.com/api"]`、domains なし）が 1 件だけ保存済み |

## 期待動作

### Phase 1: マッチング

- ホスト部のワイルドカードで一致する **弱い一致** だけがある（`case-12` と同じ判定）

### Phase 2: 動作

- 非対話モードのため確認できない。弱い一致は適用しない
- 認証情報を付けずに処理を続けるか、認証が必要なら失敗として報告する
- 「`eu.example.com` に一致しうる候補 `example-key` があるが、確認できないため適用しなかった」と通知する

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| `AskUserQuestion` | 発火しない |
| `example-key` | 付与しない |
| 通知 | 候補があったことと、適用しなかった理由 |

## 合否の基準

`example-key` を付与しないこと、適用しなかったことを通知すること。非対話であることを理由に弱い一致を採用したら不合格。

## 分岐の根拠

非対話モードは確認を省いて既定の動作で進むが、弱い一致での付与は確認を前提とする。強い一致が複数件のときは
最新の `updated_at` を採用する（`case-08`）のと対照的に、弱い一致は確認できなければ適用しない。
