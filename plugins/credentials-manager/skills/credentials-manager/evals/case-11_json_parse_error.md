# Case 11: 既存 credentials.json の JSON パース失敗

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | "認証情報を一覧表示して。" |
| 引数 | なし |
| フラグ | なし |
| 既存状態 | `credentials.json` が破損（不正 JSON）。例: `{"credentials": {`（途中で切れている） |

## 期待動作

### Phase 1: パス解決と読み込み試行

- 解決パスから `credentials.json` を読み込み
- JSON パースエラーを検出

### Phase 2: バックアップ作成

- 破損ファイルを `credentials.json.bak.{ISO8601タイムスタンプ}` にリネーム or コピー
- ユーザに「`credentials.json` が破損しています。バックアップを `<bak-path>` に保存し、空ストアで再初期化します」と通知

### Phase 3: 空ストア再初期化

- `credentials.json` を `{"credentials": {}}` で書き戻し
- 後続の操作（一覧表示）を空状態で続行

### Phase 4: 一覧表示

- 「保存済み認証情報はありません」と表示し、必要なら救済手順（バックアップ参照案内）を併記

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| 生成ファイル | `credentials.json`（空ストア） + `credentials.json.bak.{timestamp}`（バックアップ） |
| 標準出力（要約） | 破損通知 + バックアップパス + 空ストア再初期化の旨 + 「保存済みなし」一覧 |
| 終了状態 | 成功（破損リカバリ後） |

## 分岐の根拠

このケースは「既知エラー系（JSON パース失敗）」分岐に該当する（`references/operations.md` セクション 8 参照）。データ消失防止のためバックアップ → 再初期化の順序が必須。
