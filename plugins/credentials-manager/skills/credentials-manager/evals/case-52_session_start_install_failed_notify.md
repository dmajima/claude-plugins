# Case 52: SessionStart hook — ルールを配置できない → 配置できなかったことを通知

## 入力

| 項目 | 値 |
|-----|---|
| トリガー | Claude Code セッション開始 |
| 既存状態 例 1 | 配置先の `.claude` がファイルで、`.claude/rules/security/` を作れない |
| 既存状態 例 2 | 配置先へのコピーが失敗する（書き込み権限が無い等） |
| フラグ | なし |

## 期待動作

### Phase 1: 自己診断・スコープ判定

- 前提（`jq`・`bash` 4 以上・`lib/` の共通定義）を確かめ、スコープから配置先を決める（`case-14`・`15` と同じ）

### Phase 2: ルールの配置

- `mkdir -p` か `cp` が失敗する

### Phase 3: 出力

- `[credentials-manager] ルール 'credentials-management.md' を <配置先> に配置できませんでした（…）。権限とパスを確認するよう、ユーザーに案内してください。` を
  `additionalContext` に入れて出力する（自己診断の通知文がある場合は先頭に添える。`jq` が無い場合は平文）
- 終了コード 0（Claude Code を止めない）

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| Hook stdout | 上記の通知文を含む JSON |
| 配置 | なし |
| 終了コード | 0 |
| Claude のコンテキスト | ルールを配置できなかったこと、ユーザに伝えて権限とパスの確認を案内すること |

## 分岐の根拠

配置に失敗したまま何も出さないと、ルールが無いことに気付けない（検出フックが動かない環境では、ルールが唯一の念押しになる）。
失敗してもセッションは止めない（フェイルオープン）。
