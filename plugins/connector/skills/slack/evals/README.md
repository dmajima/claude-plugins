# Evals: slack

このディレクトリは `slack` スキルの動作分岐の期待挙動を例示する。

## ケース一覧

| ケース | 内容 | 主な分岐根拠 |
|-------|-----|-------------|
| case-01 | チャンネル検索（MCP ツール経由でチャンネル一覧取得 → 結果整形報告） | 正常系 — 読み取り操作 |
| case-02 | メッセージ検索（キーワード指定 → slack_search_public で検索 → 結果報告） | 正常系 — 検索操作 |
| case-03 | メッセージ送信（送信内容確認 → 承認 UI → slack_send_message → 送信完了報告） | 正常系 — 書き込み操作（承認必須） |
| case-04 | スレッド読取（チャンネル + スレッド ts 指定 → slack_read_thread → スレッド内容報告） | 正常系 — 読み取り操作 |
| case-05 | メッセージ送信の承認でユーザーが「中止」を選択（送信を発行せず終了） | 異常系 — AskUserQuestion の選択 = 中止 |
| case-06 | Slack MCP サーバー未接続（MCP ツール利用不可 → フォールバック案内） | エラー系 — MCP 利用不可 |
| case-07 | プライベートチャンネル検索の同意確認（slack_search_public_and_private 使用前に確認） | 正常系 — プライバシー確認分岐 |

## 実行確認方法

各ケースの「入力」セクションのフレーズで Claude Code を起動し、「期待動作」「期待出力」と一致することを目視確認する。

- 各ケースは MCP ツール（mcp__claude_ai_Slack__*）への実アクセスを前提とするため、`run_evals.py` による自動実行の対象外とする（runnable フロントマターなし）
- 書き込み系ケース（case-03）の確認は、検証用チャンネルに対して行うこと
- AskUserQuestion の実発火・承認 UX は機械検証の射程外のため、人間レビューで確認する
