# Case 08: 課題取得で HTTP 401（同一キーでリトライせず再取得を確認）

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | "PROJ-123 を取得して"（スペースは過去の会話・課題 URL から `example.backlog.jp` と特定できる） |
| 引数 | 課題キー `PROJ-123` |
| フラグ | なし（対話モード） |
| 既存状態 | `~/.claude/credentials.json` に `domains` に `example.backlog.jp` を含むエントリ（`value` 非空）が存在するが、登録済みの API キーは Backlog 側で失効している |

## 期待動作

### Phase 1: 認証事前確認（成功）

- 対象スペースのホストを `example.backlog.jp` に確定し、credentials.json の `domains` 照合で一致エントリの `value` が非空であることを確認する
- 事前確認はエントリと値の存在のみを検査するため、キーの失効はこの時点では検出されない

### Phase 2: 操作種別判定

- 「課題取得」を **読み取り** と判定し、SKILL.md Step 3（読み取り系の実行）へ進む

### Phase 3: API 呼び出しと HTTP 401 受領

- `GET /api/v2/issues/PROJ-123` を `curl --max-time 30 -o "$RESP" -w '%{http_code}'` で呼び出す（apiKey は `--config` ファイル経由）
- HTTP ステータス **401** を受領する

### Phase 4: 同一キーでの即停止と再取得の確認

- safe-api-access.md セクション 5 の分岐表に従い、**同一認証情報でのリトライを 1 回も行わず即停止** する（401 / 403 は同一値でのリトライ厳禁）
- 後続の API（コメント取得等）も発行しない
- 「認証エラー（HTTP 401）。登録済み API キーが失効している可能性がある」と報告し、credentials-precheck.md セクション 4 の対話取得フォールバックで再取得を確認する（API キーの再発行は Backlog の個人設定 > API）
  - ユーザーが新しいキーを提供した場合のみ **1 回だけ** 再実行する（保存選択時は credentials.json のエントリを更新）
  - 中止選択時は API を追加発行せず終了する
- API キーのフル値・`apiKey=` 付き URL は会話出力しない（マスクして扱う）
- 一時ファイル（curl config・レスポンス）は trap で削除する
- サブエージェント実行時（`AskUserQuestion` 利用不可）は再取得確認を試みず `auth_failed` マニフェストを返す（subagent-protocol.md セクション 3.3 / 3.5。専用ケース: `case-17_subagent_auth_failed.md`）

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| 生成ファイル | 「保存する」選択時のみ credentials.json のエントリ更新。それ以外はなし（一時ファイルは処理終了時に削除済み） |
| 標準出力（要約） | 「認証エラー（HTTP 401）」の報告 + キー再発行・再取得の選択肢提示 →（新キー受領時）再実行結果 |
| 終了状態 | 新キー受領時: 1 回だけ再実行 / 中止時: 401 受領後の追加 API リクエスト発行数 0 で終了 |

## 分岐の根拠

このケースが分岐するトリガーは HTTP ステータス = 401 である（safe-api-access.md セクション 5: 401 / 403 は同一認証情報でのリトライ厳禁・即停止、新しい値を受領した場合のみ 1 回だけ再実行可）。case-01 と同じ読み取り経路だが、2xx ではなく 401 を受領するため、整形報告に進まず同一キーでのリトライなしで再取得確認に移る。
