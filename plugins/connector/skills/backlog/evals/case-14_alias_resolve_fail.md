# Case 14: エイリアス解決失敗（ダイレクトパス URL 依頼）

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | "このリンクのファイルを見せて https://example.backlog.jp/alias/file/9999999" |
| 引数 | エイリアス URL（存在しない ID） |
| フラグ | なし（対話モード） |
| 既存状態 | `~/.claude/credentials.json` に `domains` に `example.backlog.jp` を含む API キーエントリが存在する。プロジェクトキー `PROJ` は会話文脈から既知 |

## 期待動作

### Phase 1: 認証事前確認

- URL からスペースホストを `example.backlog.jp` に確定する
- credentials.json で API キーの存在を確認する

### Phase 2: 操作種別判定

- URL パスに `/alias/file/` を含むため **共有ファイル操作**（読み取り）と判定する

### Phase 3: エイリアス解決試行

- プロジェクトキー `PROJ` を取得する
- download API を試行: `GET /api/v2/projects/PROJ/files/9999999` → 404（存在しない）
- フォルダとしてツリー走査を試行 → 該当 ID が見つからない

### Phase 4: 解決失敗の報告

- エイリアス URL の解決に失敗した旨を報告する
- `AskUserQuestion` で以下のいずれかを依頼する:
  - ダイレクトパス URL の提供
  - プロジェクトキー + ファイルパスの手動入力
  - ID やプロジェクトキーの確認

### Phase 5: ユーザー応答に応じた分岐

- ユーザーがダイレクトパス URL を提供 → パターン A の手順でパースし API 呼び出し
- ユーザーが中止 → 操作終了

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| 生成ファイル | なし |
| 標準出力（要約） | エイリアス解決失敗の報告と AskUserQuestion による代替情報の依頼 |
| 終了状態 | ユーザー応答待ち（または応答に基づく成功/終了） |

## 分岐の根拠

このケースが分岐するトリガーはエイリアス URL の解決が完全に失敗すること（download API 404 + ツリー走査で未検出）。case-11（ファイル解決成功）・case-13（フォルダ解決成功）とは解決結果で分岐する。
