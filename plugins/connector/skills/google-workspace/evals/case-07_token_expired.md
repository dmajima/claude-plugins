# case-07: フォールバックトークンの失効（401 — 同一値でリトライせず再取得を確認）

## 入力

```
Google Drive でファイルを検索したい
```

## 前提条件

- MCP ツール利用不可 → 「直接対応する」を選択済み
- credentials.json の `google-drive` エントリは存在するが、Bearer トークンが失効

## 期待される動作

### Phase 1: トークン解決と API 呼び出し
- credentials-precheck.md セクション 1 の解決順序でトークンを解決する（失効はこの時点では検出されない）
- `https://www.googleapis.com/drive/v3/files?q=...` を呼び出し、HTTP 401 を受領する

### Phase 2: 同一トークンでの即停止と再取得の確認
- safe-api-access.md セクション 5 に従い、**同一トークンでのリトライを 1 回も行わず停止** する
- credentials-precheck.md セクション 4 の対話取得フォールバックでトークンの再取得を提示する
  - **新しい値（前回送信値と異なることを確認した値）** を受領した場合のみ 1 回だけ再実行する（保存選択時はエントリ更新）
  - 中止選択時は API を追加発行せず終了する
- サブエージェント実行時は質問せず `auth_failed` マニフェストを返す（subagent-protocol.md セクション 3.3 / 3.5）

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| 生成ファイル | 「保存する」選択時のみ credentials.json のエントリ更新 |
| 標準出力（要約） | 「認証エラー（HTTP 401）」の報告 + トークン再取得の選択肢提示 →（新値受領時）再実行結果 |
| 終了状態 | 新値受領時: 1 回だけ再実行 / 中止時: 追加 API リクエスト 0 で終了 |

## 分岐根拠

HTTP ステータス = 401（safe-api-access.md セクション 5: 同一認証情報でのリトライ厳禁・新値受領時のみ 1 回再実行可）。OAuth2 Bearer トークンは短命のため、恒久利用には MCP 導入を推奨する。
