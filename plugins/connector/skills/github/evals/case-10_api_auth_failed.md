# Case 10: API 応答での 401/403（gh auth status は成功済み — 同一トークンでリトライせず再認証を確認）

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | "https://github.com/contoso/webapp/pull/42 のレビュースレッド一覧を取得して" |
| 既存状態 | `gh auth status` は終了コード 0（認証済み表示）だが、トークンが GitHub 側で失効・revoke 済み（または対象リポジトリへの scope 不足） |

## 期待動作

### Phase 1: 認証確認（成功）と API 呼び出し

- Step 1 の `gh auth status` は成功する（失効はこの時点では検出されない）
- `gh api` でスレッド一覧を取得しようとして HTTP **401**（または 403）を受領する

### Phase 2: 同一トークンでの即停止と再認証の確認

- safe-api-access.md セクション 5 に従い、**同一トークンでのリトライを 1 回も行わず停止** する
- `gh auth login` の再実行（トークンの再発行）または `GH_TOKEN` / `GITHUB_TOKEN` の再設定をユーザーに案内する（トークン値の代理受領はしない）
- ユーザーの再認証完了後に `gh auth status` を再確認し、**1 回だけ** 元の操作を再実行する
- 中止指示があった場合は API を追加発行せず終了する
- サブエージェント実行時（`AskUserQuestion` 利用不可）は案内せず `auth_failed` マニフェスト（`service: "github"`）を返す（subagent-protocol.md セクション 3.3 / 3.5）

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| 生成ファイル | なし |
| 標準出力（要約） | 「認証エラー（HTTP 401/403）。トークンが失効している可能性がある」+ 再認証手順の案内 →（再認証後）スレッド一覧 |
| 終了状態 | 再認証後: 1 回だけ再実行して完遂 / 中止時: 401 受領後の追加 API リクエスト 0 で終了 |

## 分岐の根拠

HTTP ステータス = 401/403（safe-api-access.md セクション 5: 同一認証情報でのリトライ厳禁）。case-04 は事前チェック（`gh auth status`）段階の未認証を扱うのに対し、本ケースは事前チェック通過後の API 応答段階での認証失敗を扱う。GitHub 認証は `gh` CLI 管理のため「新しい値」の受領は credentials.json ではなく再認証（`gh auth login` / 環境変数再設定）で行う。
