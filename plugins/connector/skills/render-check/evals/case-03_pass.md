# Case 03: Backlog Markdown で全カテゴリ検出なし（PASS）

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | "この内容で Backlog の課題 PROJ-34 にコメントして"（`backlog` スキルへの発話。render-check はその内部ゲートとして起動） |
| 起動経路 | `backlog` スキルの書き込み操作直前の必須ゲート呼び出し |
| 引数 | 本文（下記）+ ターゲット `backlog-markdown` |
| フラグ | なし |
| 既存状態 | 投稿先プロジェクトの `textFormattingRule` は `markdown` と API で判定済み（呼び出し元が引き継ぐ） |

### チェック対象本文（行番号は先頭行を 1 行目として数える）

````text
## 対応内容

- ログ出力処理を `logger.info` に統一
- 詳細は下記コードを参照

```java
logger.info("completed");
```
````

## 期待動作

### Phase 1: 入力確定
- 本文とターゲット `backlog-markdown` を呼び出し元から受領する（ターゲット確認の AskUserQuestion は発火しない）

### Phase 2: チェック実行
- 前処理: フェンス行が 6 行目と 8 行目の 2 個（偶数ペア）→ 6〜8 行目をコード領域、それ以外を地の文に分割する。3 行目の `logger.info` はインラインコードのためコード領域扱い
- NOTATION: backlog-markdown.md セクション 3 の Backlog 記法混入パターン（`{code}` / `''太字''` / `[[リンク>URL]]` / `&color` / 行頭 `* ` / 行末 `|h`）→ 検出なし = PASS
- AUTOLINK: 地の文に課題キー形式（`[A-Z][A-Z0-9_]*-[0-9]+`）・`@ニックネーム`・裸の URL なし → PASS
- STRUCTURE: フェンス偶数ペアで閉じている・表ブロックなし → PASS
- SIZE: 8,000 文字以下 → PASS
- SECRET: 確定的パターン・ヒューリスティックパターンいずれも検出なし → PASS
- 5 カテゴリ全てを省略せず実施する（短文・問題なしの見込みでもスキップしない）

### Phase 3: 結果レポートとプレビュー
- 5 カテゴリ全て PASS の表 + 総合判定 PASS を提示する
- 投稿プレビュー: 本文をコードブロックで提示し、`## 対応内容` が見出し 2、`- ` 行がリスト、フェンス部がコードブロックとして表示され、通知・意図しないリンク化が発生しないことを注記する

### Phase 4: 引き渡し
- 修正提案・採用確認の AskUserQuestion は発火しない（FAIL / WARN が 0 件のため）
- `backlog` スキルへ総合判定 PASS と本文（無修正）を返す（投稿処理は `backlog` スキルが実施する）

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| 生成ファイル | なし（render-check はファイルを生成しない） |
| 標準出力（要約） | 5 カテゴリ全 PASS の表 + 総合判定 PASS + 投稿プレビュー（レンダリング後の見え方の説明付き） |
| 終了状態 | 成功（PASS + 無修正本文を `backlog` スキルへ引き渡し・投稿続行） |

## 分岐の根拠

このケースが分岐するトリガーは 5 カテゴリ全ての検出件数 = 0 件である。FAIL / WARN が 1 件もないため、修正提案（Phase 4 相当）とユーザー選択を経由せずに PASS を返す経路に入る。
