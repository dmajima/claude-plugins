# Case 02: ADO Markdown の地の文でのメンション・作業項目リンク暴発（AUTOLINK WARN → このまま投稿）

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | "この内容で PR 456 のレビューコメントに返信して"（`azure` スキルへの発話。render-check はその内部ゲートとして起動） |
| 起動経路 | `azure` スキルの書き込み操作直前の必須ゲート呼び出し |
| 引数 | 本文（下記）+ ターゲット `ado-markdown`（PR コメント） |
| フラグ | なし |
| 既存状態 | 投稿先は Azure DevOps の PR コメントスレッド |

### チェック対象本文（行番号は先頭行を 1 行目として数える）

````text
@yamada レビューありがとうございます。指摘どおり修正しました。

この修正は #123 の対応に含めます。
````

## 期待動作

### Phase 1: 入力確定
- 本文とターゲット `ado-markdown` を呼び出し元から受領する（ターゲット確認の AskUserQuestion は発火しない）

### Phase 2: チェック実行
- 前処理: コードフェンスが存在しないため本文全体を地の文として扱う
- AUTOLINK: azure-devops-markdown.md セクション 3・4 の表を地の文に適用し 2 件を検出する
  - 1 行目: 行頭の `@yamada` → メンション。**対象ユーザー（yamada と思われる）に通知が飛ぶ** ことを明示して WARN
  - 3 行目: 空白に続く `#123` → 作業項目 123 への自動リンク化。意図的なリンクの可能性があるため WARN とし、「意図したリンクか」を確認対象にする
- NOTATION / STRUCTURE / SECRET / SIZE: 検出なし

### Phase 3: 結果レポート
- AUTOLINK WARN 2 件の表（行番号付き）+ 総合判定 WARN（FAIL なし・WARN あり）を提示する
- 投稿プレビューで `@yamada` の通知発生箇所と `#123` のリンク化箇所を注記する

### Phase 4: ユーザー選択
- WARN のみのため AskUserQuestion で「このまま投稿」/「修正する」を提示する
  - 「修正する」を選んだ場合の抑止案も併記する: `@yamada` をインラインコード化（通知抑止）/ `\#123` にエスケープ（リンク抑止）
- ユーザーが「このまま投稿」を選択する

### Phase 5: 引き渡し
- 本文は無修正のまま、総合判定 WARN を `azure` スキルへ返す（FAIL ではないため投稿続行可。投稿処理は `azure` スキルが実施する）
- FAIL への格上げ・投稿の強制ブロックは行わない

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| 生成ファイル | なし（render-check はファイルを生成しない） |
| 標準出力（要約） | AUTOLINK WARN 2 件の表（メンションは通知が飛ぶ旨を明示）+ 総合判定 WARN + ユーザー選択結果（このまま投稿） |
| 終了状態 | 成功（WARN + 無修正本文を `azure` スキルへ引き渡し・投稿続行） |

## 分岐の根拠

このケースが分岐するトリガーは AUTOLINK 検査の検出結果 = 検出あり（地の文に裸の `@yamada` と `#123`）かつ FAIL 該当カテゴリ = 0 件である。AUTOLINK は WARN 止まりのため投稿ブロックにならず、「このまま投稿 / 修正する」のユーザー選択分岐に入る（FAIL 時にはこの選択肢は存在しない）。
