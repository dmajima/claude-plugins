# Case 04: ログ引用内の Bearer トークン検出（SECRET FAIL → マスク報告 → 投稿中止）

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | "この調査ログを Backlog の課題 PROJ-56 にコメントで共有して"（`backlog` スキルへの発話。render-check はその内部ゲートとして起動） |
| 起動経路 | `backlog` スキルの書き込み操作直前の必須ゲート呼び出し |
| 引数 | 本文（下記）+ ターゲット `backlog-notation` |
| フラグ | なし |
| 既存状態 | 投稿先プロジェクトの `textFormattingRule` は `backlog` と API で判定済み |

### チェック対象本文（行番号は先頭行を 1 行目として数える。トークンはダミー値）

````text
障害調査のためアクセスログを共有します。

{code}
2026-06-10 12:34:56 INFO request header: Authorization: Bearer dummy1234abcd5678efgh
{/code}

本日 12 時台のリクエストで発生しています。
````

## 期待動作

### Phase 1: 入力確定
- 本文とターゲット `backlog-notation` を呼び出し元から受領する

### Phase 2: チェック実行
- 前処理: 3 行目 `{code}` 〜 5 行目 `{/code}` をコード領域、それ以外を地の文に分割する
- SECRET: 本文 **全体（コード領域含む）** に確定的パターンを適用し、4 行目で `Bearer\s+[A-Za-z0-9._~+/=-]{16,}`（Bearer Token）に一致する値を検出する = FAIL
- NOTATION / AUTOLINK / STRUCTURE / SIZE: 検出なし（`{code}` ペアは閉じている・地の文に自動リンク要素なし）

### Phase 3: 結果レポート（マスク必須）
- 検出値（`Bearer` に続くトークン値）を先頭 4 文字 + `***` + 末尾 4 文字でマスクし、`dumm***efgh` として報告する。フル値をレポート・会話出力・プレビューに転記しない
- カテゴリ表に「SECRET / FAIL / Bearer トークン（`dumm***efgh`）がコードブロック内に含まれる / 4 行目」を提示する
- 総合判定 FAIL（投稿不可）を明示する

### Phase 4: 修正提案と採用確認
- マスク済み本文の修正案を提示する: 4 行目の `Authorization:` ヘッダ値全体を `Authorization: ****`（伏字）に置換した本文（修正案の提示時点でもフル値は表示しない）
- AskUserQuestion で確認する（選択肢: 「マスク済み修正案を採用して再チェック」/「投稿を中止」。**「FAIL のまま投稿」は提示しない**）
- ユーザーが「投稿を中止」を選択する

### Phase 5: 引き渡し
- `backlog` スキルへ総合判定 FAIL（投稿中止）を返す
- `backlog` スキルは投稿 API を呼ばず、コメントは投稿されない
- FAIL を含む本文を「投稿可」として返さない

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| 生成ファイル | なし（render-check はファイルを生成しない） |
| 標準出力（要約） | SECRET FAIL 1 件の表（検出値は `dumm***efgh` にマスク・4 行目）+ 総合判定 FAIL + マスク済み修正案 + 中止の確認結果 |
| 終了状態 | 投稿中止（FAIL 確定。`backlog` スキルは書き込みを実行しない） |

## 分岐の根拠

このケースが分岐するトリガーは SECRET 検査の確定的パターン一致 = あり（4 行目の Bearer トークン形式）である。確定的パターンは FAIL（投稿ブロック・マスク必須）のため、ユーザーに提示される選択肢は「修正採用」か「中止」のみとなり、WARN 時に存在する「このまま投稿」の分岐が現れない。
