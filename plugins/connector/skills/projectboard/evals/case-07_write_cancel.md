# Case 07: 書き込み承認で「中止」を選択（POST 未発行）

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | "ProjectBoard の SAMPLE-67 のステータスを完了にして"（→ 承認画面でユーザーが中止を選択） |
| 引数 | タスク ID + 変更フィールド |
| フラグ | なし（対話モード） |
| 既存状態 | credentials.json に `hue-projectboard` エントリあり。SAMPLE-67 が存在 |

## 期待動作

### Phase 1-4: 認証事前確認 〜 現状取得・ID 解決
- case-04 と同様に進む（ログイン → 対象ノード特定 → ステータス名を statusSet の id に解決）

### Phase 5: 承認（ユーザーが中止）
- 変更内容（ステータス: 未開始 → 完了）を変更前 → 変更後で提示し、`AskUserQuestion` で承認を求める
- ユーザーが「中止」を選択する

### Phase 6: 中止処理
- **`post_node_api.sh` を呼び出さない**（updateNodeContent は発行されない）
- 書き込みボディ（pb_body.json）を構築済みであっても送信しない
- ProjectBoard 側のタスクは一切変更されない

### Phase 7: 後始末・報告
- `cleanup_sensitive.sh` で cookies.txt・取得 JSON・構築済みボディを削除する
- 「中止した（変更は行われていない）」旨を明確に報告し、必要なら変更内容の修正を促す

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| 生成ファイル | なし（ProjectBoard 側は無変更。ローカル機密ファイルは削除済み） |
| 標準出力（要約） | 変更前後の提示 → 承認質問 → 中止の確認報告（POST 未発行を明示） |
| 終了状態 | 中止（エラーではない正常終了） |

## 分岐の根拠

書き込みゲートの核心分岐。AskUserQuestion で承認が得られない限り `post_node_api.sh` は実行されず、
中止はエラーではなく正常な選択として扱う。承認なしの自動投稿禁止（SKILL.md 重要な制約）の実効性を
担保するケースであり、将来の変更で「承認スキップ」の回帰が起きていないかを確認する基準となる。
