# Case 06: セッション切れ（401 → 自動再ログイン → リトライ）

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | "さっきのシートのタスクをもう一度取得して"（同一セッション内の 2 回目以降の操作） |
| 引数 | 既に解決済みの tenant / projectId / sourceId |
| フラグ | なし（対話モード） |
| 既存状態 | `$WORK_DIR/cookies.txt` は存在するが、ProjectBoard 側の SESSION がタイムアウト済み（落とし穴 #9） |

## 期待動作

### Phase 1: 取得試行（401 発生）
- `get_tasks.sh` → `with_session.sh` が GET を実行し、HTTP 401 を受け取る

### Phase 2: 自動再ログイン（with_session.sh 内）
- `PB_EMAIL` / `PB_PASSWORD` 環境変数が設定済みのため、`login.sh` を自動実行する
- 旧 cookies.txt は削除され（セッション固定対策）、新しい SESSION が確立される
- パスワード・Cookie 値は標準出力・会話に出力されない

### Phase 3: リトライ（1 回のみ）
- 同じ GET を 1 回だけ再実行し、200 + JSON を取得する
- 再リトライでも 401 の場合はエラーとして停止し、認証情報の再確認を促す（無限リトライしない）

### Phase 4: 続行
- 取得結果の整形・報告へ通常どおり進む（ユーザーには再ログインが発生した旨を一言添える）

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| 生成ファイル | pb_wbsnodes.json（新セッションで取得） |
| 標準出力（要約） | 再ログイン発生の注記 + 通常の取得結果報告 |
| 終了状態 | 成功 |

## 分岐の根拠

401 セッション切れ + 再ログイン + 1 回リトライの責務は `with_session.sh` / `post_node_api.sh` に
集約されている（ADR-5）。`PB_EMAIL` / `PB_PASSWORD` が未設定の場合は自動再ログインせず
エラー停止する（環境変数が再ログインの opt-in として機能する）。
