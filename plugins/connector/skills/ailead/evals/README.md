# Evals: ailead

このディレクトリは `ailead` スキルの動作分岐の期待挙動を例示する。

## ケース一覧

| ケース | 内容 | 主な分岐根拠 |
|-------|-----|-------------|
| case-01 | 共有リンクからデータ取得成功（認証確認 → fetch_share.py → 文字起こし・要約・参加者・HLS URL 報告） | 正常系 — 共有リンク有効・データ取得成功 |
| case-02 | ハッシュ期限切れ（API が outdated ステータスを返却 → 再共有を案内して停止） | 異常系 — ハッシュ期限切れ |
| case-03 | 共有リンクの有効期限切れ（API が expired を返却 → 再共有を案内して停止） | 異常系 — リンク期限切れ |
| case-04 | ailead URL がユーザ入力に含まれない（URL 提供を依頼して停止） | エラー系 — 入力不足 |
| case-05 | 文字起こしデータが空（API 成功だが transcript が空配列 → 「文字起こしなし」を報告） | 異常系 — データ欠損 |
| case-06 | パスワード保護された共有リンク（認証エラー → パスワード確認を案内） | エラー系 — アクセス制限 |
| case-07 | ailead 以外の不正 URL（URL パターン不一致 → 非対応を案内して停止） | エラー系 — 入力不正 |
| case-08 | callSummary が null（AI要約未生成 → 正常系として処理続行、topicCount: 0） | 異常系 — データ欠損（部分成功） |
| case-09 | transcripts が時刻順でない（ソートして正規化 → 正常出力） | 異常系 — データ整合（自動補正） |
| case-10 | 全 known hash 失敗 + JS チャンク再抽出も失敗（operationHash 取得不能 → exit 1） | エラー系 — ハッシュ全滅 |

## 実行確認方法

各ケースの「入力」セクションのフレーズで Claude Code を起動し、「期待動作」「期待出力」と一致することを目視確認する。

- 各ケースは外部 API（ailead 共有リンク）への実アクセスを前提とするため、`run_evals.py` による自動実行の対象外とする（runnable フロントマターなし）
- 正常系ケース（case-01）の確認は、有効な共有リンクに対して行うこと
- エラー系ケースは意図的に不正な入力・期限切れリンクで確認する
