# Case 14: 登録済み TFS 資格情報の失効（401 — 同一値でリトライせず再取得を確認）

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | "https://tfs.example.local/tfs/DefaultCollection/WebApp/_git/webapp/pullrequest/12 の PR メタ情報を取得して" |
| 引数 | 登録済み TFS ホストの PR URL |
| フラグ | なし（対話モード） |
| 既存状態 | credentials.json の `tfs-password` エントリは存在し `domains` に `tfs.example.local` を含むが、パスワードが TFS 側で失効（変更済み） |

## 期待動作

### Phase 1: 認証事前確認（成功）とホスト判定

- 解決順序 1〜2 でエントリを解決する（値の失効はこの時点では検出されない）
- ホスト判定 = 判定 3（登録済み TFS）→ NTLM で API 呼び出しへ進む

### Phase 2: API 呼び出しと HTTP 401 受領

- `curl --ntlm --netrc-file` で PR 取得 API を呼び出し、HTTP **401** を受領する

### Phase 3: 同一資格情報での即停止と再取得の確認

- safe-api-access.md セクション 5 に従い、**同一資格情報でのリトライを 1 回も行わず即停止** する
- credentials-precheck.md セクション 4 の対話取得フォールバックで資格情報の再確認・再取得を提示する
  - **新しい値（前回送信値と異なることを確認した値）** を受領した場合のみ 1 回だけ再実行する（保存選択時はエントリ更新）
  - ユーザーが同一値を再入力した場合は再送しない
  - 中止選択時は API を追加発行せず終了する
- サブエージェント実行時は質問せず `auth_failed` マニフェストを返す（subagent-protocol.md セクション 3.3 / 3.5）

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| 生成ファイル | 「保存する」選択時のみ credentials.json のエントリ更新 |
| 標準出力（要約） | 「認証エラー（HTTP 401）」の報告 + 再取得の選択肢提示 →（新値受領時）再実行結果 |
| 終了状態 | 新値受領時: 1 回だけ再実行 / 中止時: 401 受領後の追加 API リクエスト 0 で終了 |

## 分岐の根拠

HTTP ステータス = 401（safe-api-access.md セクション 5: 同一認証情報でのリトライ厳禁・新しい値の受領時のみ 1 回再実行可）。Cookie セッション認証の例外（ProjectBoard のセッション再確立）とは異なり、NTLM の 401 は資格情報自体の失敗のため同一値での再送は行わない。
