# Case 13: ユーザー直接の PR 情報取得（パターン A・読み取り）

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | 「PR https://tfs.example.com/.../pullrequest/456 の情報を見せて」 |
| 引数 | PR URL |
| フラグ | なし |
| 既存状態 | credentials.json に `tfs-password` 登録済み。PR 456 は active |

## 期待動作

1. パターン A（ユーザー直接）と判別
2. 認証確認
3. PR メタ情報を API で取得
4. 取得結果の要点を **整形してユーザーに報告**（パターン B との違い）

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| 生成ファイル | なし |
| 標準出力（要約） | PR タイトル・作成者・ステータス・レビュアー情報を整形表示 |
| 終了状態 | 成功 |

## 分岐の根拠

パターン A の読み取り。パターン B（case-10）では透過返却、サブエージェント（case-11）ではファイル書き出しとなるのに対し、パターン A では整形報告する。
