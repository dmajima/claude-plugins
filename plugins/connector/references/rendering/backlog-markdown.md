# Backlog Markdown レンダリングルール（textFormattingRule = "markdown"）

Backlog のプロジェクト設定が **Markdown** の場合に適用されるレンダリングルールと、投稿前チェックで検出すべきパターン。

> プロジェクトの記法設定は `GET /api/v2/projects/{projectIdOrKey}` のレスポンス `textFormattingRule`（`"backlog"` / `"markdown"`）で判定する。推測で記法を決めてはならない。

## 1. サポートされる Markdown 構文

CommonMark ベース。以下は標準どおりレンダリングされる。

| 要素 | 構文 |
|------|------|
| 見出し | `# H1` 〜 `###### H6` |
| 箇条書き / 番号付き | `- 項目` / `1. 項目`（ネストはインデント） |
| 太字 / 斜体 / 打消し | `**太字**` / `*斜体*` / `~~打消し~~` |
| コードフェンス | バッククォート 3 つ（言語指定可） |
| インラインコード | バッククォート 1 つ |
| 引用 | `> テキスト` |
| 表 | `\| a \| b \|` + `\|---\|---\|` 区切り行 |
| リンク | `[テキスト](URL)` |

## 2. Backlog 固有の挙動（GitHub Flavored Markdown との差異）

| 項目 | Backlog Markdown の挙動 | リスク |
|------|------------------------|-------|
| 課題キー（`PROJ-123` 形式） | **コードフェンス外では自動リンク化** | ログ・識別子の偶然一致が課題リンク化 |
| `@ニックネーム` | メンション（**通知が飛ぶ**） | コード中の `@` 表記で意図しない通知 |
| HTML タグ | 原則エスケープ（`<details>` 等の GFM 拡張は期待しない） | GitHub 向け本文の流用時に素通し表示 |
| タスクリスト `- [ ]` | チェックボックス表示（クリック操作は不可の場合あり） | 進捗管理用途には課題のチェックリスト機能を推奨 |
| 改行 | 単一改行がそのまま `<br>` 扱い（GFM の soft break と異なる） | 文章の折返し位置が GitHub と変わる |

**保護方法**: コード・ログの引用は必ずコードフェンスまたはインラインコードで囲む。フェンス内では自動リンク・メンションが発火しない。

## 3. Backlog 記法混入の検出パターン（このターゲットでは記法不一致）

投稿本文に以下が含まれる場合、Markdown スペースでは装飾されず素通し表示される。

| 検出パターン（正規表現） | 混入している Backlog 記法 | 判定 |
|------------------------|--------------------------|------|
| `\{code(:[a-z0-9]+)?\}` / `\{/code\}` | Backlog コードブロック | FAIL |
| `\{quote\}` / `\{/quote\}` | Backlog 引用 | FAIL |
| `''[^']+''` | Backlog 太字 | FAIL |
| `\[\[[^\]]+>[^\]]+\]\]` | Backlog リンク | FAIL |
| `&color\([^)]*\)\{` | Backlog 文字色 | FAIL |
| `^\* `（行頭、見出し意図） | Backlog 見出し（Markdown ではリスト扱いに化ける） | WARN |
| 表の行末 `\|h` | Backlog 表ヘッダ指定 | WARN |

判定の意味は `render-check` スキルの判定区分（FAIL = 投稿ブロック / WARN = ユーザー判断）に従う。

## 4. 修正提案の変換表（render-check が提示する修正例）

| 検出した Backlog 記法 | Markdown への変換 |
|---------------------|-------------------|
| `** 見出し` | `## 見出し` |
| `{code:lang}` ... `{/code}` | ```` ```lang ... ``` ```` |
| `''太字''` | `**太字**` |
| `[[テキスト>URL]]` | `[テキスト](URL)` |
| `+ 項目` | `1. 項目` |
| 表ヘッダ行末尾の `h` | `h` を外し直下に `\|---\|` 区切り行を追加 |

## 5. その他の注意

- 文字数: コメント・課題本文が極端に長い場合（目安 8,000 文字超）は分割投稿を検討する（WARN）
- 画像参照は添付ファイルベース（外部画像 URL の直接埋め込みは情報漏洩リスクがあるため投稿前に除去を推奨）
