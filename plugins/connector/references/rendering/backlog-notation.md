# Backlog 記法レンダリングルール（textFormattingRule = "backlog"）

Backlog のプロジェクト設定が **Backlog 記法** の場合に適用されるレンダリングルールと、投稿前チェックで検出すべき記法不一致パターン。

> プロジェクトの記法設定は `GET /api/v2/projects/{projectIdOrKey}` のレスポンス `textFormattingRule`（`"backlog"` / `"markdown"`）で判定する。推測で記法を決めてはならない。

## 1. Backlog 記法の主要構文

| 要素 | Backlog 記法 | Markdown との違い |
|------|-------------|------------------|
| 見出し | `* 見出し1` / `** 見出し2` / `*** 見出し3` | `#` ではなく行頭 `*` + 半角スペース |
| 箇条書き | `- 項目`（ネストは `--` / `---`） | ネストをインデントでなくハイフン数で表す |
| 番号付きリスト | `+ 項目` | `1.` ではなく `+` |
| 太字 | `''テキスト''` | `**テキスト**` ではない |
| 斜体 | `'''テキスト'''` | `*テキスト*` ではない |
| 打消し線 | `%%テキスト%%` | `~~テキスト~~` ではない |
| 引用 | `>テキスト` または `{quote}...{/quote}` | `>` は共通で使用可 |
| コードブロック | `{code}` ... `{/code}`（言語指定は `{code:java}`） | バッククォートフェンスではない |
| インラインコード | なし（`{code}` ブロックのみ） | バッククォート単体は装飾されず素通し |
| 表 | `\| セル \| セル \|h`（末尾 `h` でヘッダ行） | `\|---\|` 区切り行は不要・あると崩れる |
| リンク | `[[テキスト>URL]]` / `[[URL]]` | `[テキスト](URL)` ではない |
| 文字色 | `&color(#ff0000){テキスト}` | Markdown に同等構文なし |
| 改行 | 入力した改行がそのまま反映 | 行末スペース 2 つは不要 |

## 2. 自動リンク・通知（投稿前に必ず確認）

| パターン | 挙動 | リスク |
|---------|------|-------|
| 課題キー（`[A-Z][A-Z0-9_]*-[0-9]+`、例 `PROJ-123`） | 課題への自動リンク化 | コード片・ログ中の偶然一致文字列が課題リンク化される |
| `@ニックネーム` | メンション（**対象ユーザーに通知が飛ぶ**） | コード中の `@` 表記（デコレータ・アノテーション等）で意図しない通知 |
| URL（`http://` / `https://`） | 自動リンク化 | 概ね無害。内部 URL の露出に注意 |

**保護方法**: コード・ログの引用は必ず `{code}` ... `{/code}` で囲む。`{code}` 内では自動リンク・メンションが発火しない。

## 3. Markdown 混入の検出パターン（このターゲットでは記法不一致）

投稿本文に以下が含まれる場合、Backlog 記法スペースではそのまま文字として表示される（レンダリングされない）。

| 検出パターン（正規表現） | 混入している Markdown 構文 | 判定 |
|------------------------|--------------------------|------|
| `^#{1,6} `（行頭） | Markdown 見出し | FAIL |
| ^ ``` （行頭バッククォート 3 つ） | コードフェンス | FAIL |
| `\*\*[^*]+\*\*` | Markdown 太字 | FAIL |
| `\[[^\]]+\]\([^)]+\)` | Markdown リンク | FAIL |
| `^\s*\|[\s:-]+\|`（行頭、`---` 区切り行） | Markdown 表の区切り行 | FAIL |
| `^- \[[ x]\] `（行頭） | タスクリスト | WARN（Backlog 記法に同等構文なし） |
| `~~[^~]+~~` | Markdown 打消し線 | WARN |

判定の意味は `render-check` スキルの判定区分（FAIL = 投稿ブロック / WARN = ユーザー判断）に従う。

## 4. 修正提案の変換表（render-check が提示する修正例）

| 検出した Markdown | Backlog 記法への変換 |
|------------------|---------------------|
| `## 見出し` | `** 見出し` |
| ```` ```lang ... ``` ```` | `{code:lang}` ... `{/code}` |
| `**太字**` | `''太字''` |
| `[テキスト](URL)` | `[[テキスト>URL]]` |
| `1. 項目` | `+ 項目` |
| 表の `\|---\|` 区切り行 | 区切り行を削除しヘッダ行末尾に `h` を付与 |

## 5. その他の注意

- 文字数: コメント・課題本文が極端に長い場合（目安 8,000 文字超）は分割投稿を検討する（WARN）
- 絵文字コード（`:smile:` 等）はスペース設定により挙動が異なるため多用しない
- HTML タグは Backlog 記法ではエスケープされ素通しになる（`<b>` 等は装飾されない）
