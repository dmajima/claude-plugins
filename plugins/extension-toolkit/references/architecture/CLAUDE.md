# architecture/

**アーキテクチャ決定記録（ADR）** を管理する。構造変更・新規ルール追加の根拠を記録する。

## ファイル一覧

| ファイル | ADR 範囲 | 内容 |
|---------|---------|------|
| [`decisions-001-010.md`](decisions-001-010.md) | ADR-001〜010 | 初期設計判断（参照集約・チーム・evals・フック等） |
| [`decisions-011-020.md`](decisions-011-020.md) | ADR-011〜020 | 中期判断（バージョニング・README・公開ワークフロー等） |
| [`decisions-021-033.md`](decisions-021-033.md) | ADR-021〜033 | 後期判断（フレッシュ起動・venv 統合・CLAUDE.md 等） |

## 利用ルール

- 構造規約の変更は **必ず先に ADR を追記** してからルールを変更する（ADR なしの変更は規約違反）
- ADR 番号は連番。欠番（削除済み ADR）の再利用は可
- 既存 ADR の変更時は最新の決定のみを記載し、変更前の内容は Git 履歴を参照する
- ファイルが 300 行を超えた場合は次の番号範囲ファイルに分割する
- ADR 間の相互参照（「ADR-024 で更新」等）は本文末尾の運用注記に集約する
