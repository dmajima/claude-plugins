# AI 誤認回避ライティング規約（SSOT）

`extension-toolkit` が生成・編集する全ての SKILL.md・references・コマンド本文・エージェント定義における記述規約。**人間の読みやすさよりも AI エージェントが誤認しないこと** を優先する。

## 1. 基本方針

| 原則 | 内容 |
|-----|------|
| 断定 | 「〜してください」より「〜する」「〜してはならない」 |
| 条件表 | 自然文より `条件 → 動作` の表形式 |
| 否定の明示 | 「以下を行わない」だけでなく「以下を行うこと」と「以下を行ってはならない」を併記 |
| 主語の明示 | 「これ」「それ」を避け、対象の固有名詞を毎回書く |
| 参照の絶対化 | 「上記の」より具体的なファイル名・セクション番号 |

## 2. 推奨される構造化表現

### 2.1 トリガー条件は箇条書きで網羅

```markdown
## トリガー条件

- 「{具体的フレーズ1}」
- 「{具体的フレーズ2}」
- {状況の英語記述}
```

### 2.2 責務は表形式で対比

```markdown
## 責務

- {責務1}
- {責務2}

## 責務外（他スキルが担当）

| 業務 | 担当スキル |
|-----|----------|
| {業務名} | `{担当スキル名}` |
```

### 2.3 条件分岐は `条件 → 動作` 表

```markdown
| 条件 | 動作 |
|-----|------|
| 入力に `--non-interactive` フラグあり | 確認をスキップしデフォルト値で進める |
| 入力に `--non-interactive` フラグなし | ユーザに確認する |
```

### 2.4 検証項目はチェックリスト

```markdown
- [ ] {検証項目1}
- [ ] {検証項目2}
```

## 3. 避けるべき表現

| 避ける | 理由 | 代替 |
|-------|------|------|
| 「適切に」「必要に応じて」 | 解釈が分かれる | 具体的な条件を明記する |
| 「上記」「下記」 | 文脈断絶時に解決不能 | セクション番号・ファイル名 |
| 「等」「など」 | 列挙不完全 | 完全列挙 or 「以下のいずれか」 |
| 「できれば」「望ましい」 | 必須/任意が不明 | 「必須」「推奨」「任意」 |
| 「通常は」 | 例外の扱いが不明 | 例外条件を明記 |

## 4. frontmatter の description

| 用途 | 文字数目安 | 内容 |
|-----|----------|------|
| プラグイン | 80 文字以内 | プラグインの目的を 1 文で |
| スキル | 制限なし | トリガーフレーズ + Use when + Skip when を網羅 |
| コマンド | 60 文字以内 | コマンドの効果を 1 文で |
| エージェント | 制限なし | 専門領域・起動条件を網羅 |

スキルの description は AI のトリガー判定に使われるため、**詳細・冗長で問題ない**。詳細は [description-guide.md](description-guide.md) を参照。

## 5. SKILL.md の必須セクション

```markdown
---
name: {kebab-case}
description: {トリガー条件を網羅した詳細説明}
---

# {Skill Title}

{1〜2 文の概要}

## 責務
## 責務外（他スキルが担当）
## トリガー条件
## 前提
## 実行フロー
### 1. {ステップ名}
### 2. ...
## 重要な制約
```

各セクションは省略不可（該当なしの場合は「なし」と明記）。

## 6. 実行フローの記述

| ルール | 内容 |
|-------|------|
| 番号付き | `### 1. ステップ名` 形式 |
| 入出力明示 | 各ステップの入力・出力・参照ファイルを明記 |
| 分岐あり | 条件表で分岐を表現 |
| 詳細手順 | `references/{name}.md` に分離し本文から参照 |
| references 参照 | 相対パス `[name](references/name.md)` |

## 7. 否定形の書き方

```markdown
## 重要な制約

- {対象} を {動作1} してはならない
- {対象} を {動作2} すること
- {対象} に対して {動作3} を行う前に必ず {前提条件} を確認すること
```

NG パターンと OK パターンを併記する:

```markdown
| 判定 | パターン | 例 |
|-----|---------|---|
| NG | {NG パターン} | `{NG 例}` |
| OK | {OK パターン} | `{OK 例}` |
```

## 8. 対話・非対話モードの記述

各スキルの「実行フロー」冒頭に以下を含める:

```markdown
### 実行モード判定

| 入力 | モード | 動作 |
|-----|-------|------|
| `--non-interactive` フラグあり / 引数で全パラメータ指定 | 非対話 | デフォルト値・引数値で確定し進行 |
| 上記以外 | 対話 | 不足パラメータをユーザに確認 |
```

## 9. references への分離基準

| 内容 | 配置 |
|-----|------|
| トリガー判定に必要 | `SKILL.md` 本文 |
| 実行時の判断基準 | `SKILL.md` 本文（200 行以内）or `references/rules.md` |
| 詳細手順 | `references/procedures.md` |
| 環境構築 | `references/setup.md` |
| 出力テンプレート | `references/template/` |
| 動作例 | `evals/` |

## 10. 禁止記号

`§`（U+00A7 セクション記号）の使用を全文書で禁止。代替表現:

| 用途 | 代替 |
|-----|------|
| 章番号 | `1. 概要` / `セクション1` / `第1章` |
| 節参照 | `2.1 を参照` / `セクション2.1 を参照` |
| 前項参照 | `前項` / `前セクション` |
