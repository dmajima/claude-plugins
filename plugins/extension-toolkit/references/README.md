# references/ ディレクトリ構成

`extension-toolkit` プラグイン横断の共通ナレッジ・ポリシー・テンプレート・スクリプトを集約するリソース領域。

## ディレクトリ構造

| ディレクトリ | 内容 | ファイル数目安 |
|------------|------|------------|
| `policies/` | ポリシー・制約ルール（命名・構造・配置・依存・ライセンス等） | 12+ |
| `guides/` | ガイド・設計指針（description 設計・evals 作成・エージェント活用等） | 6+ |
| `checklists/` | チェックリスト・検証ルール（完了チェック・検証ルール・レビュー鮮度） | 3+ |
| `procedures/` | 手順・業務フロー（移行ガイド・OK/NG 例集等） | 1+ |
| `architecture/` | ADR（アーキテクチャ決定記録、ADR 番号範囲で分割） | 3 |
| `templates/` | 推奨構成テンプレート（スキル・プラグイン・コマンド・エージェント等） | 17+ |
| `teams/` | エージェントチーム定義（レビューチーム編成） | 4 |
| `scripts/` | 実行スクリプト（venv 構築・フック・evals エンジン） | 8+ |

## サイズ閾値

| 閾値 | アクション |
|-----|----------|
| ~200 行 | 目安上限。超過時は分割を検討 |
| 300 行超 | 分割必須 |

## 分離原則

各ファイルは以下の種別のいずれか 1 つに特化する:

| 種別 | 配置先 | 内容 |
|-----|-------|------|
| ルール・制約 | `policies/` | 「何をしてはならないか」「何を守るべきか」 |
| ガイド・指針 | `guides/` | 「どう設計・記述すべきか」のベストプラクティス |
| チェックリスト | `checklists/` | 検証項目・確認リスト |
| 手順・フロー | `procedures/` | ステップバイステップの作業手順・例集 |
| テンプレート | `templates/` | コピーして使うひな形 |
| 設計判断 | `architecture/` | ADR（決定・理由・トレードオフ・代替案） |

ルールファイル内にテンプレート・チェックリスト・手順が混在する場合は、適切なファイルに分離する。

## 参照パスの記法

| 参照元 | 参照先 | パス記法 |
|-------|-------|---------|
| 同カテゴリ内 | 同カテゴリ | `filename.md` |
| 異なるカテゴリ | 別カテゴリ | `../category/filename.md` |
| SKILL.md から | references/ 配下 | `../../references/category/filename.md` |
| スキル references/ から | プラグイン references/ | 深さに応じた相対パス |
