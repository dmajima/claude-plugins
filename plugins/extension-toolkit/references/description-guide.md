# description 設計ガイド（SSOT）

スキル・コマンド・エージェント・プラグインの `description` フィールドの設計指針。

## 1. 用途別の方針

| 対象 | 主な読み手 | 方針 |
|-----|----------|------|
| プラグイン `plugin.json` | 人間（マーケットプレイス UI） | 端的に 1 文 |
| スキル `SKILL.md` frontmatter | AI（自動トリガー判定） | 詳細・網羅的に |
| コマンド `*.md` frontmatter | 人間（コマンド一覧） | 端的に 1 文 |
| エージェント `*.md` frontmatter | AI（呼び出し判定） | 詳細・網羅的に |

## 2. プラグインの description

| 制約 | 値 |
|-----|---|
| 文字数 | 80 文字以内 |
| 文体 | 体言止め可。「〜を支援するツールキット」「〜を自動化するプラグイン」等 |
| 含めるもの | 主要な目的 1 つ |
| 避けるもの | 機能リスト・トリガーフレーズ |

例:

```json
{
  "description": "Claude Code の各種拡張要素の作成からマーケットプレイス公開までを支援するツールキット"
}
```

## 3. スキルの description

スキルの description は AI が **自動トリガー判定** に使う。冗長な説明は判定ノイズになるため、**5W1H を中心に簡潔** に記述し、**最大 300 文字以内**（全角・半角ともに 1 文字 = 1 文字でカウント）に収める。

### 3.1 必須要素（5W1H）

| 要素 | 内容 | 必須 | 表現例 |
|-----|------|-----|-------|
| **What** | 何をするスキルか（動詞 + 対象成果物） | 必須 | 「〜を新規作成・改修するスキル」 |
| **Where** | どの対象ファイル/ディレクトリに対する操作か | 必須 | 「（`SKILL.md` + `references/` 一式）」「（`agents/{name}.md`）」 |
| **When** | いつ起動するか（日本語フレーズ例 + 英語 Use when 句） | 必須 | 「「〜を作って」「〜を更新」等の依頼で起動する。Use when the user wants to ...」 |
| **Why** | なぜ別スキルでなくこれか（責務外の明示） | 必須 | 「SKIP when target is X (use other-toolkit), Y (use ...)」 |
| **How** | 動作形態（処理が特殊な場合のみ） | 任意 | 「オーケストレータとして対象プラグインの〜を起動」 |
| **Who** | AI 自動トリガー判定（暗黙のため記述不要） | 不要 | — |

### 3.2 推奨順序とテンプレート

```markdown
description: {What+Where 1 文}。「{日本語フレーズ例1}」「{例2}」「{例3}」等の依頼で起動する。Use when {英語 When 句}. SKIP when {責務外 Why 句} (use {他スキル名}).
```

- 順序は **What+Where → When（日本語）→ When（英語）→ Why** を基本とする
- How は省略可。ただし「オーケストレータ」「並列起動」など動作形態の特殊性が AI 判定に必要な場合のみ加える
- 主語は明示する（「Claude Code のスキル」「Claude Code のサブエージェント」など）

### 3.3 文字数制約

| 制約 | 値 |
|-----|---|
| 上限 | **300 文字**（必ず順守） |
| 下限の目安 | 150 文字（短すぎるとトリガー精度低下） |
| 改行 | 禁止（YAML frontmatter の単一行文字列） |
| カウント方法 | 全角・半角・記号・空白を含めた純粋な文字数（surrogate pair は 1 文字として扱う） |

300 字を超える場合は以下の順で削減:

1. 装飾的な形容詞（「網羅的に」「効率的に」等）を削除
2. 例示の過剰提示を削減（フレーズ例 3 〜 4 個に圧縮）
3. ADR 番号や副次仕様を削除（本文や ADR 索引で参照）
4. Where を「対象ファイル名のみ」に短縮
5. 動作形態（How）が必須でなければ削除

### 3.4 例

#### 良い例（5W1H 網羅・約 250 字）

```markdown
description: Claude Code のスキル（SKILL.md・references・evals 一式）を新規作成・改修するスキル。「新しいスキル foo を作って」「skill foo を更新」「○○用のスキルが欲しい」等の依頼で起動する。Use when the user wants to create or modify a Claude Code skill. SKIP when the target is a plugin shell (plugin-toolkit), command (command-toolkit), agent (agent-toolkit), or hook (hook-toolkit).
```

含まれる要素:
- What: スキルを新規作成・改修
- Where: `SKILL.md` + `references/` + `evals/` 一式
- When: 日本語フレーズ 3 例 + Use when 句
- Why: SKIP when + 4 つの代替スキル

#### 悪い例（300 字超過・装飾過多）

```markdown
description: Claude Code のスキル一式（SKILL.md と references と evals の各種ファイル）を新規作成・既存改修・リファクタリング・機能追加するための包括的かつ網羅的なスキル。... （以下省略）
```

問題: 「包括的」「網羅的」が冗長、対象列挙が冗長、フレーズ例が抽象的。

### 3.5 アンチパターン

| パターン | 問題 | 改善 |
|---------|------|------|
| 300 文字超過 | トリガー判定ノイズ・SSOT 違反 | 装飾語・副次仕様を削除 |
| 短すぎる（150 文字未満） | トリガー精度低下 | 5W1H 各要素を最低限カバー |
| Where（対象成果物）の不在 | 別の対象（例: コマンドかスキルか）と誤判定 | `agents/{name}.md` 等の対象を明示 |
| What と When のみで Why 不在 | 別スキルとの責務境界が不明・重複起動 | SKIP when + 他スキル名を必ず付ける |
| ADR 番号や内部用語の羅列 | AI 判定に寄与しない | 本文・ADR 索引へ移動 |
| トリガーフレーズが抽象的 | 関連性のない場面で誤起動 | 想定ユーザ発話を 3 例以上具体化 |

## 4. コマンドの description

| 制約 | 値 |
|-----|---|
| 文字数 | 60 文字以内 |
| 文体 | 体言止め可 |
| 含めるもの | コマンドの効果 1 つ |
| 避けるもの | 引数仕様（`argument-hint` に書く） |

例:

```markdown
---
description: 拡張要素（スキル/プラグイン/コマンド/エージェント/フック）の作成・公開を支援
argument-hint: <種別> <対象名> [--non-interactive] [--full-auto]
---
```

### 4.1 `argument-hint` 必須化（ADR-023）

引数を受け取るコマンド（本文に `$ARGUMENTS` を含む、または引数ベースのルーティング表を持つ）は、frontmatter に `argument-hint` を **必ず記載** する。`/` 補完 UI に表示される SSOT であり、利用者がコマンド利用時に最初に見る引数仕様である。

| 制約 | 値 |
|-----|---|
| 必須/任意 | 引数を受け取るコマンドは **必須**。引数なしのコマンドは省略可 |
| 文字数 | 60 文字以内（目安） |
| 改行 | 禁止（YAML の単一行文字列） |
| 必須引数の表記 | `<引数名>` |
| 省略可引数の表記 | `[引数名]` |
| フラグの表記 | `[--flag 値]`（値あり）または `[--flag]`（値なし） |
| 重複禁止 | `description` 内で同じ引数仕様を繰り返さない（SSOT 違反） |

#### 4.1.1 推奨例

| 用途 | argument-hint 例 |
|-----|-----------------|
| 入出力ファイルパス | `<入力MDパス> [出力HTMLパス] [--title タイトル]` |
| オーケストレータ | `<種別> <対象名> [--non-interactive] [--full-auto]` |
| 単機能（必須引数のみ） | `<対象パス>` |
| 単機能（フラグのみ） | `[--dry-run]` |

#### 4.1.2 アンチパターン

| パターン | 問題 | 改善 |
|---------|------|------|
| `argument-hint: 引数を入力してください` | 補完で具体的に何を入れるか分からない | 必須引数を `<...>` で明示 |
| `argument-hint` 不在 + 本文の `$ARGUMENTS` 利用 | `/` 補完で引数の存在に気付けない | frontmatter に追加 |
| `description` に引数仕様を併記 | SSOT 違反・60 文字制限を圧迫 | `argument-hint` に集約 |
| `argument-hint: [--dry-run] ...`（クォートなし） | YAML が `[...]` をフローシーケンスとして解析失敗 | 値全体をダブルクォートで囲む（次節参照） |

#### 4.1.3 YAML エスケープ規則（必須）

`argument-hint` の値が **YAML 特殊文字で始まる** 場合、ダブルクォートで囲まないと YAML パースエラーになる（GitHub プレビューや `frontmatter valid` 機械チェックで失敗）。

| 値の先頭文字 | クォート要否 | 例 |
|-----------|----------|---|
| `<`（必須引数開始） | 不要 | `argument-hint: <入力ファイル> [--flag]` |
| `[`（省略可引数 / フラグ開始） | **必須** | `argument-hint: "[--dry-run] [--scope user]"` |
| `{` `&` `*` `?` `!` `\|` `>` `%` `@` `` ` `` で始まる | **必須** | `argument-hint: "{...}"` 等 |

YAML 仕様上、行頭の `[` はフローシーケンス（配列）の開始記号として解釈される。
値中に `|`（OR 区切り）や `:` を含む場合もクォート推奨。

```yaml
# NG: YAML パースエラー（[...] が配列リテラルとして解釈される）
argument-hint: [--dry-run] [--scope user|project|local|all]

# OK: 値全体をダブルクォートで囲む
argument-hint: "[--dry-run] [--scope user|project|local|all]"
```

検証は `frontmatter valid`（[`validation-rules.md`](validation-rules.md) 節 1）で機械的に検出される。
PR レビュー時には GitHub の Markdown プレビューで `Error in user YAML` が出ていないかを確認すること。

## 5. エージェントの description

スキル同様 AI のトリガー判定に使われる。以下を含める。

| 要素 | 内容 |
|-----|------|
| 専門領域 | エージェントの専門性 |
| 評価観点 | レビュー時に何を見るか |
| 起動条件 | いつ呼び出されるか |

例:

```markdown
---
name: code-reviewer
description: コード品質・正確性・パフォーマンスを評価する実装エンジニア。コード生成・リファクタリング・コードレビュー時に使用する。
---
```

## 6. description 検証チェックリスト

### 6.1 スキル description（5W1H）

スキル作成後に以下を確認:

- [ ] **What**: 何をするスキルかが 1 文で示されている
- [ ] **Where**: 対象成果物（ファイル/ディレクトリ）が明示されている
- [ ] **When（日本語）**: 想定ユーザ発話が 3 例以上具体的に列挙されている
- [ ] **When（英語）**: `Use when ...` 句が含まれている
- [ ] **Why**: `SKIP when ...` と関連スキル名が明示されている
- [ ] **文字数**: 300 文字以内（必須）
- [ ] **改行**: 含まれていない（YAML 単一行）
- [ ] 抽象語（「包括的」「網羅的」「効率的」等）の装飾なし
- [ ] ADR 番号・内部用語の羅列なし

### 6.2 エージェント description

- [ ] 専門領域が明示されている
- [ ] 評価観点（何を見るか）が含まれる
- [ ] 起動条件（いつ呼ばれるか）が含まれる

### 6.3 プラグイン description

- [ ] 80 文字以内
- [ ] 主目的 1 つに焦点
- [ ] 機能リストではなく目的記述

### 6.4 コマンド description

- [ ] 60 文字以内
- [ ] 引数仕様を含まない
- [ ] 効果 1 つに焦点

## 7. 共通の禁止事項

- 改行（YAML frontmatter の文字列内）
- 過去形・未来形の混在（現在形で統一）
- 主語の省略（明確に対象を書く）
- バージョン情報の記載（plugin.json の `version` で管理）
