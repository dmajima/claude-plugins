# ユーザ対話ルール（SSOT）

ユーザに選択や入力を求める際の手段を統一する。**Claude Code の UI（AskUserQuestion）を原則として使用** する（ADR-013 準拠）。

## 1. 選択 UI 利用の原則

| 原則 | 内容 |
|-----|------|
| 第一推奨 | `AskUserQuestion` ツール（選択 UI） |
| 例外 | 自由入力が必要・選択肢が動的・テキストのみで完結する場合 |

## 2. AskUserQuestion を使うべき場面

| 場面 | 例 |
|-----|---|
| 複数選択肢から 1 つ選ぶ | バージョン更新（メジャー / マイナー / パッチ / 更新しない） |
| Yes/No 確認 | 既存ファイル上書き確認 |
| 複数選択（multiSelect） | 含めるアイテム種別（commands / skills / agents / hooks） |
| モード選択 | 公開モード（ハンドオフ / フルオート） |
| 重複対応 | 重複検出時の対応（マージ / 新規 / キャンセル） |

## 3. テキスト対話を使ってよい場面

| 場面 | 例 |
|-----|---|
| 自由入力（短い） | プラグイン名、スキル名 |
| 自由入力（長い） | 1 行説明、トリガーフレーズ |
| 確認結果の報告 | 「以下を確認しました」のような **入力を求めない** 通知 |
| 動的選択肢が必要 | 候補をユーザの環境から動的に列挙する場合（既存ファイル一覧等） |

## 4. AskUserQuestion 利用方法

```text
AskUserQuestion({
  questions: [{
    question: "選択肢の質問文",
    header: "短いヘッダー（任意、UI 上部に表示）",
    options: [
      {
        label: "選択肢 1（短い見出し）",
        description: "選択肢 1 の詳細説明"
      },
      {
        label: "選択肢 2",
        description: "選択肢 2 の詳細説明"
      }
    ],
    multiSelect: false
  }]
})
```

### 必須項目

| 項目 | 内容 |
|-----|------|
| `question` | 何を聞いているかが明確な質問文 |
| `options[].label` | 各選択肢の短い見出し |
| `options[].description` | 各選択肢の意味・帰結を簡潔に |
| `multiSelect` | 複数選択可なら `true`、単一なら `false` |

### 推奨項目

| 項目 | 内容 |
|-----|------|
| `header` | UI 上部の短いラベル（4 単語以下） |

### 「Other」オプション

ユーザが選択肢以外の対応を取りたい場合、AskUserQuestion は自動的に「Other」オプションを表示する。明示的に追加する必要はない。「Other」が選択されたら自由入力で詳細を聞く。

## 5. 提示の原則

| 原則 | 内容 |
|-----|------|
| 選択肢は 2〜5 個 | 多すぎると選びにくい。多い場合は事前に候補を絞る |
| label は具体的に | 「Yes」「No」より「上書き」「キャンセル」 |
| description は帰結を書く | 何を選ぶとどうなるか |
| 推奨を示す | 「（推奨）」を label に含めて誘導してよい |
| キャンセルを含める | 重要な操作では「キャンセル」を必ず選択肢に含める |

## 6. アンチパターン

| パターン | 問題 | 代替 |
|---------|------|------|
| 自由入力で「1 / 2 / 3 を入力」 | UI を活かしていない | AskUserQuestion を使う |
| 選択肢が長文 | UI で読みにくい | label を短く、description で詳細 |
| 選択肢が 6 個以上 | 認知負荷が高い | 段階的選択（カテゴリ → 詳細）に分ける |
| 「Other」を明示的に追加 | 自動追加されるため重複 | 削除 |

## 7. 例: 重複検出時

```text
AskUserQuestion({
  questions: [{
    question: "プラグイン `foo` は既に存在します。どう進めますか？",
    header: "命名衝突対応",
    options: [
      {
        label: "別名で作成",
        description: "新しいプラグイン名を入力して新規作成（例: foo-v2）"
      },
      {
        label: "既存に追加",
        description: "既存プラグイン foo に中身を追加配置するシナリオへ切替"
      },
      {
        label: "キャンセル",
        description: "何もせず終了"
      }
    ],
    multiSelect: false
  }]
})
```

## 8. 例: 公開モード選択

```text
AskUserQuestion({
  questions: [{
    question: "公開方法を選択してください。",
    header: "公開モード",
    options: [
      {
        label: "ハンドオフ（推奨）",
        description: "git コマンドを提示。ユーザがコミット・プッシュ・PR 作成を手動実行"
      },
      {
        label: "フルオート",
        description: "git push + PR 作成まで自動実行（main 直接 push は禁止）"
      }
    ],
    multiSelect: false
  }]
})
```

## 9. 既存スキルへの適用

各スキルの SKILL.md / references 内で **「ユーザに以下を提示」「選択肢: 1. ... 2. ...」** という記述を、AskUserQuestion 利用に置き換える。スキル内でテキスト対話していた箇所を順次 AskUserQuestion 化する。

## 10. 非対話モードでの扱い

`--non-interactive` フラグありの場合は AskUserQuestion を呼ばず、引数で全パラメータを確定する。引数不足時はエラーで終了する（または明示されたデフォルト値を使う）。

## 11. AskUserQuestion 利用不可・非推奨ケースの判定

AskUserQuestion による選択 UI が原則だが、以下のいずれかに該当する場合は **テキスト対話または別手段** にフォールバックする。判定は Claude 側で行い、判定根拠（どのケースに該当するか）をユーザに通知する。

| 区分 | 内容 | 対応 |
|------|------|------|
| (a) ツール自体が無効化 | AskUserQuestion が利用環境で無効化されている / disable リストに含まれる | テキスト対話に切替、ユーザに事前通知 |
| (b) 自由入力主体 | label/description の 2-4 オプションで表現できない（パスワード入力 / 任意長文字列 / API キー入力等） | テキスト対話で自由入力を促す |
| (c) 複雑バリデーション | 入力値の正規表現 / 組合せ検証 / 既存値との照合 等の生検証が必要 | テキスト対話 + Claude 側で検証ループ |
| (d) 動的選択肢で件数過大 | 候補が利用者環境から動的列挙され、5 以上または流動的 | 段階的選択（カテゴリ→詳細）に分解するか、候補プレビュー + テキスト対話 |
| (e) 純粋な情報通知 | 入力を求めない通知（完了報告・結果サマリー） | プレーンテキスト出力（節 3 の通知ケース） |

判定に迷う場合は **AskUserQuestion を選ぶ**（節 1 の原則を優先）。

## 12. 利用不可時のフォールバック手順

AskUserQuestion を利用できない / 非推奨ケースと判断した場合、以下の手順を踏む。

1. **ユーザへの通知**: 「本来 AskUserQuestion で確認するところ、{理由} のため代替手段を取ります」と明示
2. **対話手段の提示**: 代替手段の候補を提示（テキスト対話 / 段階的絞込 / 中断 等）
3. **必要なら明示確認**: 重要な操作（公開・削除・上書き）の場合は「テキスト対話で進めて良いか」を 1 度確認
4. **入力検証**: Claude 側で入力値を検証し、不正なら再質問（リトライ上限を設定）
5. **ログ記録**: セッションの `progress.md` に「AskUserQuestion フォールバック理由」を記録（再現性のため）

### 12.1 ユーザへの通知テンプレート

```text
{操作名} について本来 AskUserQuestion で選択 UI を提示するところ、
{理由 (a)-(e) のいずれか} のためテキスト対話で進めます。

以下から選んで返信してください:
- {選択肢 1}: {帰結}
- {選択肢 2}: {帰結}
- キャンセル: 何もせず終了
```

### 12.2 フォールバック判定のドッグフード

AskUserQuestion 利用判断そのもの（利用するか、テキスト対話にするか）を **AskUserQuestion で確認しない**。Claude 側で節 11 のフローチャートに従って自動判定する。これは「判定の判定」を無限後退させないため。

## 13. 禁止事項

- 重要な選択（公開・削除・上書き等）を AskUserQuestion を使わずテキスト対話で行うこと（節 11 (a)-(d) の例外を除く）
- AskUserQuestion の結果を確認せず処理を進めること
- 選択肢に必要な「キャンセル」を含めないこと
- AskUserQuestion 利用判定の根拠をユーザに伝えずフォールバックすること（節 12 ステップ 1）
- フォールバック時に「テキスト対話で進めます」と通知せず無断切替すること
