# 実行手順詳細

`command-toolkit` の詳細実行手順。

## 配置先の選択

| 用途 | 配置先 |
|-----|-------|
| プロジェクト固有 | `<repo>/.claude/commands/{name}.md` |
| グローバル | `~/.claude/commands/{name}.md` |
| プラグイン同梱 | `plugins/{plugin-name}/commands/{name}.md` |

## テンプレート展開手順

### 1. ベースコピー

`${CLAUDE_PLUGIN_ROOT}/references/templates/command/command.md` を配置先にコピー。

### 2. プレースホルダ置換

| プレースホルダ | 置換値 |
|--------------|-------|
| `{コマンドの 1 行説明（60 文字以内）}` | description |
| `{必須引数を <...>、省略可を [...]、フラグを [--flag 値] で記述。引数を受け取らないコマンドはこの行ごと削除}` | argument-hint（引数受取時は必須、ADR-023）|
| `{パターン 1}` | 引数パターン |
| `{skill-name-1}` | ルーティング先スキル |
| `{確認項目 1}` | 引数空時の確認項目 |

### 3. プロンプト本体の充填

テンプレートの構造を保ちつつ、コマンド固有のロジックを末尾に追加する。

## オーケストレータ型コマンドの場合

`/extension` や `/publish` のように複数スキルへルーティングするコマンドは以下を含める:

```markdown
## ルーティング

| 引数パターン | 起動スキル |
|------------|----------|
| `skill <name>` | `skill-toolkit` |
| `plugin <name>` | `plugin-toolkit` |
| `command <name>` | `command-toolkit` |
| `agent <name>` | `agent-toolkit` |
| `hook <name>` | `hook-toolkit` |
| `readme <target>` | `readme-toolkit` |
| `review <target>` | `extension-reviewer` |
| `publish <plugin>` | `marketplace-publisher` |
```

## 単機能型コマンドの場合

単一のロジックを実行する場合は `## ルーティング` を削除し、本文に直接プロンプトを書く。

## description 設計

| 用途 | 文字数 | 例 |
|-----|-------|---|
| プラグイン同梱コマンド | 60 文字以内 | `拡張要素の作成・公開を支援` |
| プロジェクト用コマンド | 60 文字以内 | `現在のブランチでテストを実行` |

避けるべき表現:

| 避ける | 理由 |
|-------|------|
| 引数仕様（`--foo` 等の記述） | `argument-hint` に書く（SSOT、ADR-023）|
| 複数機能を並列列挙 | 60 文字超過しやすい |
| 過去形・未来形 | 現在形で統一 |

## argument-hint 設計（ADR-023）

引数を受け取るコマンドは frontmatter に `argument-hint` を必ず記載する。`/` 補完 UI で利用者が最初に見る引数仕様の SSOT。

### 設計手順

1. **必須引数の洗い出し**: 本文の `$ARGUMENTS` 解釈から、必須位置引数を特定する
2. **省略可引数の洗い出し**: 省略時のデフォルト動作があるものを特定する
3. **フラグの整理**: `--flag 値` / `--flag` 形式のオプションを列挙する
4. **配置順**: 「必須引数 → 省略可引数 → フラグ」の順で並べる
5. **文字数調整**: 60 文字以内に収まるよう、長すぎる引数名は短縮する

### 例

| コマンド種別 | argument-hint |
|-------------|---------------|
| 入出力ファイル変換 | `<入力MDパス> [出力HTMLパス] [--title タイトル]` |
| オーケストレータ（ルーティング） | `<種別> <対象名> [--non-interactive] [--full-auto]` |
| 単機能（必須引数のみ） | `<対象パス>` |
| 単機能（フラグのみ） | `[--dry-run] [--verbose]` |

### 引数を受け取らないコマンドの場合

本文に `$ARGUMENTS` を一切書かず、ルーティング表も持たないコマンドは `argument-hint` を **省略** する。テンプレートから `argument-hint` 行ごと削除する。

## 引数空時の動作設計

| 戦略 | 適用条件 |
|-----|---------|
| 必須引数を対話で確認 | 必須引数あり |
| ヘルプ表示 | 引数仕様が複雑 |
| デフォルト動作実行 | 引数なしでも意味のある動作が定義可能 |

## ルーティング設計

### 完全一致ルーティング

引数の最初のトークンと完全一致でスキル選択。

### パターンマッチング

引数全体を正規表現で評価し、最初に一致するルートへ。

### フォールバック

どのルートにも一致しない場合の動作を必ず定義。

| フォールバック | 動作 |
|-------------|------|
| ヘルプ表示 | 利用可能パターンを提示 |
| デフォルトルート | 最も一般的なルートを起動 |
| エラー | 引数不正としてユーザに修正を促す |
