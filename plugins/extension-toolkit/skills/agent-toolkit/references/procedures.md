# 実行手順詳細

`agent-toolkit` の詳細実行手順。

## モード判定

| 入力の特徴 | モード |
|----------|-------|
| 1 名の役割指定（単数形） | 単体エージェント |
| 「チーム」「複数視点」「議論」を含む発話 | チーム編成 |
| `--team` フラグあり | チーム編成 |
| レビュー系（観点網羅必要） | チーム編成（最低 3 名） |

## 単体エージェント作成手順

### 1. パラメータ確定

| パラメータ | 必須 | 例 |
|----------|------|---|
| エージェント名（kebab-case） | 必須 | `code-reviewer` |
| 専門領域 | 必須 | コード品質 / セキュリティ / アクセシビリティ |
| 主な評価観点 | 必須（3 つ以上） | - |
| 利用ツール | 任意 | `Read, Grep, Glob`（デフォルト） |
| モデル | 任意 | `sonnet`（デフォルト） |
| 配置先 | 必須 | `~/.claude/agents/` or `plugins/{plugin}/agents/` |

### 2. テンプレート展開

`${CLAUDE_PLUGIN_ROOT}/references/templates/agent/agent.md` を配置先にコピー、プレースホルダ置換。

| プレースホルダ | 置換値 |
|--------------|-------|
| `{agent-name}` | エージェント名 |
| `{役割名}` | 表示名 |
| `{専門領域・評価観点・起動条件を含む説明}` | description |
| `{領域 1}` `{領域 2}` | 専門領域 |
| `{評価軸 1}` `{評価軸 2}` | 主な評価軸 |
| `{デファクトスタンダード}` | 参照する外部知識 |

### 3. 評価観点の充実化

| 領域 | 推奨評価観点 |
|-----|------------|
| コード品質 | 正確性 / パフォーマンス / 可読性 / テスト容易性 |
| セキュリティ | OWASP Top 10 / 認証認可 / 入力検証 / 機密情報露出 |
| UX | アクセシビリティ / 情報設計 / インタラクション / エラーフィードバック |
| インフラ | スケーラビリティ / 可用性 / 監視 / コスト |
| 法務 | OSS ライセンス互換 / プライバシー法令 / 契約整合 |

### 4. 出力フォーマットの設計

```markdown
## {役割名} レビュー結果

### Critical
- {重大な問題、即時修正必須}

### High
- {重要な問題、修正推奨}

### Medium
- {中程度の問題、検討推奨}

### Low / Suggestion
- {軽微な問題・改善提案}

### 総合判定
{APPROVE / CONDITIONAL_APPROVE / REJECT} — {理由 1 行}
```

## チーム編成手順

### 1. パラメータ確定

| パラメータ | 必須 | 例 |
|----------|------|---|
| チーム名（kebab-case） | 必須 | `system-design` |
| 目的 | 必須 | 設計判断の合意形成 |
| リードエージェント | 必須 | `architect` |
| メンバー（3 名以上） | 必須 | `implementation-engineer` `security-engineer` `project-leader` |
| 議論ラウンド数 | 任意 | 最低 3、上限 5 |

### 2. メンバー構成の検証

詳細は [team-design.md](team-design.md) の「メンバー選定」を参照。

| 観点 | 確認内容 |
|-----|---------|
| 必要観点の網羅 | 主要観点が全て担当エージェントに割り当てられている |
| 専門性の相補性 | メンバー間で専門領域が重複していない |
| 議論成立 | 異なる視点を持つメンバーで反論・合意形成が可能 |
| サイズ | 3〜5 名（レビュー系最低 3 名）。観点 2 つに固定なら 2 名、プラグイン全体レビューで観点網羅必須なら 6 名まで例外として許容 |

### 3. テンプレート展開

`${CLAUDE_PLUGIN_ROOT}/references/templates/agent/team.md` を `agents/teams/{team-name}.md` 等に配置。

### 4. スポーンプロンプト充填

テンプレートのスポーンプロンプトに以下を反映:

- 各メンバーの責務（リード / 評価軸別メンバー）
- 議論ラウンド数（最低 3 回）
- 期待成果物（合議結果 + トレードオフ明記）

### 5. 各メンバーエージェント定義の確認

メンバーのエージェント定義（`~/.claude/agents/{member}.md`）が既存していることを確認。未存在のメンバーは単体エージェント作成手順を派生で実行する。

## 共通の検証

- [ ] frontmatter 必須フィールド全指定
- [ ] description ガイドライン準拠
- [ ] 評価観点 3 つ以上
- [ ] 出力フォーマット定義済
- [ ] レビュー系チームは 3 名以上
- [ ] パスポータビリティ合格

## デファクトスタンダードの取り込み

エージェントの専門性を高めるため、領域に応じた標準・リファレンスを取り入れる。

| 領域 | 推奨参照 |
|-----|---------|
| セキュリティ | OWASP / CWE / NIST CSF |
| アクセシビリティ | WCAG 2.1 / ARIA |
| 可用性 | SRE Book / SLO/SLI |
| クラウド | Well-Architected Framework |
| OSS 法務 | SPDX License Identifier |
| 設計 | C4 Model / DDD / SOLID |

参照を含める場合、エージェント定義の「専門性」セクションに明記する。
