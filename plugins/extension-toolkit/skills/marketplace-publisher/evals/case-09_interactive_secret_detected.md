# Case 09: 対話モードでのシークレット検出（4 択提示）

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | "`my-plugin` を公開" |
| 引数 | `my-plugin`（**フラグなし**= 対話モード） |
| フラグ | なし（対話モード）|
| 既存状態 | プラグイン実体内に `.env` ファイルあり、または内容に AWS アクセスキーパターンを含む |

## 期待動作

### Phase 1: プラグイン実体検証

`plugins/my-plugin/.claude-plugin/plugin.json` 存在確認後、**シークレット混入スキャン** を実行（[`../references/secret-scan.md`](../references/secret-scan.md) の検出パターンに従う）。

### Phase 2: 検出 → fail-closed（対話モード）

検出ファイルを `AskUserQuestion` で提示し、4 択を提供:

```text
シークレット混入の疑いを検出しました。公開フローを中断します。

検出ファイル:
- plugins/my-plugin/.env — filename:.env
- plugins/my-plugin/config/api.yaml:23 — content:aws_access_key

どう対応しますか？
1. 該当ファイルを削除/移動して再実行
2. .gitignore に追加して再実行
3. 誤検出として続行（二重確認あり）
4. キャンセル
```

### Phase 3: 選択分岐（対話モード固有）

| 選択 | 動作 |
|-----|------|
| 1（削除/移動） | 該当ファイル削除/移動を案内、本スキル終了（再実行待ち）|
| 2（gitignore 追加） | `.gitignore` 追加を案内、本スキル終了（再実行待ち）|
| 3（誤検出として続行） | **二重確認 (`AskUserQuestion`) で「本当に公開してよいか？」を再質問** → ユーザが yes を選んだ場合のみ続行 |
| 4（キャンセル） | 何もせず終了 |

### Phase 4: 選択 3 の二重確認フロー

```text
本当にこのプラグインを公開しますか？検出されたパターンが誤検出でないことを確認しましたか？

1. はい、公開を続行（自己責任）
2. いいえ、キャンセル
```

「はい」→ 通常の公開フロー（重複検査 → marketplace-toolkit 委譲 → git push）に復帰。
「いいえ」→ 何もせず終了。

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| 変更ファイル | 選択により異なる（選択 3 の「はい」の場合のみ通常フロー）|
| 標準出力 | 検出ファイル一覧 + 4 択 + 二重確認 + 選択結果 |
| 終了状態 | 選択により異なる（中断 / キャンセル / 続行）|
| ユーザ対話 | 最低 1 回（選択 3 の場合は 2 回）|

## 分岐の根拠

対話モード（`--non-interactive` / `--full-auto` 不在）+ シークレット検出 → 4 択提示 + 二重確認。
case-07（フルオート + シークレット）と case-08（非対話ハンドオフ + シークレット）は選択肢 3 を提供しない（fail-closed 強化）が、本ケースは対話モードのため選択肢 3 を提供し、ユーザの明示的な意思決定（二重確認）に委ねる同値分割の対称ペア。
