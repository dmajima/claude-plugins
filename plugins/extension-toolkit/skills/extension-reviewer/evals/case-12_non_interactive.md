# Case 12: --non-interactive モード（自動レビュー、結果のみ提示）

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | "`code-formatter --non-interactive` をレビュー" |
| 引数 | `code-formatter` |
| フラグ | `--non-interactive` |
| 既存状態 | スキルが存在 |

## 期待動作

### Phase 1: モード判定

SKILL.md「実行モード判定」テーブルに従い `--non-interactive` を検出 → 非対話モード。

| モード特性 | 値 |
|----------|----|
| ユーザ確認 | 行わない（`AskUserQuestion` 呼び出しなし） |
| 修正提案 | 結果として提示するが **適用しない** |
| 観点・修正方針の質問 | スキップ |

### Phase 2: 対象判定 + チーム選定 + 並列起動

通常フローと同一（case-01 参照）。`skill-review-team` を起動。

### Phase 3: 結果統合

通常フローと同一。Critical / High / Medium / Low に分類。

### Phase 4: 引き渡し（非対話）

| 結果 | 動作 |
|-----|------|
| Critical/High なし | 結果のみ標準出力に提示し終了 |
| Critical/High あり | 結果のみ標準出力に提示し終了（該当 `*-toolkit` への接続提案は文字列のみ、対話なし） |

`AskUserQuestion` は **一切呼び出さない**。修正の自動適用も行わない（`--auto-fix` 同時指定時のみ軽微修正を自動適用）。

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| 標準出力 | レビュー結果（指摘・優先度・総合判定）のみ。質問・選択肢提示なし |
| 終了状態 | レビュー完了 |
| ユーザ対話 | 発生しない |

## 分岐の根拠

`--non-interactive` フラグ → 自動化スクリプト・CI からの呼び出しを想定し、対話ゲートを全て省略。
