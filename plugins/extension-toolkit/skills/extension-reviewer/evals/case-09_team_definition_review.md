# Case 09: チーム定義レビュー（個別 4 名並列）

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | "`skill-review-team` チーム定義をレビュー" |
| 引数 | `teams/{name}.md` |
| フラグ | なし |
| 既存状態 | チーム定義が単体ファイル |

## 期待動作

### Phase 1: 対象判定

`teams/{name}.md` → チーム定義レビューモード。

### Phase 2: 個別エージェント選定（4 名）

[`../references/team-selection.md`](../references/team-selection.md) に従う。専用チームを設けず、以下を並列起動:

| エージェント | 配布元 | 観点 |
|------------|-------|------|
| `plugin-structure-reviewer` | プラグイン同梱 | 規約準拠（チーム情報テーブル・スポーンプロンプト等） |
| `description-trigger-reviewer` | プラグイン同梱 | チームの起動条件・命名のトリガー精度 |
| `architect` | グローバル | チーム編成の妥当性・観点網羅性 |
| `project-leader` | グローバル | メンバー相補性・サイズ妥当性・議論ラウンド設計 |

エージェント定義レビュー（case-08）に対して `project-leader` を追加する。チーム編成特有の評価軸（メンバー相補性・サイズ・議論ラウンド）を担当する。

### Phase 3: 並列起動 + 機械チェック

| 機械チェック | 内容 |
|------------|------|
| 必須項目 | チーム情報テーブルに `目的` `リード` `メンバー` `人数` `議論ラウンド` |
| サイズ | 標準 3〜5 名（観点固定で 2 名のみ可、その理由が明記されているか） |
| リード | 指定済みかつメンバー一覧に含まれるか（重複表記排除） |
| スポーンプロンプト | 存在するか・全メンバーに役割が割り当てられているか |
| メンバー相補性 | 担当エージェントの専門領域が重複していないか（具体基準: 同一グローバルエージェントが 2 行以上存在しない / 同名のプラグイン同梱エージェントが 2 行以上存在しない / 専門領域カラムの主キーワードが完全一致するエージェントが 2 行以上存在しない） |

### Phase 4: 結果統合 + 引き渡し

通常の統合 → 優先度付け → 次アクション提案（修正は `agent-toolkit` のチームモードで）。

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| 標準出力 | エージェント別の指摘 + 統合レビュー結果 + 総合判定 |
| 終了状態 | レビュー完了 |

## 分岐の根拠

対象 = チーム定義（専用チームなし、エージェント定義レビューに `project-leader` を加えた 4 名構成）。
