# Cross-cutting Rules (plugins-update)

`plugins-update` プラグインの全 Phase に横断的に適用されるルール。
本ファイルは XR-1〜XR-5 の **SSOT**。コマンド本文 (`commands/update-all.md`) は本ルールへの参照のみを持ち、規則本体を再定義しない。

| ID | ルール | 適用対象 |
|----|------|---------|
| XR-1 | 入力検証 | A-0-1（`--scope` 引数値）/ A-1（識別子）/ B / C / D / E / G-3 |
| XR-2 | タイムアウト + サーキットブレーカー | B / C / D / E / G-3 |
| XR-3 | 出力サニタイズ | F-2 / F-3 / G-2 / B-1 例外行抽出時（F-1 は件数のみのため対象外） |
| XR-4 | リトライ上限 | G-3 |
| XR-5 | Unknown 警告閾値 | F-1 |

> **SSOT 注記**: 本表が XR の Phase 適用先の **唯一の正典**。`phase-flow.md` の各 Phase 見出し副題に
> 同等列挙が存在するが、それは実装者の便宜のための再掲であり、規範性は本表のみ持つ。差異が生じた
> 場合は本表を信頼し `phase-flow.md` 側を更新する（ADR-PU-004 SSOT 配置原則準拠）。

## XR-1: 入力検証

### ルール

プラグイン名・マーケットプレイス名・スコープ名を以下で検証し、合致しないエントリは
**Skipped（不正な名前）** として除外し、CLI コマンドには絶対に渡さない。

| 対象 | 検証 |
|------|------|
| plugin-name / marketplace-name | NFKC 正規化後、正規表現 `^[A-Za-z0-9]([A-Za-z0-9_.-]{0,62}[A-Za-z0-9])?$` に合致（先頭・末尾は英数字、長さ 1〜64） |
| scope（A-1 内部表現の検証用） | ホワイトリスト `user` / `project` / `local` のいずれかと完全一致 |
| `--scope` 引数値（A-0-1 のユーザー入力検証用） | ホワイトリスト `user` / `project` / `local` / `all` のいずれかと完全一致（`all` は省略時の既定値であり明示指定も可。A-1 では `all` は scope ループ展開後にスコープ別 `user` / `project` / `local` の値で再検証される） |
| `<plugin>@<marketplace>` 識別子 | `@` 文字が **正確に 1 個** であること（複数あればエントリ拒否） |

### 適用詳細

- 識別子は `@` で **分割した後**、左右それぞれを正規表現に照合する（識別子全体ではない）。
- NFKC 正規化は Claude 自身が内部処理として実施可能なため、原則すべての環境で適用する。
  万が一何らかの理由で実施できない場合のみ当該エントリを Skipped 扱いとする。
- CLI 引数は **シェル経由ではなくプロセス引数として直接渡す**（Bash でのトークン分割や
  `$ARGS` 展開を避ける）。`<plugin>@<marketplace>` 形式は連結後の 1 引数として渡し、
  シェルメタ文字を含む引数を引用符なしで渡さない。XR-1 の正規表現を通過した識別子のみを使用する。

### パス検証（Phase A の `<repo>` 用）

`<repo>` は `git rev-parse --show-toplevel` の結果。以下をすべて満たす場合のみ採用し、
いずれかを満たさない場合は Project / Local 処理をスキップして INFO で理由を表示する:

| 検証項目 | 判定 |
|---------|------|
| `..` を含まない | 含めば拒否 |
| 絶対パス | Windows: 正規表現 `^[A-Za-z]:[\\/]`、POSIX: 正規表現 `^/` |
| 改行・null 文字を含まない | 含めば拒否 |
| シェル特殊文字を含まない | `'`（シングルクォート）/ `"`（ダブルクォート）/ `` ` ``（バッククォート）/ `$` / `;` / `\|` / `&` / `<` / `>` を含めば拒否（POSIX のパスは合法だが PowerShell / Bash の文字列展開で脱出されるリスクを排除） |
| UNC パスでない | Windows で `^\\\\` で始まる場合は拒否（リモート共有上の細工された settings.json 経由の攻撃面排除） |
| シンボリックリンク・ジャンクションでない | Windows: PowerShell `Get-Item -LiteralPath '<repo>' \| Select-Object LinkType` で `null` でない場合は拒否（リパースポイント検出）。`-LiteralPath` を使い、`<repo>` は単一引用符でクォート。**この時点で `<repo>` は前段「シェル特殊文字を含まない」検証で `'`（シングルクォート）含有が除外済み** のため、シングルクォートクォートはリテラル安全（順序制約は phase-flow.md A-Repo「検証順序の規範」を参照）。POSIX: `test -L <repo>` で真なら拒否 |
| 実在ディレクトリ | Read ツールで存在確認できない場合は拒否 |

判定不能な環境（必要なツールが利用できない等）では **フェイルクローズ**（スキップ + 理由 INFO 表示）。

### 根拠

- CWE-78（OS Command Injection）/ CWE-88（Argument Injection）への防御。
- 末尾文字を英数字に限定するのは、ハイフン・ドット・アンダースコア末尾による CLI 引数境界の誤認回避。
- 64 文字上限は DNS ラベル制限（63 字）と Claude Code プラグイン名の実用上限を勘案した経験値。
- UNC パス排除は CWE-22 Path Traversal の派生（リモート共有経由の信頼境界外アクセス）への防御。

## XR-2: タイムアウト + サーキットブレーカー

### ルール

| 対象 | 値 | 超過時の挙動 |
|------|-----|-------------|
| 個別 CLI 呼び出し | 60 秒 | 当該呼び出しを Failed として記録し次へ進む |
| 全体実行 | 30 分 | 残エントリを Skipped（全体タイムアウト）として終了 |

### サーキットブレーカー（XR-2 の補助）

同一マーケットプレイスに対する **累計 3 件以上の Failed**（連続・非連続問わず）が発生した場合、
当該 MP 配下の残エントリを Skipped（サーキットブレーカー作動）として時間浪費を抑制する。
集計は MP 単位カウンタでフェーズ横断（Phase B / C / D / E すべての Failed をカウント）。

### 適用詳細

- 個別 60 秒は Phase B / C / D / E / G-3 のすべての CLI 呼び出しに適用。
- サーキットブレーカー作動中の MP は G-3 のリトライ対象から除外する。

### 根拠

- 60 秒: GitHub HTTPS / SSH 経由の典型的な fetch + reset の所要時間（数秒〜数十秒）に対する
  3 倍程度のマージン。ネットワーク遅延を考慮した経験値。
- 30 分: 大規模環境（プラグイン 100 件超）でも 60 秒 × 100 = 100 分の暴走を防ぐためのハードリミット。
- サーキットブレーカー累計 3 件: 設計判断は ADR-PU-006 を参照。

## XR-3: 出力サニタイズ

### ルール

CLI 出力をユーザに表示する直前（テーブルセルに格納する直前）に、本セクションのサニタイズ規則を必ず適用する。

### 適用ポイント

- **適用必須**: F-2 / F-3 のテーブル `備考` 列 / G-2 の質問文の `<error>` 部分 / B-1 で例外行から
  MP 名を抽出する処理。
- **適用範囲**: テーブルの `備考` 列・エラー文字列・質問文の `<error>` 部分のみ。
  プラグイン名列・マーケットプレイス名列・結果列（OK / Failed / Updated 等の固定値）には
  **デフォルトマスクを適用しない**（誤検知でプラグイン名が伏せられて更新成否不明になる事故を防ぐ）。
- **対象外（明示）**: **Phase A の `claude plugin marketplace list` 出力**は本サニタイズの対象外
  （MP 名・URL 主体の構造化出力で機密性が低く、dry-run / 通常モード共通で対象外）。F-1 サマリ表は
  件数（整数）のみのため対象外。
- **タイミング**: サニタイズ前文字列はメインコンテキストに保持しない。テーブルセル生成時に
  サニタイズ後文字列のみを保持し、生出力は破棄する。

### サニタイズ規則本体

正規表現は CLI 出力の **値部分** に対して適用する。

#### 適用順序

1. **規則ベース**（下表）を **すべて適用**して秘匿トークンを置換する。
2. **デフォルトマスク**（後述）を残余文字列に適用する。

この順序により「引用符付きトークンは文脈内 = マスクしない」例外と「`Bearer xxx` は規則ベースで先処理」が
矛盾なく成立する。

| パターン | 置換後 | 備考 |
|---------|-------|------|
| `(?i)(token\|password\|secret\|authorization\|bearer\|x-api-key)[:=\s]+\S+` | `<key>=***REDACTED***` | 汎用 key=value（空白区切りの `Bearer xxx` も捕捉） |
| `(?i)[a-z][a-z0-9+.-]*://([^@/\s]+)@` | `<scheme>://***@` | URL 埋め込み認証（`http(s)/git/ssh/ftp` 等の任意スキーム、大小文字スキームを問わず `user:pass@` / PAT 単独 `token@` / URL エンコード `%40` を含む形式を全て捕捉） |
| `([a-zA-Z_][\w-]*)@([\w.-]+):` | `***@<host>:` | scp-like SSH URL（`git@github.com:user/repo.git` 形式の内部ホスト名・ユーザ名を伏字） |
| `ghp_[A-Za-z0-9]{36,}` / `github_pat_[A-Za-z0-9_]{82,}` / `gho_[A-Za-z0-9]{36,}` / `ghs_[A-Za-z0-9]{36,}` / `ghu_[A-Za-z0-9]{36,}` | `***GITHUB_TOKEN***` | GitHub PAT |
| `glpat-[A-Za-z0-9_-]{20,}` | `***GITLAB_TOKEN***` | GitLab PAT |
| `AKIA[0-9A-Z]{16}` / `ASIA[0-9A-Z]{16}` | `***AWS_KEY_ID***` | AWS アクセスキー |
| `xox[baprs]-[A-Za-z0-9-]{10,}` | `***SLACK_TOKEN***` | Slack トークン |
| `eyJ[A-Za-z0-9_-]{16,}\.[A-Za-z0-9_-]{16,}\.[A-Za-z0-9_-]{16,}` | `***JWT***` | JWT（実用 JWT のヘッダ・ペイロード・署名最小長を踏まえ各セグメント 16 字以上に制限し誤検知抑制） |
| `AIza[0-9A-Za-z_-]{35}` | `***GOOGLE_API_KEY***` | Google API Key |
| `sk_(live\|test)_[A-Za-z0-9]{24,}` | `***STRIPE_KEY***` | Stripe API Key |
| `DefaultEndpointsProtocol=[^;]+;AccountKey=[^;]+` | `***AZURE_STORAGE***` | Azure ストレージ接続文字列 |
| `npm_[A-Za-z0-9]{36}` | `***NPM_TOKEN***` | NPM Token |
| `sk-ant-api[0-9]{2,3}-[A-Za-z0-9_-]{32,}` | `***ANTHROPIC_API_KEY***` | Anthropic API Key（API バージョン番号 2〜3 桁対応で将来拡張に追従） |
| `sk-[A-Za-z0-9]{48}` | `***OPENAI_API_KEY***` | OpenAI API Key |
| `hf_[A-Za-z0-9]{34}` | `***HUGGINGFACE_TOKEN***` | HuggingFace Token |
| `https://[a-f0-9]{32}@[\w.-]*sentry\.io[^\s]*` | `***SENTRY_DSN***` | Sentry DSN |
| `pypi-AgEIcH[A-Za-z0-9_-]{70,}` | `***PYPI_TOKEN***` | PyPI Token |
| `https://discord(?:app)?\.com/api/webhooks/[0-9]+/[A-Za-z0-9_-]+` | `***DISCORD_WEBHOOK***` | Discord Webhook（Bot 投稿経路）|
| `[0-9]{8,}:AA[A-Za-z0-9_-]{33}` | `***TELEGRAM_BOT_TOKEN***` | Telegram Bot Token |
| `(?<![A-Za-z0-9])(SK\|AC)[a-f0-9]{32}(?![A-Za-z0-9])` | `***TWILIO_KEY***` | Twilio Account SID（`AC` + 32 hex）/ Auth Token（`SK` + 32 hex）。前後単語境界で誤検知抑制 |
| `machine\s+\S+\s+login\s+\S+\s+password\s+\S+` | `<netrc-credential>` | .netrc 形式 |
| `/[\w./-]+\.pem`、`id_rsa`、`id_ed25519` | `<ssh-key-path>` | SSH 鍵パス |
| `C:\\Users\\[^\\]+` / `/Users/[^/]+` / `/home/[^/]+` | `<user-home>` | ローカルパス内のユーザ名 |

#### デフォルトマスク（テーブル備考列のみに適用）

上記いずれにも合致しない長さ **40 字以上** の `[A-Za-z0-9_\-]+` 連続トークンが、
以下のいずれかの **文脈外** で出現した場合に `***POSSIBLE_SECRET***` でマスクする。

閾値を 40 字としたのは: API トークンの典型長（30〜80 字）の中央域をカバーしつつ、
コミットハッシュ短縮形 (7〜8 字) ・SemVer (`v2.6.0` 等) ・プラグイン名（XR-1 で 64 字以下に制限済み）
の誤検知を構造的に排除するため。32 字付近の旧式 OAuth トークン等は規則ベース（GitHub PAT・
GitLab PAT・Stripe Key 等の具体パターン）で先処理されるため、デフォルトマスクの守備範囲外でも
取りこぼしリスクは限定的。

#### 「文脈内」の具体ルール

以下のいずれかに該当する場合は **文脈内** とみなしマスクしない:

| 文脈 | 判定基準 |
|------|---------|
| URL 内 | トークンが `https?://...` の path / query 内に含まれる |
| ファイルパス内 | トークンが `/` または `\` を含むパス文字列の一部 |
| 引用符付きトークン | トークンが `"..."` または `'...'` で囲まれている（ただし `"Bearer xxx"` のような認証ヘッダ値はマスク対象） |
| プラグイン識別子内 | `<plugin>@<marketplace>` 形式の `@` 前後（XR-1 で各 64 字以下に制限済みのため 40 字閾値で誤検知が起きうるが、識別子全体構造で除外する） |

#### 「文脈外」の判定（マスク対象）

以下を満たす場合に **文脈外** = マスク適用:
- 直前文字が空白 / 行頭 / `:` / `=` / `,`
- 直後文字が空白 / 行末 / `,` / `)`
- 上記「文脈内」のいずれにも該当しない

#### URL 内クエリパラメータの副規則（文脈内例外の例外）

「URL 内文脈はマスクしない」例外には以下の **副規則** を適用する。URL の `?key=value` /
`&key=value` 部分のうち `key` が以下の正規表現にマッチする場合、`value` は **文脈外扱いで
マスクする**（短いトークンの URL クエリ内露出を防止）。

**重要**: 本副規則は **デフォルトマスク 40 字閾値とは独立** に適用され、`value` の長さを問わず
（1 字でも）マスク対象とする。置換後は `***POSSIBLE_SECRET***` で統一。

```text
(?i)(token|key|secret|password|api[_-]?key|auth|sig|signature|access[_-]?token|refresh[_-]?token|bearer)
```

例:
- `https://example.com/?api_key=shorttoken` → `https://example.com/?api_key=***POSSIBLE_SECRET***`
- `https://github.com/repo?token=abc123` → `https://github.com/repo?token=***POSSIBLE_SECRET***`
- `https://example.com/?id=12345`（`key` パターン非該当）→ マスクしない

#### テストケース

##### テストケース記載ルール（MANDATORY）

- **実トークンの貼り付け禁止**: 本物のシークレット（GitHub PAT・AWS キー・JWT 等の実値）を
  テストケースに直接記載してはならない。誤って実トークンを混入させた場合は速やかにローテーションする。
- **ダミーは長さプレースホルダ表記**: `ghp_<36字>@github.com/...` のように長さを記号で示す。
  ランダム生成器で「実トークン形のダミー」を作って貼り付けることも禁止（誤って実トークンと衝突する
  リスク・正規表現がマッチする可能性のため）。
- **CI 検査の推奨**: `git grep -E '(ghp_|AKIA|sk-|hf_|xox[baprs]-|pypi-|glpat-)[A-Za-z0-9_-]{16,}'`
  を CI で実行し、本プラグイン配下に実トークン形が混入していないか定期確認する。

| 入力（抜粋） | 期待挙動 |
|------------|---------|
| `key=abcdef0123456789...（40+字）` | マスク（key=value 文脈、規則ベースで先にマスクされる場合あり） |
| `https://example.com/abcdef0123456789...（40+字）/path` | マスクしない（URL の path/query 内） |
| `https://ghp_<36字>@github.com/user/repo`（PAT 単独形式） | マスク（規則ベース GitHub PAT で先処理、URL 埋め込み認証規則も拡張済） |
| `Bearer abcdef0123456789...（40+字）` | マスク（規則ベース汎用 key=value で先処理、`Bearer` を key とみなす） |
| `commit-hash abc1234` | マスクしない（7 字、40 字未満） |
| `error message: abcdef0123456789...（40+字）` | マスク（行末・空白文脈） |
| プラグイン名 `extension-toolkit-long-name`（30+字、テーブル名前列） | マスクしない（列単位例外） |
| 長さ 35 字（40 字未満）の任意トークン `abcdef0123456789abcdef0123456789abc` | マスクしない（40 字未満は規則ベース対象外なら素通り） |
| プラグイン識別子 `extension-toolkit-long-name@dmajima-claude-plugins-marketplace`（合計 60+ 字、備考列に出現） | マスクしない（`@` 構造が識別子内文脈外判定で除外。XR-1 で各 64 字以下に制限済みのため安全） |
| 備考列の `Twilio sid: ACabcdef...32hex` | マスク（`AC` + 32 hex の Twilio パターン、単語境界判定で誤検知抑制） |
| 短い JWT 風文字列「eyJ + `<5字>` + `.eyJ` + `<5字>` + `.<3字>`」（各セグメント 16 字未満） | マスクしない（v3.3.0 で各セグメント最小長を 16 字に引き上げたため、誤検知抑制） |
| 正常 JWT 形式「eyJ + `<20字>` + `.eyJ` + `<25字>` + `.<43字>`」（各セグメント 16 字以上） | マスク（規則ベース JWT パターンに合致） |
| 大文字スキーム `Mailto:User:Pass@example.com` | マスク（URL 埋め込み認証パターンに `(?i)` 付与済、大小文字スキーム両対応） |
| 引用符付き Bearer `"Bearer <40+字>"` | マスク（規則ベース汎用 key=value 先処理が引用符文脈内判定より優先・適用順序ルール） |
| URL クエリ短トークン `https://example.com/?api_key=shorttok` | マスク（URL 内クエリパラメータ副規則：`api_key` が key パターンに合致するため `value` を文脈外扱い） |
| URL クエリ識別子 `https://example.com/?id=12345`（key パターン非該当） | マスクしない（副規則の対象外） |
| ヘッダー文脈 `header[X-Custom-Auth]: <40+字>`（直前 `:` あり） | マスク（直前文字 `:` で文脈外条件成立、40+字でデフォルトマスク発動） |
| `header[X-Custom-Auth]: <30字>`（40 字未満） | マスクしない（規則ベース非該当 + デフォルトマスク 40 字閾値未達） |

#### **重要な例外（テーブル列単位）**

テーブルの `プラグイン名` 列・`マーケットプレイス名` 列・`結果` 列には
**規則ベース・デフォルトマスクともに一切適用しない**（プラグイン名・コミットハッシュ・
バージョン識別子の誤検知防止）。具体パターンも `備考` 列のみで適用する。

### 根拠

- 多層シークレット保護: 規則ベース（具体パターン）+ デフォルトマスク（汎用）の二段構え。
- 40 字閾値: コミットハッシュ短縮形（7〜8 字）・バージョン識別子（v2.x.0 等の数字主体）を
  避けつつ、API トークンの典型長（30〜80 字）をカバーするバランス値。
- 列単位の例外: プラグイン名は最大 64 字（XR-1 で制限）のため、デフォルトマスクが
  プラグイン名を伏せるリスクを構造的に排除する。

## XR-4: リトライ上限

### ルール

リトライは元の失敗集合に対し **最大 1 回**（合計 2 試行）。
リトライ中に新規発生した失敗は記録のみとし、再度 Phase G を起動しない。

### 適用詳細

- 「失敗集合」とは Phase F 時点の **Failed エントリのみ**。Missing は CLI リトライで回復しないため
  対象外（Phase F-4 でユーザに `enabledPlugins` 除外を促す）。Unknown は要手動確認のため対象外。
- リトライは G-3 で実施。サーキットブレーカー作動中の MP には適用しない。
- 2 回目失敗時は G-4 で最終結果として追記出力する。

### 根拠

- 無限ループ防止。
- 一過性のネットワーク・認証エラーは 1 回リトライで多くが解消する経験則。
- 慢性的な失敗（CLI 不在・認証情報破損等）に複数回リトライしても改善しないため、
  早期に手動調査へ委ねる方針。

## XR-5: Unknown 警告閾値

### ルール

Phase F-1 サマリで Unknown 件数が **試行済み（Skipped を除く）エントリの合計件数の 20%** を
超える場合、明示的な警告メッセージを併記する:

```text
警告: Unknown 件数が試行済み全体の 20% を超えています（<U>/<T> 件）。
CLI 出力フォーマットが変わった可能性があるため、F-2/F-3 の備考列を確認し、
必要なら個別に手動更新してください。
```

### 全体件数の定義

「試行済み件数 `<T>`」は、A-1 / A-2 で Skipped 除外されたエントリを含まない、
実際に CLI 呼び出しが行われたエントリの合計（マーケットプレイス + 全スコーププラグイン）。

### 根拠

- 「正常に分類できないケースが過半数を占めるのは異常」という経験的閾値。
- Skipped を分母から除外する理由: A-2 の MP 整合性検証等で意図的に除外されたエントリは
  「実行しなかった」ものであり、Unknown 率の母数に含めると警告ノイズが増える。
