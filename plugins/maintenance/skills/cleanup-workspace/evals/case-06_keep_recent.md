# Case 06: keep-recent で最新 N 件保持

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | "30 日より古い workspace を削除、ただし最新 3 件は残して" |
| 引数 | `--days 30 --keep-recent 3` |
| フラグ | なし |
| 既存状態 | 30 日より古いセッションが各スコープに 5 件以上存在 |

## 期待動作

### Phase 1: 引数解析
- `--days 30`、`--keep-recent 3`

### Phase 2: 対象収集 + 古さ判定
- 通常通り 30 日より古いものを候補に追加

### Phase 3: keep-recent 適用
- スコープごとに `LastWrite` 降順にソート
- 各スコープで新しい順 3 件を候補から除外
- 「保護されたセッション: keep-recent: N 件」に件数記録

### Phase 4: 候補表示
- 残った候補のみ表示

### Phase 5 以降
- 対話モードで AskUserQuestion → 削除実行

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| 生成ファイル | なし |
| 削除実行 | 各スコープの新しい順 3 件以外が削除される |
| 標準出力（要約） | 「keep-recent: 3 件」「保護されたセッション: keep-recent: N 件」 |
| 終了状態 | 成功 |

## 分岐の根拠

このケースが分岐するトリガーは `--keep-recent` の値 > 0 である。`0` の場合（既定）は保護なし。

## エッジケース

| 状況 | 動作 |
|-----|------|
| 候補件数 < keep-recent 値 | すべて保護され、削除対象 0 件になる |
| 異なるスコープでの独立適用 | global と project のそれぞれで上位 N 件を保護 |
