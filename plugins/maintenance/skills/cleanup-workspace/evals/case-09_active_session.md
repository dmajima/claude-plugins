# Case 09: 進行中セッション保護

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | "古い作業フォルダを整理して" |
| 引数 | `--days 30` |
| フラグ | なし |
| 既存状態 | 30 日より古いと判定される（mtime ベース）が、`progress.md` の mtime が直近 5 分以内のセッションが存在<br>※連続実行中のタスクなど |

## 期待動作

### Phase 1: 対象収集
- セッションフォルダ自身の mtime ではなく、再帰的に全ファイルの最新 mtime を取得

### Phase 2: 進行中保護判定
- 各候補について `progress.md` の `LastWriteTimeUtc` を確認
- 現在時刻から 5 分以内なら候補から除外
- 「保護されたセッション: 進行中: N 件」にカウント

### Phase 3: 候補表示
- 進行中セッションは表示されない（保護件数のみサマリで表示）

### Phase 4 以降
- 通常通り削除実行（進行中分は除外済み）

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| 生成ファイル | なし |
| 削除実行 | 進行中セッション以外のみ削除 |
| 標準出力（要約） | 「保護されたセッション: 進行中: N 件」 |
| 終了状態 | 成功 |

## 分岐の根拠

このケースが分岐するトリガーは `progress.md` の `LastWriteTimeUtc > UtcNow - 5min` である。

## 5 分閾値の根拠

- Claude Code の典型的なタスク粒度（数十秒〜数分）に対し十分な保護幅
- `progress.md` は進行中タスクで頻繁に更新される運用前提
- ユーザが古いセッションを意図的に削除する場合、対象は通常 5 分以上未更新

## エッジケース

| 状況 | 動作 |
|-----|------|
| `progress.md` 不在 | 進行中判定はスキップ（mtime のみで判定） |
| `progress.md` の mtime > 5 分 | 通常通り削除候補に追加 |
| 強制削除フラグ | 設けない（事故防止のため）。手動で `progress.md` の更新を停止すれば削除可能 |
