# Case 10: `--include-tmp` で tmp 追加削除

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | "古い workspace を整理しつつ、全セッションの tmp も掃除して" |
| 引数 | `--days 30 --include-tmp` |
| フラグ | `--include-tmp` |
| 既存状態 | 30 日より古いセッション複数 + 新しいセッションの `workspace/tmp/` 配下にも一時ファイル多数 |

## 期待動作

### Phase 1: 引数解析
- `--include-tmp` → tmp 追加クリーンアップ有効

### Phase 2: 通常の削除フロー
- 30 日より古いセッションを通常通り削除（case-02 と同様）

### Phase 3: tmp 追加クリーンアップ
- 削除対象外のセッション（=新しい / 進行中保護 / keep-recent 保護）について、`workspace/tmp/` 配下のファイルを全削除
- `workspace/tmp/` 自体は残す
- バリデーション合格セッションのみ対象（不正パス・リンクは除外）

### Phase 4: サマリ出力
- 通常の削除サマリに加え、「tmp/ 掃除済み: N セッション」を表示

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| 生成ファイル | なし |
| 削除実行 | 古いセッション削除 + 新しいセッションの tmp ファイル削除 |
| **削除されないもの** | **セッションフォルダ本体（保持対象セッション）/ `workspace/tmp/` 自体のディレクトリ** |
| **削除されるもの** | 保持対象セッションの **`workspace/tmp/` 配下のファイル群のみ** |
| 標準出力（要約） | 「===== 削除結果 =====」+ 「tmp/ 掃除済み: N セッション」 |
| 終了状態 | 成功 |

### 境界（明示）

| 対象 | 削除有無 |
|-----|---------|
| 30 日より古いセッション本体 | 削除（通常フロー） |
| 新しいセッション（保持対象）の本体 | **保持** |
| 新しいセッションの `workspace/tmp/` ディレクトリ自体 | **保持** |
| 新しいセッションの `workspace/tmp/` 配下のファイル | **削除** |
| 進行中セッション（progress.md 5 分以内）の `workspace/tmp/` | 進行中保護のためスキップ可（仕様確認）|

## 分岐の根拠

このケースが分岐するトリガーは `--include-tmp` フラグ = 指定あり である。指定なしの場合は tmp 追加処理を行わない。

## 安全装置

- tmp 配下削除でもバリデーション必須（セッション名形式 + リンク種別）
- `workspace/tmp/` 自体は削除しない（配下のファイルのみ）
- ドライランモード（`--dry-run`）と併用した場合、tmp 削除もドライラン表示（実削除なし）

## 関連ケース

- `--include-tmp` 単独使用（古いセッションがないが tmp だけ掃除したい場合）も同じスクリプトでカバー
