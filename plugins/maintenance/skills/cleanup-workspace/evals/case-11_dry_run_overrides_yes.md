# Case 11: `--dry-run` と `--yes` 同時指定（dry-run 優先）

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | "30 日より古い workspace を dry-run と yes 両方付けて確認" |
| 引数 | `--days 30 --dry-run --yes` |
| フラグ | `--dry-run --yes`（両方指定） |
| 既存状態 | 30 日より古いセッションフォルダが存在 |

## 期待動作

### Phase 1: 引数解析 + 優先順位判定
- `--dry-run` と `--yes` の同時指定を検出
- 警告ログ「--DryRun と --Yes を同時指定: --DryRun を優先（実削除は行いません）」を出力
- 内部的に `$Yes = $false` に強制設定

### Phase 2 以降: ドライランフロー
- 通常通り対象収集 → 候補表示
- AskUserQuestion は発火しない（dry-run のため）
- 実削除は行わない（exit 0）

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| 生成ファイル | なし |
| 削除実行 | なし |
| 標準出力（要約） | 警告「--DryRun と --Yes を同時指定: --DryRun を優先」 + 候補一覧 + 「(dry-run) 実削除は行いません。」 |
| 終了状態 | 成功（exit 0） |

## 分岐の根拠

このケースが分岐するトリガーは `--dry-run` フラグ AND `--yes` フラグの両方が指定された場合である。意図しない実削除を防ぐため、`--dry-run` を優先する。

## 安全装置の意義

- ユーザがスクリプトラッパ・CI 等から両方指定した場合の事故防止
- 「とりあえず両方つけておけば安全」という誤解からくる削除を抑止
- 警告ログを必ず出力し、優先順位を明示
