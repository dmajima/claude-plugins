# Case 19: 削除途中の権限エラー / ロック発生時の続行

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | "古い作業フォルダを整理して（CI で自動実行）" |
| 引数 | `--days 30 --yes` |
| フラグ | `--yes` |
| 既存状態 | 30 日より古いセッション 5 件のうち、1 件が読み取り専用属性 / 別プロセスでロック中 / アクセス権限なし のいずれか |

## 期待動作

### Phase 1〜3: 通常通り
- 引数解析・候補収集・進行中保護判定

### Phase 4: 削除実行（部分失敗）
- 候補 5 件を順次 `Remove-Item -Recurse -Force -ErrorAction Stop` で削除
- 4 件は成功
- 1 件は `Remove-Item` が例外を投げる（権限エラー / ロックエラー）
- 該当セッションは `$failed` 配列に `Path / Error` で追加
- **残りの候補は続行され、削除を完了する**

### Phase 5: サマリ出力
- "削除完了: 4 件" を出力
- "失敗: 1 件" を出力
- 失敗一覧:
  ```
  失敗一覧:
    FAILED <path>
            <error message>
  ```
- 解放容量: 成功 4 件分のみ集計

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| 削除完了件数 | 4（5 件中） |
| 失敗件数 | 1 |
| 失敗詳細 | Path + Exception.Message の各 1 行 |
| 終了状態 | exit ≠ 0（失敗 1 件以上のため）|

## 分岐の根拠

このケースが分岐するトリガーは `Remove-Item` の例外発生 + try/catch による継続 である。
safety.md 節 6「失敗時の続行」の仕様を回帰テストとして固定する。

## 設計意図

CI / 非対話モード（`--yes` 経由）で 1 件の障害（権限不足 / ロック）が全体を止めると
バックアップディレクトリの肥大化が止まらず運用に支障する。1 件失敗で残りは続行する
仕様を eval として独立保証する。
