# Case 10: `--no-backup` でバックアップなし

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | "バックアップなしで同期して" |
| 引数 | `--repo ... --no-backup --yes` |
| フラグ | `--no-backup --yes` |
| 既存状態 | 通常 |

## 期待動作

### Phase 6: バックアップ取得をスキップ
- `--no-backup` 指定のため、バックアップディレクトリは作成されない
- 警告ログ出力: 「--NoBackup 指定: バックアップを取得しません。」

### Phase 7: 同期適用
- 通常通り同期

### Phase 9: サマリ
- 「バックアップ: なし (--NoBackup)」と明示表示

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| 生成ファイル | 同期成果物のみ（バックアップディレクトリは作成されない） |
| 標準出力（要約） | 「バックアップ: なし (--NoBackup)」「警告: バックアップを取得しません」 |
| 終了状態 | 成功 |

## 分岐の根拠

このケースが分岐するトリガーは `--no-backup` フラグ = 指定あり である。

## 安全装置

- 警告ログを必ず出力する
- ロールバック手段がないことを README に明記する
- 対話モードでは AskUserQuestion で「バックアップなしで本当に同期しますか？」を追加確認する（推奨。本実装では引数指定時はスキップ）

## ロールバック不可

このモードで同期した場合、自動ロールバック手段はない:

- バックアップディレクトリが存在しない
- OS の復元機能（Windows ファイル履歴、Time Machine 等）が有効ならそれを利用
- ない場合は、リモート repo のコミット履歴から手動でファイルを取り出して復旧
