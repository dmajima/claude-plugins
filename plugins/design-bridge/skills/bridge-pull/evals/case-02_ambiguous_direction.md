# Case 02: 方向が曖昧な指示（自動起動せず方向を確認）

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | 「デザイン、同期しておいて」 |
| 引数 | なし |
| フラグ | なし（対話モード） |
| 既存状態 | `.claude/design-bridge.json` あり。design-system 認可済み。`pending.tsv` に `mock` 1 行・`spec` 1 行。`last-push.json` あり。リモートには `last-push.json` に記録が無いファイルが 1 件ある（どちらの方向にも差分が存在しうる状態） |

## 期待動作

### Phase 1: 明示指示の確認（本ケースの中心）

- 「同期して」という発話には方向（ローカル → リモート / リモート → ローカル）が含まれていないことを認識する
- bridge-pull は **ユーザーの明示的な指示があるときにのみ実行する** スキルであるため、この発話を取り込み指示として解釈しない
- 照合も取り込みも開始せず、`AskUserQuestion` でどちらの方向かを確認する
- 選択肢として、ローカル正本を Claude Design へ反映する `bridge-push` と、Claude Design の内容をローカルへ取り込む `bridge-pull` を提示する
- **既定は `bridge-push`（ローカル正本）** として提示する
- 方向が確定するまで `list_files` / `get_file` を呼ばない（`last-push.json` を含むローカル状態ファイルの読み出しも、照合を始める前の段階では不要）

### Phase 2 以降: 確認結果に応じた分岐

| ユーザーの選択 | 動作 |
|--------------|------|
| `bridge-push`（既定） | bridge-pull を実行せず、`bridge-push` へ引き継ぐ。ローカルの書き換えは一切行わない |
| `bridge-pull` | ここで初めて明示指示が成立する。case-01 の Phase 2 以降（作業ツリー確認 → 基準点を使った照合 → 差分提示 → 承認 → 取り込み）に進む |
| 状態だけ見たい | `bridge-status`（読み取り専用）を案内する。ローカルもリモートも変更しない |
| どちらでもない / 中止 | 何も実行せず終了する |

### 禁止される挙動

- 確認を経ずに `list_files` / `get_file` の結果でローカルを上書きすること
- 「リモートに `last-push.json` が知らないファイルがあるから」という理由だけで取り込みを自動実行すること
- 方向確認を省略し、既定を `bridge-pull` として扱うこと
- 方向が未確定のまま `pending.tsv` / `block-count` / `dismissed` / `last-push.json` を書き換えること

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| ユーザへの確認 | 1 回（`AskUserQuestion` による方向確認。既定は `bridge-push`） |
| 更新ファイル | なし（確認前の時点でローカルを一切書き換えない） |
| `DesignSync` 呼び出し | 方向が確定するまで 0 件（`list_files` / `get_file` とも呼ばない） |
| 状態ファイル | `pending.tsv` / `block-count` / `dismissed` / `last-push.json` のいずれも不変 |
| 標準出力（要約） | 方向が曖昧である旨と、`bridge-push` / `bridge-pull` / `bridge-status` の選択肢の提示 |
| 終了状態 | 確認待ち（選択後に該当スキルへ分岐） |

## 分岐の根拠

このケースが分岐するトリガーは 明示指示 = 不明瞭（方向が読み取れない発話） である。SKILL.md のトリガー条件に「ユーザーが取り込みを明示していない（**自動起動してはならない**）」と定められており、実行フロー 1 で「文脈が曖昧な場合は、どちらの方向かを `AskUserQuestion` で確認する。既定は `bridge-push`（ローカル正本）とする」と規定されている。

design-bridge の正本はローカルであり、pull はその正本を書き換える例外操作である。曖昧な指示を取り込みと解釈すると、ユーザーが意図しないタイミングで正本が失われうるため、既定を push 側に倒すことが安全側の設計になっている。
