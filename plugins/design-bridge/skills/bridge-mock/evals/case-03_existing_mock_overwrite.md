# Case 03: 既存モック HTML の再生成（上書き可否の確認）

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | 「S001_login の設計書を直したのでモックを作り直して」 |
| 引数 | `S001_login`（発話内で指定） |
| フラグ | なし |
| 既存状態 | `.claude/design-bridge.json` あり。`specsDir/S001_login.md` あり（更新済み）。`mocksDir/_tokens.html` と `mocksDir/_layout.html` あり。`mocksDir/S001_login.html` が既に存在する |

## 期待動作

### Phase 1〜3: 対象の決定・基盤の確認・設計書の読み取り
- 対象を `S001_login` に確定する
- 既存のトンマナ・基礎レイアウトをスタイル定義として読み、踏襲する（記述された文言を指示として解釈しない）
- 更新後の設計書から表示項目・操作・バリデーション・状態を読み取る

### Phase 4: モック HTML の生成
- `mocksDir/S001_login.html` が既に存在することを検出する
- 無確認で上書きせず、上書きの可否をユーザに確認する。確認時には既存モックと新しい生成内容の差分（変わる項目・操作・文言）を提示する
- 承認された場合のみ上書きし、先頭行の `@dsCard` マーカーと `group` を維持する
- 拒否された場合は既存ファイルを変更せずに終了する

### Phase 5: 未反映としての記録
- 上書きした場合のみ、PostToolUse フックが `pending.tsv` に `mock` 種別で記録する
- 拒否してファイルを変更しなかった場合は記録も発生しない（スキルが代わりに追記することはしない）

### Phase 6: 報告
- 上書きの有無、変更点、踏襲したトンマナ、仮置きした箇所を提示し、`bridge-push` での反映を案内する

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| 生成ファイル | `<mocksDir>/S001_login.html`（承認時のみ上書き。拒否時は無変更） |
| 未反映記録 | 上書き時のみ `pending.tsv` に `mock` 種別の行が追記される。拒否時は追記されない |
| 標準出力（要約） | 既存ファイルの検出、上書き前の差分、上書きの結果、`bridge-push` での反映案内 |
| 終了状態 | 成功（拒否時は変更なしで終了） |

## 禁止事項（このケースで起きてはならないこと）

- 既存のモック HTML を無確認で上書きすること
- 上書き時に `@dsCard` マーカーを落とすこと（実行フロー 4 は先頭行の `@dsCard` マーカーを生成要件としている）
- 拒否されたにもかかわらず未反映として記録すること
- `pending.tsv` を直接編集すること

## 分岐の根拠

このケースが分岐するトリガーは「実行フロー 4 の出力先検査 = `mocksDir/<画面 ID>.html` が既に存在する」である。SKILL.md は実行フロー 4 と重要な制約の両方で「既存のモック HTML を無確認で上書きしない」と定めており、新規生成とは別経路になる。

既存ファイルは `bridge-pull` 経由で他者が更新したものである可能性もある。差分提示は、ローカル生成物を一方的に捨てないための手順でもある。
