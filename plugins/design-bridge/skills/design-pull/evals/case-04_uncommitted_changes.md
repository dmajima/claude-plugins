# Case 04: mocksDir に未コミット変更がある（警告して判断を仰ぐ。拒否なら中断）

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | 「Claude Design の変更を取り込んで」 |
| 引数 | なし |
| フラグ | なし（対話モード） |
| 既存状態 | `.claude/design-bridge.json` あり。design-system 認可済み。`mocks/S001_login.html` と `mocks/S002_home.html` にコミットしていない編集が残っている。`last-push.json` あり（両ファイルとも記録ありだが、ローカル現物は記録と食い違う）。リモートにも同名のカードが存在する |

## 期待動作

### Phase 1: 明示指示の確認

- 取り込み方向が明示されているため、方向確認には分岐せず実行に進む

### Phase 2: 作業ツリーの確認（本ケースの中心）

- `git status` を確認する
- `mocksDir` 配下に未コミットの変更があることを検出する（`mocks/S001_login.html`、`mocks/S002_home.html`）
- 取り込みは対象ファイルを上書きするため、これらの未コミット変更が失われうることを **警告する**
- 警告には、どのファイルが未コミットかを具体的に列挙する
- ユーザーの判断を仰ぐ。少なくとも次の選択肢を提示する

| 選択肢 | 動作 |
|-------|------|
| 中止する | 何も書き換えず終了する。先にコミットまたは退避するよう案内する |
| 未コミット変更のないファイルのみ取り込む | 衝突しない対象に限定して Phase 3 以降へ進む |
| 承知のうえで続行する | 上書きで失われることを理解したうえで Phase 3 以降へ進む |

- 警告を出さずに取り込みを開始してはならない
- ユーザーに代わって `git` のコミット・stash・checkout 等を実行しない

### Phase 3 以降: 判断に応じた進行

- **「中止する」が選ばれた場合**（本ケースの既定の経路）

| 項目 | 動作 |
|-----|------|
| 照合 | 行わない。`last-push.json` の読み出し以降へ進まず、`list_files` / `get_file` を呼ばない |
| ローカル | 一切変更しない。モック HTML・設計書・スクリーンショットのいずれにも触れない |
| 状態ファイル | `pending.tsv` / `block-count` / `dismissed` / `last-push.json` を変更しない |
| 報告 | 未コミット変更があったこと、ユーザーが中止を選んだこと、コミットまたは退避後の再実行を案内する |
| 終了状態 | 中断 |

- **続行が選ばれた場合**は、case-01 と同じく「基準点を使った照合 → 差分提示 → 承認 → 取り込み → フックによる `pending.tsv` 記録」の順に進む
- 続行する場合でも、Phase 4 の差分提示と承認は省略しない（警告への同意は取り込み内容への承認を兼ねない）

### Phase 7: 報告

- 未コミット変更があった旨と、それに対してユーザーが選んだ扱いを報告に含める

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| ユーザへの確認 | 1 回以上（未コミット変更の警告と扱いの確認）。続行時はさらに取り込み承認 |
| 警告内容 | 未コミット変更のあるファイルの列挙と、上書きで失われる旨の明示 |
| `DesignSync` 呼び出し | 中止時は 0 件。続行時は case-01 と同じく `list_files` と絞り込んだ `get_file` |
| 更新ファイル | 中止時はなし。続行時は承認された対象のみ |
| git 操作 | 行わない（コミット・stash・checkout をスキルが代行しない） |
| 標準出力（要約） | 未コミット変更の警告、選ばれた扱い、取り込み結果または中断の報告 |
| 終了状態 | 中断（中止選択時）または成功（続行選択時） |

## 分岐の根拠

このケースが分岐するトリガーは `git status` の結果 = `mocksDir` 配下に未コミット変更あり である。SKILL.md の前提 4「作業ツリーがクリーンであること（上書きで未コミットの変更を失わないため）」が満たされていない状態にあたり、実行フロー 2 で「上書きで失われる旨を警告してユーザーの判断を仰ぐ。承認が得られなければ中断する」と規定されている。

未コミットの編集は復元手段が無く、取り込みによる上書きは不可逆である。そのため前提違反を検出した時点で自動進行を止め、判断を人間に返すのが正しい振る舞いになる。中止が選ばれた場合に「ローカルを一切変更しない」で終わる点は、認可エラー時（case-06）と同じ不変条件である。
