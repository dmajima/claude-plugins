# Evals: design-pull

このディレクトリは `design-pull` スキルの動作分岐ごとの期待挙動を定義するケース集。各ケースは仕様書として機能する（`DesignSync` への実アクセスと対話承認を伴うため、自動実行フロントマターは付与しない）。

## ケース一覧

| ケース | 内容 | 主な分岐根拠 |
|-------|-----|-------------|
| [case-01_interactive_full_scan.md](case-01_interactive_full_scan.md) | 引数なし。全件照合して差分を要約提示し、承認された分だけ取り込む。ローカルのみに存在するファイルは取り込まない | 引数 = なし → 対話モード・全件照合 |
| [case-02_ambiguous_direction.md](case-02_ambiguous_direction.md) | 「同期して」など方向が読み取れない発話。`AskUserQuestion` で方向を確認し、既定は `design-push`。取り込みを自動実行しない | 明示指示 = 不明瞭 → 方向確認への分岐（自動起動の禁止） |
| [case-03_non_interactive_path.md](case-03_non_interactive_path.md) | パスを引数で明示。対象は該当ファイルのみに絞られるが、差分提示と承認は省略されない | 引数 = パス → 非対話モード（承認は維持） |
| [case-04_uncommitted_changes.md](case-04_uncommitted_changes.md) | `mocksDir` 配下に未コミットの変更がある。上書きで失われる旨を警告し、ユーザーの判断を仰ぐ | `git status` の結果 = `mocksDir` 配下に未コミット変更あり |
| [case-05_pending_preserved.md](case-05_pending_preserved.md) | 既に `pending.txt` にエントリがある状態で取り込む。既存エントリを保持したまま取り込んだパスを追記し、クリアしない | 取り込み完了後の整合処理（`pending.txt` 不変条件） |

## カバレッジ

| 観点 | 対応ケース |
|-----|----------|
| 対話モード | case-01、case-02、case-04 |
| 非対話モード | case-03 |
| 起動条件の分岐（明示指示の有無） | case-02 |
| 前提条件の不足（作業ツリー） | case-04 |
| 取り込み後の後処理 | case-05 |
| 承認の省略禁止 | case-01（対話）、case-03（非対話） |

## 中心的な不変条件

design-pull はローカル正本を書き換える例外操作であるため、次の 3 点がケース横断で検証される。

1. **ユーザーの明示的な指示なしに実行しない**（case-02）
2. **差分提示と承認を経ずにローカルを上書きしない**（case-01、case-03、case-04）
3. **取り込み後に `pending.txt` をクリアしない**（case-01、case-03、case-05）

3 点目は、取り込んだモックに対応するスクリーンショットと設計書が古いまま残るためである。`design-push` による整合の取り直しが完了するまで、未反映の記録を消してはならない。

## 実行確認方法

各ケースの「入力」セクションのフレーズで Claude Code を起動し、「期待動作」「期待出力」と一致することを目視確認する。

- `DesignSync` への実アクセスを伴うため、検証用の design-system プロジェクトに対して実施する
- 各ケースの確認後は、`.claude/.local/plugins/design-bridge/pending.txt` が削除されていないことをファイルシステム上で確認する
- 差分提示の要約品質と承認 UI（`AskUserQuestion`）の実発火は機械検証の射程外のため、人間レビューで確認する
- case-04 の確認では、検証用リポジトリで `mocksDir` 配下にあえて未コミット変更を作ってから実行する

## ケース追加ルール

起動条件（明示指示の判定）、照合・差分提示の規則、取り込み後の `pending.txt` の扱いのいずれかを変更した場合は、対応するケースを必ず追加・更新する。
