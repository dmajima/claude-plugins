# Case 02: 方向が曖昧な指示（自動起動せず方向を確認）

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | 「デザイン、同期しておいて」 |
| 引数 | なし |
| フラグ | なし（対話モード） |
| 既存状態 | `.claude/design-bridge.json` あり。design-system 認可済み。`pending.txt` に未反映 2 件。リモートにもローカルが知らないファイルが 1 件ある（どちらの方向にも差分が存在する） |

## 期待動作

### Phase 1: 明示指示の確認（本ケースの中心）
- 「同期して」という発話には方向（ローカル → リモート / リモート → ローカル）が含まれていないことを認識する
- design-pull は **ユーザーの明示的な指示があるときにのみ実行する** スキルであるため、この発話を取り込み指示として解釈しない
- 照合も取り込みも開始せず、`AskUserQuestion` でどちらの方向かを確認する
- 選択肢として、ローカル正本を Claude Design へ反映する `design-push` と、Claude Design の内容をローカルへ取り込む `design-pull` を提示する
- **既定は `design-push`（ローカル正本）** として提示する

### Phase 2 以降: 確認結果に応じた分岐

| ユーザーの選択 | 動作 |
|--------------|------|
| `design-push`（既定） | design-pull を実行せず、`design-push` へ引き継ぐ。ローカルの書き換えは一切行わない |
| `design-pull` | ここで初めて明示指示が成立する。case-01 の Phase 2 以降（作業ツリー確認 → 照合 → 差分提示 → 承認 → 取り込み）に進む |
| どちらでもない / 中止 | 何も実行せず終了する。状態だけ見たい場合は `design-status` を案内してよい |

### 禁止される挙動
- 確認を経ずに `list_files` / `get_file` の結果でローカルを上書きすること
- 「リモートに差分があるから」という理由だけで取り込みを自動実行すること
- 方向確認を省略し、既定を `design-pull` として扱うこと

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| ユーザへの確認 | 1 回（`AskUserQuestion` による方向確認。既定は `design-push`） |
| 更新ファイル | なし（確認前の時点でローカルを一切書き換えない） |
| 外部呼び出し | 方向が確定するまで取り込みのための `get_file` を行わない |
| 標準出力（要約） | 方向が曖昧である旨と、`design-push` / `design-pull` の選択肢の提示 |
| 終了状態 | 確認待ち（選択後に該当スキルへ分岐） |

## 分岐の根拠

このケースが分岐するトリガーは 明示指示 = 不明瞭（方向が読み取れない発話） である。SKILL.md のトリガー条件に「ユーザーが取り込みを明示していない（**自動起動してはならない**）」と定められており、実行フロー 1 で「文脈が曖昧な場合は、どちらの方向かを `AskUserQuestion` で確認する。既定は `design-push`（ローカル正本）とする」と規定されている。

design-bridge の正本はローカルであり、pull はその正本を書き換える例外操作である。曖昧な指示を取り込みと解釈すると、ユーザーが意図しないタイミングで正本が失われうるため、既定を push 側に倒すことが安全側の設計になっている。
