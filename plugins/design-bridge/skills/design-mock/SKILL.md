# design-mock

Markdown の画面設計書を入力に、トンマナ（`_tokens.html`）と基礎レイアウト（`_layout.html`）に準拠した画面モック HTML を生成する。

## 責務

- トンマナ（デザイントークン）と基礎レイアウトの雛形を生成する
- 画面設計書の記述から画面モック HTML を生成する
- 生成した HTML に `@dsCard` マーカーを付与する
- 生成結果を未反映として記録し、`design-push` へ繋ぐ

## 責務外（他スキルが担当）

| 業務 | 担当スキル |
|-----|----------|
| claude.ai/design への反映・スクショ生成 | `design-push` |
| claude.ai/design からの取り込み | `design-pull` |
| 導入・ディレクトリ構成作成 | `design-init` |
| 設計書（Markdown）本文の執筆 | （ユーザーまたは通常の編集作業） |

## トリガー条件

- 「ログイン画面のモックを作って」「設計書からモックを起こして」
- 「トンマナを作って」「基礎レイアウトを用意して」
- 新しい画面設計書を追加した直後

このスキルを起動しないケース:

- モックは既にあり反映したいだけ（→ `design-push`）
- 導入が済んでいない（→ `design-init`）

## 前提

1. `.claude/design-bridge.json` が存在すること
2. 対象画面の Markdown 設計書が `specsDir` にあること（トンマナ生成時は不要）

## 実行モード判定

| 入力 | モード | 動作 |
|-----|-------|------|
| 画面 ID を引数で指定 | 非対話 | 該当画面のモックを生成 |
| `--tokens` / `--layout` | 非対話 | トンマナ / 基礎レイアウトの雛形を生成 |
| 上記以外 | 対話 | 対象画面と、既存ファイルがある場合の上書き可否を確認 |

## 実行フロー

### 1. 対象の決定

引数または対話で対象画面を決める。`specsDir` に対応する Markdown が無い場合は、先に設計書を用意するよう促す。

### 2. 基盤の確認

`mocksDir/_tokens.html` と `mocksDir/_layout.html` の有無を確認する。

| 状況 | 動作 |
|-----|------|
| 両方ある | それを読み、色・タイポグラフィ・余白・コンポーネント定義を踏襲する |
| 無い | 先にトンマナと基礎レイアウトを生成してよいかユーザーに確認する |

画面モックは必ず既存のトンマナに従わせる。画面ごとに独自の色やサイズを導入しない。

### 3. 設計書の読み取り

対象の Markdown から、画面に必要な情報を抽出する。

- 画面名・画面 ID
- 表示項目とその属性（必須・任意、型、桁数）
- 操作（ボタン・リンク）と遷移先
- バリデーション・エラー表示
- 状態（初期表示・入力中・エラー・完了）

設計書に記載が無い項目を勝手に作り込まない。不足がある場合は、仮置きした箇所を生成後の報告で明示する。

### 4. モック HTML の生成

`mocksDir/<画面 ID>.html` を生成する。要件は次のとおり。

| 要件 | 内容 |
|-----|------|
| 先頭行 | `<!-- @dsCard group="画面" -->`（group は設計書の分類に合わせる） |
| スタイル | `_tokens.html` のトークンを参照。画面固有の値をハードコードしない |
| 構造 | `_layout.html` の骨格に沿う |
| 内容 | 設計書に書かれた項目・操作・状態を反映する |
| 文言 | 設計書の文言をそのまま使う（創作しない） |
| 外部参照 | CDN 等の外部リソースに依存しない（オフラインで開けること） |

既存ファイルがある場合は、無確認で上書きしない。

### 5. 未反映としての記録

生成・更新したパスを `.claude/.local/plugins/design-bridge/pending.txt` に追記する（PostToolUse フックが拾うため通常は自動。フック未適用の環境では明示的に追記する）。

### 6. 報告

生成したファイル、踏襲したトンマナ、設計書に記載が無く仮置きした箇所を提示し、`design-push` での反映を案内する。

## 重要な制約

- 既存のモック HTML を無確認で上書きしない
- トンマナを無視した独自スタイルを画面モックに持ち込まない
- 設計書に無い機能・項目を創作しない（仮置きする場合は必ず報告する）
- 外部 CDN への依存を持ち込まない（Claude Design 上での表示とオフライン閲覧のため）
- スクリーンショット生成は行わない（`design-push` の責務）
