# Evals: design-mock

このディレクトリは `design-mock` の動作分岐の期待挙動を例示する。

## ケース一覧

| ケース | 内容 | 主な分岐根拠 |
|-------|-----|-------------|
| [case-01](case-01_screen_id_with_tokens.md) | 画面 ID 指定でのモック生成（非対話・トンマナ既存） | 実行モード判定 = 画面 ID を引数で指定 + 実行フロー 2 の「両方ある」 |
| [case-02](case-02_tokens_layout_missing.md) | トンマナ・基礎レイアウト未整備（対話で雛形生成の可否を確認） | 実行フロー 2 の「無い」 |
| [case-03](case-03_existing_mock_overwrite.md) | 既存モック HTML の再生成（上書き可否の確認） | 実行フロー 4 の「既存ファイルがある場合」 |
| [case-04](case-04_spec_not_found.md) | 対象の設計書が `specsDir` に無い（生成せず用意を促す） | 実行フロー 1 の「対応する Markdown が無い場合」 |

## カバレッジ対応

| 必須カバレッジ | 対応ケース |
|--------------|----------|
| 対話モード | case-02 / case-03 |
| 非対話モード | case-01（画面 ID 指定）/ case-02 で言及する `--tokens` `--layout` |
| 主要分岐の各ブランチ | case-01（基盤あり）/ case-02（基盤なし）/ case-03（出力先に既存ファイルあり） |
| エラー系（既知） | case-04 |

実行モード判定表の `--tokens` / `--layout`（雛形のみを確認なしで生成する非対話経路）は、case-02 の「分岐の根拠」「関連ケース」で同じ雛形生成の非対話版として記述している。前提 1（`.claude/design-bridge.json` の存在）が満たされない場合の `design-init` への誘導は case-04 で前提不足の兄弟分岐として扱う。

## 実行確認方法

各ケースの「入力」セクションのフレーズで Claude Code を起動し、「期待動作」「期待出力」と一致することを目視確認する。

本スキルは設計書の記述内容と既存トンマナに依存する AI 主導スキルのため、自動実行スクリプト（`demo.sh`）は適用外とし、目視確認を基本とする。生成 HTML については次の 4 点を機械的に確認できる。

- 先頭行に `<!-- @dsCard group="..." -->` があること
- 外部 CDN への参照（`http://` / `https://` で始まる `src` / `href`）が無いこと
- 画面固有の色・サイズがハードコードされておらず、トンマナのトークンを参照していること
- 生成パスが `.claude/.local/plugins/design-bridge/pending.txt` に記録されていること

## ケース追加ルール

新しい分岐ロジックを追加した時は、対応するケースファイル（`case-{2 桁番号}_{snake_case 名}.md`）を必ず追加し、本一覧表を同期する。各ケースには「分岐の根拠」「関連ケース」セクションを含める。
