# Case 04: 前提チェック NG で中断

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | 「ログイン画面のモックを作って」（パターン A）／ `/design-mock S999_report`（パターン B） |
| 引数 | なし（A）／ `S999_report`（B・画面 ID） |
| フラグ | なし |
| 既存状態 | 前提のいずれかが不成立。**A**: `.claude/design-bridge.json` が無い（design-bridge 未導入）。**B**: 設定はあるが `specsDir` に対象設計書 `S999_report.md` が無い（`mocksDir/_tokens.html` と `mocksDir/_layout.html` はある） |

本ケースは「前提チェックで NG を検出したら、何も生成せずに中断する」という単一の分岐を扱う。NG になりうる箇所が前提 1 と前提 2 の 2 つあるため、入力をその 2 パターンで示す。検査の順序どおり、前提 1 が NG ならそこで止まり、前提 2 の検査には進まない。

## 期待動作

### Phase 0: 前提 1 の確認（パターン A で NG）
- `.claude/design-bridge.json` の有無を最初に確認する
- 無い場合、`specsDir` / `mocksDir` を解決できないため本スキルを進めない
- `design-init` による導入を案内して中断する
- フックも未導入のため、仮にファイルを作っても未反映として記録されないことを併せて伝える

### Phase 1: 対象の決定（前提 2 の確認・パターン B で NG）
- `.claude/design-bridge.json` から `specsDir` を解決する
- `specsDir` に `S999_report` に対応する Markdown が無いことを検出する
- 先に設計書を用意するようユーザに促す
- `specsDir` にある既存の設計書一覧を提示し、画面 ID の取り違えであれば選び直せるようにする

### 以降の Phase（両パターンに共通）
- 基盤の確認・モック HTML の生成・未反映としての記録は **実行しない**
- 設計書が無い状態で画面構成を推測して生成することはしない

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| 生成ファイル | なし。A では `_tokens.html` / `_layout.html` / 画面モックのいずれも作らず、B では `<mocksDir>/S999_report.html` を作らない |
| 未反映記録 | 追記なし（A では状態ディレクトリ自体を作らない） |
| 案内先 | A は `design-init` による導入、B は対象設計書の作成 |
| 標準出力（要約） | 不成立だった前提の内容、上記の案内先、整えてから再実行する案内。B ではあわせて `specsDir` の既存設計書一覧 |
| 終了状態 | 中断（未生成） |

## 禁止事項（このケースで起きてはならないこと）

- 未導入のまま `mocks/` を推測して作り、あたかも導入済みのように振る舞うこと
- `.claude/design-bridge.json` を本スキルが代わりに生成すること（`design-init` の責務）
- 設計書が無いまま画面名から内容を推測してモックを生成すること（重要な制約「設計書に無い機能・項目を創作しない」に反する）
- 空のモック HTML を作って未反映として記録すること（Stop フックが実体のない反映を促す状態になるため）
- `pending.tsv` に手で追記すること

## 分岐の根拠

このケースが分岐するトリガーは「前提チェックの結果 = 不成立」である。SKILL.md の前提セクションは次の 2 項目を定め、いずれも NG 時の帰結を「中断」としている。

1. `.claude/design-bridge.json` が存在すること。無ければ `design-init` を案内して中断する
2. 対象画面の Markdown 設計書が `specsDir` にあること（トンマナ生成時は不要）

2 つの入力パターンを 1 ケースとして扱うのは、検査箇所が違うだけで分岐そのもの（前提不成立 → 生成なし・記録なし・中断）が同一であり、検証すべき不変条件も案内先の文言を除いて共通だからである。ケースを分ける必要が生じるのは、どちらかの経路で結末が変わる仕様になった場合である。

なお前提 2 の但し書き「トンマナ生成時は不要」のとおり、`--tokens` / `--layout` の単体指定では設計書が無くても中断しない（case-05）。
