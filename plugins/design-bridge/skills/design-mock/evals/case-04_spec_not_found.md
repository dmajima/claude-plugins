# Case 04: 対象の設計書が specsDir に無い（生成せず用意を促す）

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | `/design-mock S999_report` |
| 引数 | `S999_report`（画面 ID） |
| フラグ | なし |
| 既存状態 | `.claude/design-bridge.json` あり。`mocksDir/_tokens.html` と `mocksDir/_layout.html` あり。`specsDir` に `S999_report.md` が存在しない |

## 期待動作

### Phase 1: 対象の決定
- `specsDir` に `S999_report` に対応する Markdown が無いことを検出する
- 先に設計書を用意するようユーザに促す
- `specsDir` にある既存の設計書一覧を提示し、画面 ID の取り違えであれば選び直せるようにする

### 以降の Phase
- 基盤の確認・モック HTML の生成・未反映としての記録は **実行しない**
- 設計書が無い状態で画面構成を推測して生成することはしない

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| 生成ファイル | なし（`<mocksDir>/S999_report.html` を作らない。未反映リストにも追記しない） |
| 標準出力（要約） | 対象設計書が `specsDir` に見つからない旨、`specsDir` の既存設計書一覧、設計書を用意してから再実行する案内 |
| 終了状態 | 中断（未生成） |

## 禁止事項（このケースで起きてはならないこと）

- 設計書が無いまま画面名から内容を推測してモックを生成すること（重要な制約「設計書に無い機能・項目を創作しない」に反する）
- 空のモック HTML を作って未反映として記録すること（Stop フックが実体のない反映を促す状態になるため）

## 分岐の根拠

このケースが分岐するトリガーは「実行フロー 1 の対象決定 = `specsDir` に対応する Markdown が無い」である。SKILL.md は「`specsDir` に対応する Markdown が無い場合は、先に設計書を用意するよう促す」と定めており、前提 2（対象画面の Markdown 設計書が `specsDir` にあること）の NG パスにあたる。

同じ前提不足の兄弟分岐として、前提 1 の `.claude/design-bridge.json` が存在しない場合がある。この場合は `specsDir` / `mocksDir` の解決自体ができないため、本スキルを進めずに `design-init` での導入を案内する。
