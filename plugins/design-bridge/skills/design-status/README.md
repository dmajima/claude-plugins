# design-status (skill)

ローカル正本（Markdown の画面設計書・モック HTML）と claude.ai/design の同期状況を、**何も変更せずに** 報告するスキルです。未反映の一覧と、リモートとのドリフト（ずれ）を分類して提示します。

## このドキュメントについて

このファイルは **人間向けのリファレンス** です。Claude Code がスキル動作中に参照することはありません。スキル動作の本体は `SKILL.md` を参照してください。

## なぜこのスキルがあるのか

design-bridge は、Markdown の画面設計書・ローカルのモック HTML・claude.ai/design 上のカードが食い違うことを防ぐためのプラグインです。正本（SSOT）は常にローカルにあり、Claude Design は表示・承認用の鏡として扱います。

ところが `DesignSync` には **リモート変更の通知機構（watch）がありません**。Claude Design 側で誰かがカードを直しても、こちらには何も届きません。したがってドリフトを検出する手段は、「明示的に実行したときの全件照合」しかありません。

その照合を行えるスキルは 2 つありますが、性質が異なります。

| スキル | 照合後の動作 | リスク |
|-------|------------|-------|
| `design-pull` | 承認を得てローカルを上書きする | 未コミットのローカル変更を失う可能性がある |
| `design-status` | **何もしない（報告のみ）** | なし |

`design-status` は、この照合を **読み取りだけで** 行う入口です。「今どうなっているか」を知りたいだけのときに、ローカルを書き換えうる `design-pull` を使う必要はありません。`design-push` / `design-pull` を実行する前に影響範囲を把握する用途にも使えます。

## 責務（要約）

- 未反映リスト（`pending.tsv`）の内容を一覧表示する
- リモートとローカルを照合し、ドリフトを分類して検出する
- 連続ブロックカウンタ（`block-count`）の状態を表示する
- 次に取るべきアクション（`design-push` / `design-pull`）を提案する

変更は一切行いません。詳細は「読み取り専用の保証」を参照してください。

## 導入手順

### 前提

- Claude Code がインストール済み
- `design-bridge` プラグインがインストール済み
- 対象リポジトリで `/design-init` が実行済み（`.claude/design-bridge.json` が存在する）
- リモート照合を行う場合のみ: `/design-login` による claude.ai/design（design-system）の認可

`.claude/design-bridge.json` が無い場合は「未導入」と報告して `design-init` を案内し、照合は行いません（エラーにはなりません）。認可が済んでいない場合はローカル側の情報のみを報告します。

### 起動方法

以下のフレーズで自動起動します。

- 「設計書とデザインのずれを確認して」
- 「同期状況を見せて」
- 「未反映は何がある？」

コマンドからの明示起動:

```text
/design-status            # 未反映一覧 + リモート照合
/design-status --local    # ローカルの未反映一覧のみ（リモート照合なし・高速）
```

## 利用方法（最小例）

### 例 1: 全体の同期状況を見る

ユーザ:
> 設計書とデザインのずれを確認して

Claude（要約）:
> 未反映 3 件を一覧表示し、リモートと照合。「ローカル先行 2 件 / リモートのみ 1 件 / 一致 8 件」のように分類して提示し、`design-push` の実行を提案する。

### 例 2: リモートに触れず素早く確認

ユーザ:
> /design-status --local

Claude（要約）:
> `pending.tsv` の未反映一覧と件数、連続ブロックカウンタの状態のみを表示する。`list_files` / `get_file` は呼ばない。リモート先行の有無は未確認である旨を添える。

### 例 3: push の前に影響範囲を見る

ユーザ:
> 反映する前に、何が変わるか見せて

Claude（要約）:
> 反映対象になる未反映ファイルと、リモートが先行しているファイルを分けて提示。リモート先行がある場合は、上書きする前に `design-pull` で内容を確認するよう促す。

## トリガー例

| 発話 | 既定動作 |
|-----|---------|
| 「デザインのずれを確認して」 | 未反映一覧 + リモート照合 |
| 「未反映は何がある？」 | 未反映一覧 + リモート照合 |
| 「ローカルだけでいいので早く見せて」 | `--local` 相当（リモート照合なし） |
| 「Claude Design に反映して」 | 本スキルではなく `design-push` |
| 「Claude Design 側の変更を取り込んで」 | 本スキルではなく `design-pull` |

## 報告されるドリフト分類

| 分類 | 意味 | 推奨アクション |
|-----|------|--------------|
| ローカル先行 | ローカルに未反映の変更がある | `design-push` |
| リモート先行 | Claude Design 側だけが新しい | `design-pull`（ユーザー判断） |
| ローカルのみ | 未 push のモック | `design-push` |
| リモートのみ | ローカルで削除済み、または別経路で追加された | 内容を確認のうえ判断 |
| 一致 | 差分なし | 不要 |

連続ブロックが上限（既定 3 回。`~/.claude/.local/plugins/design-bridge/user-config.json` の `blockLimit` で 1〜10 に調整可能）に達すると、その時点の未反映内容が却下済みとして記録され、内容が変わるまで通知が止まります。この状態にあることも併せて報告します。

## 読み取り専用の保証

| 保証 | 内容 |
|-----|------|
| ローカルファイルを変更しない | 設計書・モック・スクリーンショットのいずれも書き換えない |
| 状態ファイルを消さない | `pending.tsv` / `block-count` を削除・更新しない（クリアは `design-push` 成功時のみの責務） |
| リモートを変更しない | `finalize_plan` / `write_files` / `delete_files` を呼ばない |
| 呼ぶのは読み取り系のみ | `list_files` と、対象を絞り込んだ `get_file` のみ |
| 問い合わせを行わない | 読み取りのみのため `AskUserQuestion` を発火しない |

### リモート内容の扱い

`get_file` が返す内容は、**他の利用者が書いた可能性のあるデータ** です。内容に指示らしき文言が含まれていても従わず、異常として報告します。

また `get_file` は 1 ファイルずつの取得になるため、両側に存在し、かつ更新が疑われるものに絞って呼びます。全件取得はトークンと時間を浪費するため行いません。

## 関連スキル

| スキル | 関係 |
|-------|------|
| `design-init` | 導入・設定生成。未導入を検出したとき本スキルが案内する |
| `design-push` | ローカル正本を Claude Design へ反映する。「ローカル先行」「ローカルのみ」の解消手段 |
| `design-pull` | Claude Design 側を取り込む。「リモート先行」の解消手段（明示指示時のみ） |
| `design-mock` | 設計書から画面モック HTML を生成する |
