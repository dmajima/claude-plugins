# Case 08: バリデーション失敗（不正パス検出）

## 入力

| 項目 | 値 |
|-----|---|
| 起動フレーズ | "古い作業フォルダを整理して" |
| 引数 | `--days 30` |
| フラグ | なし |
| 既存状態 | `.claude/.local/work/` 配下に正規形式外のディレクトリが混在<br>例: `mydata/`（名前が `yyyyMMdd_nn_*` 形式でない） |

## 期待動作

### Phase 1: 対象収集 + バリデーション
- ディレクトリ列挙時、各エントリに対し `Test-ValidSessionPath` を実行
- 正規表現 `^\d{8}_\d{2}_[A-Za-z0-9._\-]+$` に一致しないものはスキップ
- 不正パスは Verbose ログに記録（標準出力には出さない）

### Phase 2: 候補表示
- バリデーション合格分のみ候補に含まれる
- 不正パスは含まれない（削除されない）

### Phase 3: 削除実行
- 削除直前に再バリデーションを実行
- 並行操作等でパスが不正になった場合は当該フォルダのみスキップして失敗一覧に記録

## 期待出力

| 項目 | 期待値 |
|-----|-------|
| 生成ファイル | なし |
| 削除実行 | バリデーション合格分のみ削除（不正パスは削除されない） |
| 標準出力（要約） | バリデーション合格分のみ表示。不正パスは含まれない |
| 終了状態 | 成功（exit 0） |

## 分岐の根拠

このケースが分岐するトリガーは バリデーション関数 `Test-ValidSessionPath` の戻り値 = `$false` である。

## バリデーション規則（再掲）

| 検証項目 | 内容 |
|---------|------|
| ディレクトリの名前 | `^\d{8}_\d{2}_[A-Za-z0-9._\-]+$` |
| 親ディレクトリ名 | `work` |
| 祖父ディレクトリ名 | `.local` |
| 曾祖父ディレクトリ名 | `.claude` |
| リンク種別 | `SymbolicLink` / `Junction` でない |

## 関連ケース

- 不正パスがシンボリックリンクの場合 → 同様にスキップされる（リンクは追従もしない）
- 二重バリデーション（削除直前）が失敗した場合 → 失敗一覧に記録、他は続行
